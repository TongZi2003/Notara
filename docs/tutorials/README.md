# Notara 视频教程：录制准备

版本基线：`codex/notara-vault-clean`，Native Vault 0.14.9。状态：内容与录屏脚本初稿，尚未录制。首轮面向学生，用中文讲解，在已验证的 macOS 环境录屏；Windows 安装路径另见[Windows说明](../runtime/windows-native-vault.md)，不将本机录屏当作Windows实机证据。

## 主线

先让观众完成一次真实学习：带着一道题开口、自己尝试、得到帮助、留下理解和后续入口。功能随这条过程出现，不按八个分页逐一念说明书。首集不要求先拆整本书、规划完整课程或配置多个高级模型。

统一使用自编示例，不依赖个人课堂、商业讲义或历史测试实例。每集说明学生要做的操作、可以输入的话、应看到的结果和失败时的处理。模型回复保留实际结果，不将预写回复剪成真实运行；等待可加速，但注明实际耗时。

## 分集安排

| 集数 | 题目与时长 | 观众完成的事情 | 主要画面 |
| --- | --- | --- | --- |
| 00 | 安装与第一次打开，3–5分钟 | 用自己的模型配置打开持久学习空间 | Node版本、启动、设置；认证和密钥不入镜 |
| 01 | 从一道不会的题开始，6–8分钟 | 跟老师讨论一题，找到题卡、认知变化、小结和下次入口 | 对话、资产分屏、卡片、日历；详见本目录脚本 |
| 02 | 把讲义拆成能复用的卡片，6–8分钟 | 导入PDF，限定章节/题目范围，核对一题一卡与来源 | 资产PDF、区域引用、指令里的“书籍拆解与资料整理”、图谱父子关系 |
| 03 | 给自己准备一节课，6–8分钟 | 提供目标，生成备课剧本和路线，从路线开课 | “备课”“路线规划”、学生正文和折叠教师参考、上课小结 |
| 04 | 错题怎样变成有用的经历，5–7分钟 | 结合实际作答诊断，查看理解如何变化，再找回相关经历 | “学习经历与方法整理”“找卡片与资料”、学生理解与锦囊 |
| 05 | 没有教材也能学，5–7分钟 | 从一个C语言特性或算法目标开始，运行程序并用测试检查 | “路线规划”“备课”、代码和实际测试；上线前单独走读此场景，不用数学验收代替 |
| 06 | 老师背后的教室，3–5分钟 | 理解后台研究、备课与核验的作用，查看任务状态和结果 | 教室列表/像素视图切换、查看分析；不把派工说成质量保证 |

先录 00、01，完整走一遍学生路径，再录 02、03。后几集的标题是内容计划，不意味着已完成录制或对应学科的真实验收。

## 00：安装篇必讲内容

录屏使用发布时确定的 checkout。当前功能分支安装命令：

```sh
git clone --branch codex/notara-vault-clean https://github.com/TongZi2003/Notara.git Notara
cd Notara
node --version
npm ci --no-audit --no-fund
npm run build
npm run vault
```

Node 需要24或更新版本。Native Vault 使用 `npm run vault`，不要混用 README 中旧 Host 的 `trial` 路线。默认数据根、端口、自定义数据目录与重新打开方式见 [启动说明](../runtime/vault-launcher.md)。这不是临时验收环境；重启要回到同一数据目录。

首次配置主教师模型，演示配置入口后切走，不拍密钥、账户信息和带认证参数的地址。00、01只要求一个可用的教师模型；独立子代理模型放到02/06说明。当前Web设置没有OpenAI订阅OAuth入口，不能录成点一下即可登录；已接入模型与配置方式按发布版本实际界面讲解。

认证提示出现时，回终端运行 `npm run vault:open`，使用服务提供的有效入口；不指导观众关闭认证。终端关闭会停止本地服务，重新启动不会删除学习内容。

## 录制素材与镜头约定

- 示例题见 [自编录制材料](assets/first-lesson.md)。第一集直接在对话输入题目，不要求观众先整理整个仓库。
- 素材分“空学习集”和“已完成课堂”，分开备份。开头可先展示完成态，再明确切回空环境操作；不要假装同一次操作瞬间生成全部资产。
- 展示自己真实输入的答案。故意错误作为演示时标注“模拟学生作答”，不要拿它宣称真实学生学习效果。
- 原生对话与资产保持分屏；教师参考默认折叠。像素教室只在派工发生时短暂展示，首集不占用教学主线。
- 小字动作行用于解释读取、核验、保存的目的；失败行保留可见。执行详情按需展开，不要求学生理解命令。
- 内容检查与点击检查分开：公式、原题、参考答案、学生理解、来源都核对后，才把产物作为录制完成态。
- 每集结尾留一个可以照做的动作；不宣称生成卡片等于掌握，也不把复习档位说成能力分数。

## 文本读写方式的设计记录

主教师现已统一使用原生 Bash，下面保留决策依据。当前动作行的可读性来自 Bash `description` 中的用途标签与 `bash-display-client.js` 的小字折叠渲染，不来自 shell 命令本身。

两条可行方向：

1. **先统一展示。** 保留原生文件读写的版本保护，将读取/写入也展示为“回看这道题的原始条件”“补充你刚才修正的理解”等动作行。需要确认原生工具怎样传递用途；不能假定已有可用字段。
2. **统一 Bash 入口，并支持批量操作（已采用）。** 用户补充的批量写入价值成立：主教师审阅完一小批题卡后，可以在一次调用中集中保存，再批量回读，减少逐文件往返。用 Bash 调用复用现有文件IO的窄CLI命令，保留读版本、更新时版本校验、单文件原子保存和真实回执。不要默认用 `cat >`、任意脚本覆盖文件来代替这些机制。CLI读到的内容也不能假定会登记到原生 read 的观察记录里。

批量合同保持简单：每个文件分别带真实读取版本，新建与覆盖明确区分；结果逐文件给成功、冲突或失败，保留已成功项，不因一个失败重写整批。重试只处理未成功项。更新旧卡保留学生理解与复习历史，不整批覆盖成空模板；批量读取只返回相关章节或小节，避免为了省调用而注入整库。现有UI继续显示“保存这批题卡”“核对刚保存的内容”等小字动作行，展开后可查看每个文件的实际结果。当前已实现 `write-batch` 批量新建/精确替换；普通读取直接使用原生 shell。

目前已经验证原生 write 拒绝覆盖未读文件，原生 edit 在文件被外部修改后拒绝旧版本覆盖；普通 shell 读写不会自动获得这些保证。Bash的权限也走自己的原生沙箱决定，不能靠 `[notara:...]` 文案识别读写或授予权限。选定统一入口前，应明确怎样沿用当前权限和版本合同，不为美化文字引入另一套宽泛审批判断。

首集使用当前Bash工作流录制，镜头与旁白保留“学生看懂目的、需要时展开详情”的表述，不要求观众理解Shell命令。
