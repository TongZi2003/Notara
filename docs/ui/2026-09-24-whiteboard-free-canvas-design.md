# 双面课堂白板：自由画布与指定区域流式板书

日期：2026-09-24。状态：交互设计稿，未接入正式插件。

## 本轮明确的方向

用户选择了“自由画布，内容块可拖动”，并补充：“模仿一下 HyperKnow 的白板，他会选择在白板的特定部分板书，并且是流式的。”

因此，本方案采用自由画布。先前建议的“连续纸面＋局部并排”不作为课堂主布局；连续阅读顺序用于导出的笔记。

用户最后澄清：“不是让他变成黑色的板板”“不是笔画流式，是文字流式”，并要求不同颜色的高亮，提供 HyperKnow 截图作为明确视觉参照。当前采用**白色点阵、手写风格字形、紧凑分列的无卡片板书、文字流式与局部彩色高亮**。深灰绿黑板、逐笔轨迹动画均已撤回，不是已确认方向。

交互稿：`docs/ui/whiteboard-study.html`；样式与行为在同名 CSS/JS。历史、数学与空课堂均为明确标识的合成示例，不连接模型，不复制真实课堂记录。

## 空间与视觉

- 外围导航和对话沿用白底浅灰操作；白色点阵画布上使用手写风格字形，标题、短段落和小图沿几列自然展开。控件仍用清晰系统字体。去掉大标题和板面上的流程图连接，选中或正在写入的区域才显示轻量轮廓。
- 蓝、绿、橙、粉四种荧光笔色局部强调关键词，配合少量圈画。可以选中文字后上色、改色或清除；颜色是呈现，不代表掌握状态。示例先有自然列布局，内容块仍可自由拖动。
- 一道题、一张图、一段推导、一个比较或一个追问可以占据独立区域。没有强制的三段式课程、固定卡片格子或必须走完的节点。
- 老师依据内容关系选择已有区域补写，或在相关内容旁开辟新区域。前端负责测量、排布与避让；不用让模型猜像素坐标。
- 用户可以拖块、平移和缩放画布。用户移动过的块不因教师后续补写被排版器搬回原位。
- 视觉位置和内容的阅读顺序分开：拖到左边不自动变成第一章，拖到右边也不表示知识先修。
- 历史例子比较支付与运输责任；数学例子组织图形、代数与适用条件。它们说明空间行为，不是产品内置课程结构。

## 指定位置的流式板书

一次板书先有明确目标区域，再在该区域增量呈现内容。不要每次输出整张白板，也不要把完整答案事后播放打字动画当成真实流式接线。

拟采用的行为：

1. 选择目标块，或在相关块旁创建新块；给该区域轻量的“正在板书”状态。
2. **文字流式出现，不播放汉字笔顺或描摹字形。** 手写感来自字形与板面排布。高亮范围随对应文字出现；已有完成内容稳定留在原处。生产接入时公式或结构未完整应保留可读的上一个版本，不展示破碎排版。
3. 补充作用于该块；纠正作用于准确的段落，必要时保留折叠的认识变化。错误表述不能和修正结论并列成两个当前事实。
4. 一次写入完成后清掉暂态光标，保存已经确认的内容。中断时明确暂存与完成状态，不能显示“已保存”掩盖写入失败。

**当前设计稿的实现范围**：用合成内容模拟文字流式写入，支持暂停/继续；第一轮补充比较区域，第二轮切到另一块修订认识。保留未改变的文字和其他块的位置。手写字形使用本机楷体字体栈，不引入逐笔素材或第三方执行依赖。它不是实际模型流，也尚未实现流式 Markdown 解析、公式中间态或持久化。

## 教师焦点与用户视角

- “跟随板书”打开时，老师换区域才平滑移动视角；不随每个 token 推动整块画布。
- 用户平移、缩放、拖块或主动定位旧资料时，暂停跟随。
- 后台继续板书，并给出“回到正在板书的位置”；只有用户选择后才跟过去。
- 缩放、全览和跟随是画布控制，不是教学路径按钮。
- 对话保留唯一原生输入框。引用某块只补充上下文，不覆盖已有草稿。
- 窄屏在板书、资料关系和同一个对话之间切换；默认聚焦可读区域，不把全部画布压成微缩文字。全览用于定位，细读回到对应区域。

## 另一面：本课资料关系

节点是本课实际使用的教材、笔记、题目及本课笔记，关系标明来源、比较、改编或引用，并能回到这次关系发生的板书位置。计划使用、仅检索到和实际在课堂使用必须区分。

本轮交互稿的节点对应 `whiteboard-study-materials/` 中的合成 Markdown 文件。材料弹层明确其演示性质；关系表达不冒充史料核验。生产中不将整个 Vault 的邻域自动称作“本课使用资料”。

用户补充要求知识视图使用同样的渲染方式。当前两面统一使用白色点阵、手写标题与资料说明、多色高亮和无卡片框的内容区域。知识面保留真实资料之间的引用与比较线，不变成概念图。缩放、全览、高亮工具条只有一份，在两面之间移动；两面分别保存当前视角。资料节点可拖动，连线随之更新，来源打开及返回板书仍走原来的引用位置。演示中新增加资料时，系统只调整未被用户拖过的节点；已手动摆放的节点保持位置。

## Markdown 与导出

- 沿用已经确定的方向：一份课堂 Markdown 笔记是板书内容的持久来源；HTML 是投影，不设第二份可独立写入的 HTML 正文。
- 块的身份、课堂绑定和版本由系统维护。布局位置可作为同一笔记的呈现元数据；摄像机位置等个人界面状态不混进教学事实。具体语法与写入合同尚未实施。
- 画布位置与笔记阅读顺序分开。导出按讨论关系形成清楚的阅读顺序，保留图解和可展开题目。
- 默认不导出个人尝试、修订过程、额外提示与参考推导；选择包含后再加入。已在共享板书中公开形成的结论不因为取消“参考推导”而消失。
- 折叠不是保密。未选择的内容必须从导出文件物理排除；原始聊天不会自动整段打包。来源列表不等于打包原文。
- 当前稿由合成状态生成页面及导出预览，**不是生产 Markdown 事实源的实现**。HTML 下载打包样式；独立文件打开的兼容性需另验。

## 与现有插件的接入边界

本轮只读核对了实际源码，未修改以下文件：

- `examples/native-vault/workspace-client.js / createVaultWorkspace`：已有按 key 常驻的视图座位和唯一 `nativeConversationBody`。白板应作为一个视图接入；切换不能复制输入框。
- 同文件 `choose / openView`：视图的选择由工作区状态控制。小屏互切需要沿用这条路径，不能只靠 CSS 把两个输入面各画一份。
- `examples/native-vault/lesson-data.js / upsertLessonSummary`：同一课堂替换一个小结块，不是连续板书。保留小结职责，另行明确课堂笔记绑定。
- `examples/native-vault/teaching-state.js / bindTeachingLesson`：`materials` 是路线携带的计划资料引用；没有据此确认本课实际使用集合。可由课堂笔记明确引用和实际课堂引用建立范围，不能直接用预载清单替代。

只读审查中提出的“是否以事件代替 Markdown 正文”和“白板是否属于学生视图”不是待选方向：用户已经明确 Markdown 正文和学生白板。原生事件如有需要，只承担绑定、通知等职责，不能反过来新增第二套内容事实源。

自由画布与指定区域流式行为已按用户选择设计。接下来应在这份可见设计稿上确认块的视觉密度、自动放置与用户位置的优先级，再实现原生会话到 Markdown 的真实增量写入、版本冲突和刷新恢复。
