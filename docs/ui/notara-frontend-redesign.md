# Notara 前端重设计（基于 Native Vault 0.14.9）

状态：设计稿与可交互原型保留；现代白灰主题、全局导航与非白板页面已在 `codex/notara-modern-ui` 接入 Native Vault 0.15.0，具体实现范围、原生保留项与验证见 [接入记录](../dev-log/2026-09-24-native-modern-ui-integration.md)。基线为 `codex/notara-vault-clean` @ `5a5886f`（标签 `native-vault-v0.14.9`，`@notara/vault-native` 0.14.9）。下文仍是设计目标，不能把每条目标当作已实现；白板须先讨论最终形态。

- 原型：[`notara-frontend-prototype.html`](./notara-frontend-prototype.html)。默认是现代简约，加 `?style=notebook` 打开手写手帐。
- 浏览器验收：[`docs/evidence/frontend-redesign/`](../evidence/frontend-redesign/)，包括 `verify-prototype.mjs`、`verification.json` 和 28 张截图。
- 原型里的数据全部是合成的。原型不作为像素级合同，信息架构、交互与口径以本文为准。

## 1. 现状与问题

0.14.9 的学生界面分两层：

- **DSH 原生外壳**：左侧是原生品牌栏、「新会话」、工作区与会话列表、设置。对话输入框带模型、权限（中文为「工作区内修改」）和预设（教学者 / Standard mode）选择。
- **`examples/native-vault` 的工作区**：注册在 `conversation.workspace` 上。`workspace-client.js` 的 `createVaultWorkspace` 平铺 8 个分页（对话 / 轨迹 / 资产 / 图谱 / 卡片 / 路线 / 日历 / 教室），可左右分屏。样式来自 `client-source.ts` 的 `STYLE` 内联对象和 `ui-client.js` 的 `UI_CSS`，颜色全部取 `--dsw-alias-*`。

本次要解决四个问题：

1. **开发工具感重**：原生品牌、「Workspaces」、系统提示与上下文注入行、权限与预设名称直接展示给学生。
2. **8 个分页平铺，没有主次**：资料类视图都挂在某节课里，不开课就看不到自己的资料。
3. **缺少首页**：打开后看不到今天该复习什么、上次学到哪、下一节是什么。
4. **视觉层级弱**：默认 DSH 灰，控件与内容缺少层级。

## 2. 设计原则

- **学习动线优先**：今日 → 课堂 → 沉淀到资料库 → 计划与复习 → 回到今日。
- **一份 Vault，多个视角**：文件、卡片、图谱是同一批 Markdown 的不同投影，放在同一处。
- **同一课堂，多种呈现**：保留对话视图与资料伴随面板；新增白板机制原型，在板书旁继续同一课堂对话，输入框始终只有一个。白板当前的固定分块排版只是占位，不作为最终设计。
- **学生语言**：不出现会话、预设、权限、系统提示、工具名、路径或 ID（见 AGENTS「学生可见内容」）。
- **只放已实现的入口**：每个入口都对应现有 Remote 方法或原生能力（§6），未实现的功能不留占位。
- **状态如实**：
  - 复习档位不称为「掌握」。
  - 有小结不等于掌握，进度只统计开课与小结。
  - 「尚未观察」不渲染成失败。
  - 后台分析只显示状态。

## 3. 信息架构

### 3.1 全局结构

```
┌ 侧栏 ─────────────┐┌ 主区 ──────────────────────────────┐
│ [拾] Notara · 拾页 ││                                     │
│ [+ 新的一课]       ││   今日 ／ 资料库 ／ 计划 ／ 课堂     │
│ 今日         (4)   ││                                     │
│ 资料库             ││                                     │
│ 计划               ││                                     │
│ 课堂               ││                                     │
│  ● 进行中的课      ││                                     │
│  · 最近的课 …      ││                                     │
│ 设置  · 已连接     ││                                     │
└────────────────────┘└─────────────────────────────────────┘
```

- **今日**：默认落地页，属于全局页，不依赖打开某节课。
- **资料库**：分「文件｜卡片｜图谱」三个视图，合并了原来的资产、卡片、图谱。
- **计划**：分「路线｜日历｜复习」三个视图，合并了原来的路线和日历（日历原有的「间隔复习」模式独立成「复习」）。
- **课堂**：侧栏列出进行中与最近的课。课堂可切换白板、对话与教室；中点弦示例课默认进入白板。
- **侧栏数字**：「今日」旁的数字是今日到期（含逾期）的卡片数，取自 `reviewQueue status=due`。

## 4. 页面

### 4.1 今日

从上到下依次是：日期、标题「今天想学点什么？」、开课输入框、三个快捷入口，然后是双栏面板。

| 模块 | 内容 | 现有数据来源 | 动作 |
|---|---|---|---|
| 开课输入框 | 题目与尝试 | — | 回车后新建教学课堂，把文字作为第一条消息（§7.3） |
| 快捷入口 | 从一份资料开始 / 规划一条学习路线 / 复盘最近的学习 | manifest 技能 `route-planning`、`learning-review` | 打开资料库；新建课堂并插入对应技能 |
| 今天要复习 | 到期（含逾期）数、待评估数、前 4 张卡及其状态 | `reviewQueue`，status 为 `due` / `pending` | 「全部复习」进入计划 · 复习；「让老师带我复习」带入对话，沿用 `CalendarView` 中 `bring` 的意图文本 |
| 今天的课 | 当天排课的路线节点 | `calendar` 中 kind=`lesson` 的事件 | 未开课：开始这节课（`openRouteLesson`）；已开课：回到该课堂 |
| 继续学习 | 最近 3 节课、运行中标记、最后一句 | 原生 `sessions.list`（排除 blank 与 subagent） | 打开课堂 |
| 路线 | 每条路线的节数、有小结数、已开课数、分段进度条、下一节（计划） | `routes` 的 nodes（`sessionId`、`summary`、`scheduledOn`） | 打开计划 · 路线 |
| 最近的课堂小结 | 最近 2 条 | `lessonLog` | 在资料库定位到小结段落 |
| 日记 | 今天是否已写 | `calendar` 中 kind=`daily` 的事件，`dailyNote` | 打开或新建今天的日记 |

补充规则：

- 路线进度条下固定写「进度只统计开课与小结，不代表已经掌握。」
- 「下一节（计划）」取路线里第一个主线上、未开课且无小结的节点。它只是顺序提示，不锁课（0.11.0 起先修不限制开课）。
- **空学习空间**：只保留输入框和「从一道题开始 / 带一份资料 / 规划一条路线」三步，每步都是现有入口。其他面板不显示空壳。

### 4.2 课堂

**2026-09-24 增补：双面白板机制原型。** 用户已明确当前板书只是占位，最终不能照此固定笔记排版设计。本轮验证视图、引用、对话和导出接线；块的样式、布局、画布组织、自动编排与生成式图解均未定稿。下图保留为「对话」页签的布局，不再规定所有课堂只能以对话为主区。

- 「白板」页签包含板书面与知识视图；桌面侧边使用同一课堂消息和输入框，小屏切换到对话面再返回白板。
- 板书正文只有一份 Markdown，由内容块投影。题面、学生尝试、提示和参考解释分别折叠；可追加笔记、编辑笔记、从对话摘录、围绕内容追问。
- 知识视图只含本课笔记实际引用的现有示例资料，来源/专题/案例关系取自同一资料对象；可打开原资料、按小节定位，并回到板书的使用位置。它不是抽象概念图，也不是全库图谱。
- 导出 Markdown 和独立 HTML，可分别选择是否包含学生尝试/对话摘录、提示/参考解释；默认都排除正文。普通笔记中用户自行写入的内容仍会导出，界面明确说明。导出不发布网页、不包含资料全文或 AI 对话服务。
- 种子示例课的 Markdown 修改保存到当前浏览器；新增课堂仍遵循原型的临时内存生命周期，可在刷新前导出。真实 Vault 持久化、真实教学自适应、语音均未接入。

```
┌ 课程标题 [教法][目标][路线·第 n 节] ┊ 对话｜教室 ┊ 教学设置 ┊ 总结本课 ┊ ▣ ┐
├──────────────── 对话 ─────────────────┬┈┬───────── 伴随面板 ─────────┤
│ 学生消息（带引用）                      │ │ 资料 卡片 图谱 路线 日历  ✕ │
│ ▸ 查看相关卡片与学情（折叠步骤）        │ │ 《中点弦的斜率》             │
│ 老师回复                                │ │ 内容／参考理解（折叠）／学生理解 │
│ 题目研究员 · 已交给老师                 │ │                              │
│ ✓ 已记录本题评估：已表现／尚未观察      │ │                              │
│ [输入框：引用 · 指令 · 模型 · 发送]     │ │                              │
└────────────────────────────────────────┴┈┴──────────────────────────────┘
```

**页头**

- 左侧：课程标题、教法（取教学设置里的教法选择）、目标、所属路线节点。
- 右侧：「白板｜对话｜教室」页签、教学设置、总结本课、伴随面板开关。白板模式下最后一个入口切换到本课知识视图。
- 教学设置对话框的字段与 `teaching-client.js` 现有字段一致：学习目标、期限、每天学习时长、科目、教法、本课临时要求、老师人格。

**伴随面板**：替代原来左右两排各 8 个分页的分屏栏。

- 主区固定显示对话或教室。右侧面板用图标切换资料 / 卡片 / 图谱 / 路线 / 日历。
- 面板可拖动调宽，范围 25%–75%，与现有 `nv-split-handle` 一致。窄屏下改为覆盖层。
- 对话里点击 Vault 产物时，仍在伴随面板的资料视图打开（沿用 `attachConversationFileNavigation`）。

**对话流**

- 系统提示与上下文注入行默认隐藏（§7.2），开启调试模式后恢复原生行。
- Bash 步骤沿用 0.8.2 的小字折叠行，只显示 `[notara:<intent>]` 的中文用途。
  - 本设计让展开后的命令与原始输出只在调试模式可见。
  - 现在点开就会显示，所以这是一处行为变化，**需要确认**。
- 后台工作员沿用 `WorkerToolRow` 的状态行，固定附一句「后台结果只交给老师，老师会用自己的方式讲给你。」
- **评估回执（新增投影）**：把 `record-review` 的真实回执渲染成逐项三态（已表现 / 需练习 / 尚未观察）和题卡链接。写入失败时如实显示失败，不套用成功文案。

**输入框**：沿用原生组件。

- 保留「指令」菜单（0.14.2 起合并常用项与「更多技能」）、附件和模型选择。
- 权限选择移到设置页（§7.4，待核实）。

**新的一课（空课堂）**：原生 hero 输入框，下方配常用技能 chip：路线规划、书籍拆解、作文批改、从资料库带入。

### 4.3 教室

- **列表视图**，从上到下：
  - 主教师卡：人格名与当前状态。
  - 五位后台工作员：来自 `worker-catalog.js` 的 `WORKER_PRESETS`，状态有待命、分析中、分析完成、未启用等。
  - 后台任务：每个课堂同时只有一个。
- **查看分析**：「查看分析（含完整解法）」仍是学生主动打开原生只读子记录，旁边注明默认不展示完整解法。
- **像素视图**：沿用 `notara.classroom.view` 子槽和 `examples/pixel-classroom`，本设计不重绘。
- **教室设置**：对话框字段与 `classroom-client.js` 一致，包括工作员、模型、推理等级、资料范围（none / read）、每次分析的生成上限、独立人格。

### 4.4 资料库

**页头**：视图切换（文件｜卡片｜图谱）、搜索（`search`）、新建（新建页面，或从模板新建）、导入（`saveAsset`）。模板名取自 `templates/*.md` 的 `name`。

**文件视图**：三栏布局。

- 文件树：按目录折叠，点目录不进入投影。
- 阅读编辑器：CodeMirror Live Preview 与 PDF 阅读器。
- 属性栏：
  - 操作：带入对话、在图谱中查看、复习安排。
  - 属性：类型、位置、标签、复习状态、是否已开始复习。
  - 关系：来源与上级、拆出与被引用。
- 响应式：宽度低于 1180px 收起属性栏；低于 760px 时文件树改为下拉选择。
- PDF：支持翻页、缩放、适应宽度、框选原文区域。框选后底栏提供「带入选区对话」「保存高亮」「创建区域引用卡片」，与现有 `PdfReader` 一致。

**卡片视图**：卡片网格。

- 筛选：
  - 类型：全部 / 知识卡片 / 锦囊 / 教学专题。
  - 复习状态：今日到期 / 待评估 / 复习中 / 熟悉，口径与复习队列相同。
  - 标签筛选；可按专题（`parent`）分组。
- 每张卡显示：类型、复习状态、标题、摘录、来源行（文件 · 页码或锚点）。

**图谱视图**：沿用现有力导向图和交互（单击看详情、悬停高亮一阶邻居、以此为中心、标签筛选）。

- 图例按节点在图中的角色区分：来源、有子卡的卡片、卡片、锦囊、孤立节点。
- 边分两种：拆分为实线，引用为点线。
- 节点命中区要覆盖圆点与标签。原型验收时发现两者之间的空隙点不中，已按此修正。

**全局页的「带入对话」**

- 弹出目标选择：「当前课堂《…》」或「新的一课」。
- 资料放进目标课堂的输入框，何时发送由学生决定（与现有 `insertVaultReference` 一致，不代发）。
- 如果是在课堂的伴随面板里操作，就直接放进当前输入框。

### 4.5 计划

**路线**

- 左侧是路线列表，每条显示阶段数、节数、有小结数和进度条。
- 右侧按 `stage` 分泳道：
  - 主线是实线卡片，条件补练与拓展是虚线分支（`pathway`）。
  - 卡片上显示先修数和状态：计划中 / 已安排 / 已开课 / 有小结 / 进行中。
- 点击节点打开右侧抽屉，提供：
  - 开始这节课 / 回到这节课 / 再学一次（`openRouteLesson`，再学一次用 `repeat`）。
  - 安排日期（`scheduleLesson`）。
  - 查看规划、查看小结、在日历中查看。
  - 请老师规划或调整：带入路线页和现有意图文本。
- 抽屉固定提示「安排、修改日期不会自动开课，也不会标记完成」。
- 底部可展开课堂日志（`lessonLog`）。

**日历**

- 月历加当天安排。事件沿用 `calendarProjection` 的五类：课程安排、课堂小结、到期复习、评估记录、日记，在月格里用彩色点标注。
- 当天栏提供：事件列表、打开或新建这天的日记、把一节课安排到这天。

**复习**：原「间隔复习」模式独立成页签。

- 筛选沿用 `calendar-client.js` 的 `FILTERS`：今日到期 / 待评估 / 复习中 / 熟悉 / 全部。
- 详情区包括：
  - 复习档位与下次日期。
  - 评估经历（逐项三态）。
  - 自评表单：1–8 项不重复的能力，每项选三态之一，外加一段证据说明，全部填齐才能保存。
  - 操作：让老师带我复习、打开原文、撤销最近一次评估。
- 保存回执沿用现有文案，区分「已保存能力评估并更新复习安排」与「原复习安排保持不变」。
- 固定提示「复习档位只决定下次什么时候复习，不代表已经掌握。」

## 5. 视觉语言

两套主题共享信息架构、组件与交互，允许首页构图和局部排版不同，并沿用 [`themes.md`](./themes.md) 的两条约定：按信息角色定字阶；手帐装饰只在 `data-sf-style=notebook` 下生效。两套主题都跟随原生的浅色 / 深色 / 跟随系统。

2026-09-24 根据用户实际浏览反馈调整现代主题：参考 HyperKnow 首页的集中构图、留白、白色圆角面和轻浅选中态；最终明确为纯白背景、浅灰按钮和选中态。移除紫色主按钮、淡黄色纸面、荧光黄标记及黄黑搭配。手帐借鉴只保留细点阵和排版节制，现代正文不使用圆体或手写字体。原有独立手写手帐主题保留。

### 5.3 现代简约

- **表面**：页面、输入面和侧栏均为纯白；用细浅边界与轻阴影区分层次，不使用暖黄纸面。侧栏从满高色块改为带外侧留白的独立圆角面。
- **首页构图**：日期、标题、输入区居中；输入区最大 720px，快捷入口为低权重文字操作。复习、课程、路线和小结置于下方，不挤占开始学习的区域。
- **内容层次**：今日各分区去掉整块卡片外壳，靠留白、字阶和细分隔线组织。需要单独操作的课程项、输入框、浮层仍有圆角表面；不把所有内容包进相同圆角矩形。
- **操作**：主按钮、发送键、普通按钮和选中态统一浅灰，低权重操作使用文字按钮。hover/active 只轻微改变灰阶、边界和位置，遵守减少动画设置。
- **字体**：本地/系统无衬线，`Helvetica Neue` / Helvetica → `Hiragino Sans GB` → `PingFang SC` → `Noto Sans SC` → `Microsoft YaHei UI` → Arial；不引入外部字体，现代主题不加载霞鹜文楷。标题 600、控件和列表 500、正文 400，保持清楚层次。
- **手帐借味**：保留图谱/路线的精细点阵和内容排版节制；没有黄色高亮、仿纸色、贴纸或手写正文。原有手帐主题仍可单独选择。
- **响应式**：1100px 以下今日内容区转单列，760px 以下保留侧栏抽屉。短控件不竖向折字；880px 以下输入框模型按钮使用短标签。收起的侧栏完全离开视口，避免浮动侧栏外边距露边。

### 5.4 手写手帐

- **字体**：霞鹜文楷，文件在仓库的 `packages/client/assets/notebook/fonts/wenkai.woff2`（SIL OFL 1.1，约 7.6 MiB），只在选择手帐时加载；原型验收已确认现代主题不会下载它。公式、代码、来源原文保留各自的字体。
- **纸面**：
  - 只给滚动的文档根铺 32px 横线，使用 `background-attachment:local`，横线随内容滚动。
  - 对话纸左侧加一条红色页边线。
  - 控件与画布保留自己的底色，图谱、路线仍用点阵。
- **侧栏**：线圈本的装订孔；品牌「拾」做成红色印章；「新的一课」是一张黄色便签。
- **选中态**：荧光笔涂抹，即不规则圆角的半透明黄色。
- **纸片**：
  - 今日面板顶部贴胶带，交错轻微旋转（不超过 0.4°）；「今天要复习」是黄色便签。
  - 卡片库是顶边带红线的索引卡。
  - 路线节点是贴胶带的便签，分支是蓝色虚线便签。
  - 图谱节点是带白边和投影的彩色贴纸。
- **对话**：
  - 学生消息是便签，老师的回复写在横线上。
  - 评估回执贴胶带并盖「已记录」印章。只有真实保存成功才出现印章，对应 themes.md「待定便签，实际保存后胶带与印章」。
- **小装饰**：日历里的「今天」用红笔圈出；首页标题下画一条波浪线。
- **约束**：
  - 旋转只做装饰，不用于坐标布局；开启 `prefers-reduced-motion` 时无动画。
  - 逐行基线对齐沿用 `packages/client/src/theme/align-notebook.ts` 的测量方式；原型只用 32px 行高近似。

### 5.5 窄中屏与控件换行

窄中屏（约 801px 宽度、左右分屏同时打开）最容易出现控件被压成竖排。处理原则是：短控件与标题不换行，非必要 label 先压缩。

- **≤960px**：侧栏收到 204px，把宽度让给对话和伴随面板；伴随面板标题单行省略（`text-overflow:ellipsis`），头部图标按钮收到 26px，头部间距收紧。
- **≤880px**：对话输入框里的模型控件换成短标签「模型」（完整名称仍在同一按钮的 DOM 里），避免 `.bar` 内的控件被压成竖排。
- **始终不换行**：`.nav-row`、`.model-btn`、`.conn` 等短控件加 `white-space:nowrap`，标题用省略号而不是折行。
- 这些只调整控件尺寸与标签显隐，不改信息架构、`data-act` 与交互；两套主题共用同一套断点。

### 7.1 全局页不带会话读取 Vault

- `createVaultClient(ctx, undefined)` 发送空 scope，Host 端 `teaching-runtime.js` 的 `editorFor` 会回落到启动工作区 `this.root`。
- 单 Vault 安装（`npm run vault` 的默认情况）下，全局页和课堂读取的是同一个根目录。
- 存在多个工作区时，需要在侧栏加学习空间选择，并把选中的工作区显式传给 Host。本期只在恰好一个工作区时显示全局页，不做猜测。

### 7.2 隐藏工程行

- 按 key 注册一个空渲染即可遮蔽，不改动会话内容；调试模式下取消注册，恢复原生行。
- 实现时需确认两点：
  - `conversation.chat.node` 的 props 足以区分节点类型。
  - 隐藏后原生滚动锚点不受影响。

### 7.3 从全局页开课

- `ensureTeachingSession` 会直接返回任意当前课堂，不能作为“从今日开新课”的保证。应使用原生 `uiWorkspace.connectWorkspace(workspaceId)` / `openWorkspace`：复用目标工作区未归档的空课或新建，并保留导航取消语义。
- 等待目标 session scope/input 可用，再用原生引用/文本插入接口交接；保留首页草稿直到发送真正成功。
- 已在 rc.2 源码与类型中找到 `ctx.conversation.input.for(scope).submit(mode)`。它处理原生输入准入与序列化；新课交接、重复点击、异步切课与失败草稿保留尚未在新前端验收。原型直接发送只是模拟。
- `seedVault` 启动配置已核实默认预设为 `notara-teacher`；接入时仍须验证目标新会话的实际预设和数据根。

### 7.4 原生控件文案

- **权限选择**：来自 `dsh-client-ui-permission-presets`，中文为「仅可查看 / 工作区内修改 / 完全权限」。
  - 建议从课堂输入框移到设置页，原生设置行已经存在。
  - rc.2 能否按槽位隐藏输入框里的选择器还要核实；不能的话就保留原生控件。
- **预设名**（「教学者」「Standard mode」）：只有一个教学预设可用时，不显示选择器。
- **侧栏文案**：「新会话」「工作区」等原生文案随自定义侧栏一起被替换。设置页中的「学习空间」沿用 `NotebookSidebar` 的做法。

### 7.5 已知边界

- 已有运行目录固定了插件快照，新前端只在新运行目录或新实例里生效，不能用 `git pull` 代替升级（见 [`vault-launcher.md#版本更新`](../runtime/vault-launcher.md#版本更新)）。
- 全局页的 UI 状态（选中的文件、图谱镜头等）要和现在按会话保存的状态分开存放。
- 手帐字体约 7.6 MiB，只在选择手帐时加载，首次切换会有加载时间。
- Windows 未做实机验证。

## 9. 验收口径

- 在 `startVaultIsolated` 新建的隔离实例（新运行目录）上，用真实浏览器验收。旧课堂、旧快照上的现象不算证据。

- 必查项：
  - 1440 / 1024 / 390px 三个宽度都没有横向溢出。
  - 窄屏的侧栏抽屉与伴随面板。
  - 按钮命中测试。

  - 学生可见文本不含工程词、路径和 ID。
- 真实模型与真实学生体验单独记账，不用原型或确定性测试替代。
