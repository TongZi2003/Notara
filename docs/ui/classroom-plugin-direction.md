# 教室插件：课堂上下文与动作编排

2026-09-15讨论稿。用户将世界书明确为「控制什么时候注入什么提示词、调用什么subagent或tool」的课堂上下文编排。当前代码尚未实现本方案；数学与世界书两插件的启用状态保持不变。

## 产品分工

本体负责拆书、学习、记笔记与沉淀记忆。「教室」是统一插件名与可视界面；世界书是其中的课堂配置，负责背景、角色、教学策略和触发规则。教室呈现规则如何作用于本课，以及真实子智能体的座位、发言和任务状态。

用户可以组合出辩论课、历史情境课、变式训练等课堂，不再为每一种教学活动维护一个独立工作台。数学工作台继续承担实际二维/三维构造和计算。

## 建议的最小结构

一份世界书包含三种可复用内容，以及引用它们的运行规则：

- 背景：概念、情景、时代条件、人物关系、术语和资料引用。
- 教学策略：该怎样提问、挑错、出变式或整理板书，可引用已有技能。
- 角色：名称、座位呈现、职责、人设及可使用的能力，例如杠精同学、出题同学、助教。
- 规则：何时让哪一份内容或哪个角色参与当前课堂。

这些内容由用户编辑；日期、课堂身份、原生事件标识、运行状态和版本绑定由系统生成。座位状态来自真实任务，摆放一个角色不代表已经启动子会话，更不表示每轮都向所有角色发送全文。

### 一条规则回答五件事

| 项目 | 示例 |
|---|---|
| 何时触发 | 手动@、主教师完成一次回复、每3个完整教学回合、成功保存阶段笔记、用户输入命中关键词 |
| 作用于谁 | 主教师、指定同学，或某个已登记的工具动作 |
| 带入什么 | 当前问题、指定资料、最近形成的结论、某条教法或角色提示 |
| 执行与输出 | 临时注入上下文、加载技能、启动/继续子智能体任务、调用现有工具；结果给主教师或作为署名发言进入对话 |
| 有效多久 | 仅本轮、到当前阶段结束、整个课堂；自动任务还可设置冷却或次数限制 |

触发方式、动作和上下文寿命相互独立，不做成混杂的一个「插件类型」。第一版建议以简单规则卡编辑，显示成一句可读的话；先让常见行为可配，再根据实际复杂度决定是否需要流程画布。

## 课堂中的具体例子

| 课堂需求 | 规则组合 |
|---|---|
| 杠精挑错 | 学生@杠精同学 → 带入指定结论及来源 → 真实子智能体指出一处最影响结论的漏洞 → 在对话署名发言 |
| 变式检验 | 阶段笔记成功保存 → 带入该阶段已经讨论的条件和方法 → 出题同学准备一道变式 → 排入课堂，等学生作答后再分析 |
| 历史情境 | 当前问题涉及设定中的时代或人物 → 带入对应背景与史料阅读策略 → 教师读取实际来源并开展对话 |
| 定期质疑 | 每3个完整教学回合 → 让指定同学检查当前论证 → 每次只提交一项值得处理的问题 |
| 数学实验 | 学生要求检验参数影响 → 带入实验策略 → 教师或有相应能力的角色调用数学工作台工具 → 读取实际图形与测量再解释 |
| 重点板书 | 教师形成一个需要保留的结论 → 本轮提示教师用简短板书整理条件、公式或推导 → 显示在原对话，不新开黑板 |

融合的是背景、教法和调用能力。世界书不会因加入时代或地点文本而自动获得地图渲染，也不会因写了角色提示而自动产生独立子智能体；需要实际工具或原生子会话执行，结果才算发生。

错题练习和板书已经属于基础对话能力。世界书可以调整何时采用、由谁参与和怎样呈现，不再为它们建立第二份练习或笔记记录。

## 触发与判断

确定的时机由现有原生事件驱动。首版优先接学生输入被接收、主教师完成回复、笔记成功保存以及手动@；「每N轮」按完整教学回合计数，工具返回和子智能体插话不计成新教学回合。

「这段论证值得质疑」「现在适合考一道变式」是教学判断，由主教师根据当前上下文选择候选规则，或主动调用对应角色/技能。关键词用于找候选，不等于语义判断，更不直接推导学生已掌握。

两条触发路径最终进入同一个调度入口。规则只引用已登记的角色、技能、工具和实际教学对象；复杂任务参数交给执行者判断，课堂身份、对象版本等机械字段由现有运行时绑定。调用的失败、未执行与完成分别呈现，提示词里写了「请调用」不算实际执行。

默认在主教师发言的完整边界安排自动动作，手动@优先；每个教学回合先限制为一项自动插话任务，避免轮流抢话。用户停止会取消尚未开始的自动任务，并通过原生接口停止在途任务。子智能体结果不再无条件触发相同自动规则，事件去重由运行时完成。

## 上下文生命周期与来源

每条规则选择它实际需要的背景与材料，并在界面显示本轮带入原因。默认临时上下文在相应轮次或阶段结束后失效，角色与长期课堂约定才随课保留；不要把所有世界书全文每轮都塞进提示词。

用户明确编写并启用的教学规则与引用来的教材/世界观资料分开处理：前者可以编排行为，后者作为内容依据。导入一段资料不会自动把里面的句子注册成工具指令。现有主教师、子智能体和工具的实际权限仍由原生运行时与窄工具校验。

自动触发不改变原来的保存通路：卡片、复习、笔记、小结仍按各自规则保存；没有保存成功就不产生「笔记完成」事件。一个角色提出评价或学生看到了题目，都不自动成为掌握事实。

## 可视界面

主视图是一间有座位的教室；点击同学可看职责、本次材料、任务状态、发言及停止/继续操作。@与规则触发使用同一角色和同一原生子会话。

世界书侧栏编辑背景、角色、教学策略与规则。「本轮参与」显示：哪些条目已注入、为什么触发、谁正在工作、结果去往何处。开启规则前提供一次预览，解释当前会触发什么；开发详情可展开原生事件，不以调试轨迹替代学生界面。

## 现有代码与新增范围

- `host/src/plugins/worldbook-context.ts`已绑定真实被接收的用户输入，并按输入固定一轮上下文；可保留这条输入边界。
- `worldbook-selection.ts`目前只做字面匹配，且所有条目被明确当作背景参考。要支持本设计，必须把用户运行规则与背景材料分开，不能只修改一行提示词就声称支持编排。
- `seminar.ts`已有原生启动、继续、停止与状态读取，可复用这些接缝；固定peer/critic/assistant和研讨表单需要由可配置角色与教室呈现代替。
- 新增的是规则配置、事件到规则的匹配与调度、上下文选取/失效、可视角色管理。DSH继续拥有会话、模型调用、子任务生命周期和工具执行；不另建通用Agent运行时。

纯提示词方案容易搭建，但不能保证轮次、去重或实际调用；完整可视流程编辑器过早增加配置成本。当前建议选择薄编排层加规则卡，先验证「@挑错」「阶段后变式」「按轮次插话」三条真实闭环，再细化视觉稿和实施计划。
