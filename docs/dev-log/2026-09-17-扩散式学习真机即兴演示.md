# 扩散式学习真机即兴演示（diffusion preset）

日期：2026-09-17。方式：真实隔离实例 + 真模型（deepseek-official / deepseek-flash；`deepseek-v4.1-flash` 被该账户拒绝，支持的模型名为 `deepseek-flash` 与 `deepseek-v4-pro`）。由 agent 本人扮演学生即兴对话，无剧本。隔离实例经 `scripts/dev-isolated.ts` 启动，`testModel: false`，key 仅注入进程环境。

## 目标

验证 diffusion 预设是否改变了真实行为，而非只改了措辞：终点倒推主干、半路疑问长成待确认分支、留名的坑、判断可协商、证据纪律。

## 实际跑通的链路

1. **诊断**（lesson session-eec2f399…）：三轮渐进诊断（agent loop 伪代码 / KV 机制推理 / 模块边界 / Rust trait 对象），自述不当水平，全部用真实作答取证。
2. **协商**：学生对站点顺序抬杠（先做 loop 再啃机制），教师说明「为什么你的理由更准 + 代价 + 对冲」后接受——不是无条件让步。
3. **门控**：`propose_route` 在 handoff 未确认时被拒（真实拦截），确认后重提才生成 7 站路线（proposals → confirm → route v7，parent 链 + decl.stance 完整）。
4. **第一站**（可观测最小 loop）：学生用假模型/真工具跑出三轮，再切真 API 四轮；教师逐格核账、独立复现出「漏计 reasoning 列」的 bug 和数据版本混报。
5. **第二站**（机制三晚）：KV 公式、算术强度、交叉点、压缩回本账（9.8 轮 → 结论「可行性成本不是省钱手段」）。
6. **半路分支**（第三站开场）：学生问「为什么 KV 不跨会话持久化」→ 教师判成「第三站的第一块砖」，走 `propose_route` 加子节点待勾选，学生确认后当场讲透（三本账：搬运/占用/摊销）。

## 关键观察（对预设逐条验收）

- **终点倒推**：路线 7 站全部从「Rust 重写极简内核」倒推，未铺百科时间线。✓
- **分支授权**：学生的 KV 持久化疑问走了 `propose_route` 提案+勾选，未静默改路线；同时教师主动判定「值半站不值一站」，给了开/不开的完整理由。✓
- **留名的坑**：模板拼装顺序（供应商实现）、KV 压缩（MLA/GQA/滑窗/量化）均记成认知笔记留名，写明「坑是什么/为什么跳过/何时回来」。✓
- **证据纪律**：教师两次当场否掉学生的漂亮拟合（54=54 假数据指纹、T≈68 三区间巧合被 327 实测打死）；并按要求当场要反证。✓
- **学情修订**：`revise_memory` 把「跑到能跑就停」逐次修订为含反例与四类对象（算术/结论强度/数量级外推/前提定义边界）的细粒度记录——未产生重复条目，正是 evidence 自动绑定修复后的预期行为。✓
- **沉淀**：认知笔记 ×3（其中一条 v2 修订）、方法笔记 ×2、自产教材讲义 ×2（`create_markdown_material` 入库）、复习卡 8+5 张提案确认、两站 handoff 收课小结全部走提案+确认闭环。✓

## 暴露的问题/缺口

1. **`deepseek-v4.1-flash` 不被该账户接受**——`tests/fixtures/live-classroom.ts` 的默认 model 在本 key 下报 `INVALID_REQUEST`，只能换 `deepseek-flash`（`STUDYFORGE_LIVE_MODEL` 可覆盖）。默认值是否需要跟随账户能力，或至少在报错信息里可读，值得记一笔。
2. **`propose_route` 被门控拦截时教师误诊断**：它以为是学生没点确认、让学生「再点一次」，实际是提案被拒需要重提。学生从界面上纠正它才走通。可改进点：门控拒绝的 tool result 文案应直接告诉模型「重提即可」，避免让学生背锅。
3. **确认提案的 UX 依赖人工 RPC**：本次演示由脚本侧代点确认；真实浏览器流程未验（本次为会话/课程级验证，UI 层 `未运行`）。
4. **长程耐力未验**：目前推进到第三站正身开场；第四~七站（harness 边界/Rust 类型/上下文预算/终点验收）`未运行`。
