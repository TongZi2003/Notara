# 工具门面合并：常量 wire 取代渐进披露

## 目标

消灭 `load_tools` 造成的请求前缀缓存失效（实测一节课 3–5 次序列重启，最重一次 244K tokens 全量重读只为加一个 `propose_handoff`）。方向定为工业界的「工具合并」路线：wire 上只挂一组常量门面工具，`method` 选内层实现；工具面从此不随已装 board/插件数增长。

## 实际改动

- `packages/contracts/src/tool-facades.ts`（新）：`TOOL_FACADES` 分发表——11 个门面（find/open/note/update/record/propose/create/board/classroom/stage/delegate）覆盖 60 个内层工具；`resolveFacadeTool(name, args)` 支持已解析参数和 `tool/call` 事件里的原始 JSON 串；`FACADED_TOOL_NAMES`/`TOOL_FACADE_NAMES` 供 wire 过滤与守卫复用。`contracts/src/index.ts` 导出。
- `packages/host/src/tools/tool-facades.ts`（新）：`registerFacadeTools`——每个门面的 schema 是 `{oneOf:[{type:object, properties:{method:{type:string,const}, input:<内层原schema>}, required:[method,input]}]}`，内层参数合同只此一份不复制；execute 经 `tools.get(inner, agent)` 分发到原实现；`output.render`/`presentationMeta` 转发内层定义，来源依据 meta 链不断；output schema 用无约束 `{}`（内层结果形状各异）；未知 method/内层缺失走 `rejected()`。`facadeMethodText` 生成静态「本课能力」速查节。
- `packages/host/src/tools/tool-disclosure.ts`（重写）：投影器输出常量 wire（11 门面 + read/read_image/glob/grep/web_search/web_fetch/skill/subagent/send_message/interrupt_agent/list_subagent_models 白名单），附静态 method 速查节；`load_tools` 保留注册、退出 wire，回执兼容旧会话（仍按目录校验 names，含未知名整批拒绝）。
- `packages/host/src/tools/learning-context.ts`：`observedVersion` 扫 `tool/call` 时经 `resolveFacadeTool` 解析内层名，「先读后改」版本绑定不变。
- `packages/host/src/teaching/teaching-context.ts`：守卫先解析 facade→内层名再套 `helperForbidden` 与 `register_cards` 诊断门；helper 的 wire 过滤掉门面名（helper 直呼 facade 时按内层名命中同一禁令）。
- `packages/host/src/index.ts`：`registerFacadeTools(ctx)` 在所有 `register*Tools` 之后。
- `packages/client/src/classroom/tool-copy.ts`：`toolDisplayCopy` 用 `resolveFacadeTool` 反查内层名复用既有文案，facade 名自身也有兜底标签；旧名条目保留给历史回放。
- `resources/teaching/`（base/presets/skills）与 `packages/host/src/teaching/{book-task,guided-learning,native-delegation}.ts`：模型可见的工具用法改为 `{method,input}` 门面写法；helper 的 `allow` 名单保留原名（helper wire 本就无门面）。
- `docs/runtime/tool-disclosure.md`：重写为常量门面契约的现行描述。

## 关键不变量（均已验证）

- 内层工具全部保留注册、原名直呼可执行——注册表与 guard 是权威，声明只是描述（沿用 web_search 直呼先例）。
- 提案幂等按 callId，facade 调用天然唯一；`presentationMeta` 转发保证 source-use/session-resource/思维图元数据不变。
- helper 看不到门面；helper 经门面绕道时解析内层名命中 `helperForbidden`。
- `register_cards` 诊断门对 `record({method:'cards'})` 同样生效。
- wire 常量 = 21 工具 ≈127KB schema（比旧全量 77KB 大，因内层 schema 嵌进 `input`，但每课恒定一次进入前缀缓存）。

## 验证

- `npm run typecheck`：PASS；`npm run check:contracts`：PASS（84 same-source）。
- `npm run test:unit`：PASS 173/173。
- `npm run build` 后集成：tool-disclosure 2/2（常量 wire、facade 分发、原名直呼、load_tools 回执、重启/新课隔离）、tool-schema-projection 1/1（11 个 facade 根全部经 provider 投影为 object 根；嵌套 union 在 report-only 桶）、teaching-current 3/3、native-close 9/9。
- 全量集成（build 前快照）：269 过 / 6 失败——4 个文件全部是旧 wire 断言（8 工具初始集、`load_tools` 扩列、`course_already_closed` 旧错误文案），已按新契约改写后各自通过。
- 真实模型（tests/live）：未运行，`DEEPSEEK_API_KEY` 环境未确认。

## 未完成与下一入口

- `record.cards`（register_cards）在 method 速查节里对所有课可见——速查节是静态文本不按课裁剪；非诊断课调用仍被守卫拒绝并给出原因。若要隐藏需把速查节改为按课生成（每课内仍恒定）。
- 真机回归未跑：需验证 provider 对 `input` 下嵌套裸 `oneOf`（如 propose.card 的三分支）的接受度——测试模型不校验此层。
- PTC 列为后续正式评估项（worker-thread 信任面、`ptc:` 子调用的 trace 呈现、提案-确认链在 SDK 绑定下的行为）；facade 化使未来 SDK 只剩 11 个签名。
- 前端「正在…」标签对 facade 有兜底文案，但内层 method 级细文案（如 propose_card 的卡片数）已接入；个别新组合若显示笼统文案属可接受降级。
