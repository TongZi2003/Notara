# 2026-09-19 全仓分块审计

## 目标与方法

对全仓按模块边界做只读审计，基准为 AGENTS.md 硬规则（学生可见面不泄内部信息、失败如实、合同单源、无占位 UI、帮手只读契约）加已知历史教训。五块派只读子代理并行审（contracts/domain/host-tools/host-服务持久化/teaching-delegation-提示词），client 与横切安全两块因子代理环境不稳定改由主线程亲审。所有「高」发现经主线程回读源码复核。

## 高——真实破口/数据风险

### A1. Atlas merge 静默清空知识地图（已亲验）

`domain/organization/atlas.ts` `AtlasService.merge`：`AtlasNodesSchema.safeParse(existing)` 失败回退 `[]`。`AtlasAuthoring.preview` 的 repath 校验只查 `from` 存在性与映射互不重叠，不查 `repath.to` 与 retained 路径撞名——既有 `a`/`a/x`/`b` + repath `{from:'a',to:'b'}` → retained 双 `b` → safeParse 失败 → merge 只剩 incoming → `save` 原子落盘把整图裁成草稿子集，卡片 topic 级联照跑。姊妹 `SkeletonService.merge`（materials/skeleton-service.ts `parseNodes`）同情形抛 `skeleton_duplicate_path` 命名拒绝——不对称即 bug。修法：merge 改严格同款 + preview 前置校验 `repath.to` 撞名给可修复命名错误。

### A2. round `stop()` 停而不止 + 孤儿卡（已亲验）

`host/teaching/rounds.ts`：actor `childId` 只在 `completed` 时写入（open/answer/correct 三处），`stop()` 过滤 `(running||queued) && childId!==undefined` 恒为空集——无人被 interrupt，记录却标 stopped。且 stop 不走 `this.tail` 串行：open 中 stop 后，在途 `proposeProblems` 已原子写的卡仍落库成孤儿；stale row 的后续 `update` 连环 expectedVersion 冲突，job 以裸存储错误 reject。

### A3. round actor `detail` 泄内部信息进学生面板

`rounds.ts` open/answer/correct 失败分支写 `detail: reason(error)`；`native-delegation.ts` `incomplete()` 把 `${childId} ${stopReason} / ${diagnostic} / 已产出：${partial}` 拼进 message。`viewOf` 只剥 `childId` 字段不剥 `detail` 文本 → 经 `StudyForgeRounds` remote 送学生面板。open 的 rejected 文案同样把含 childId 原文喂教师模型。

### A4. `SeminarView.participants[].childId` 穿透插件 iframe

`contracts/plugin-learning.ts` SeminarRecord→SeminarView 未 omit；`host/plugins/seminar.ts` `list()` 直接拼进视图送 seminar-room 插件。对照 `teaching-rounds.ts` `RoundActorViewSchema` 显式 omit childId——姊妹合同不对称。SeminarView 还是纯 interface 无 zod 把关。

### A5. record-store 全版本重解析 = schema 演进地雷（两块印证）

`domain/storage/record-store.ts` `recordSchema()` superRefine 对**全部历史版本**跑当前 content schema；`host/storage.ts` `collection()` 打开时全量校验旧行。`CourseMetadataSchema.closure`（courses.ts）是后加的 required nullable 无 default——早于它落盘的行会让整条记录所有版本报废 → 裸 ZodError → `index.ts` 启动路径整个工作区打不开。`defineDomain` version:1 无 migrator、记录无版本字段、strict schema 使任何不兼容演进即触发。现状未爆（多数字段 optional/default），首个 required 演进即地雷。

### A6. 分片上传内存未根治

`host/materials/resource-service.ts`：`PendingUpload.chunks: Buffer[]` 整文件驻留，commit `Buffer.concat` 再分配一整份（单文件峰值 2-3×）；16 并发 × 256MB 理论驻留 ~4GB；过期暂存仅下次 uploadBegin 惰性清扫。读侧 `bytes()`/`docxIndex()` 整文件物化 + base64 +33% 且无并发上限。wire 层修好了，host 侧峰值没降——与已修历史故障同类、只是有界。

### A7. `pdftext` 定位符被校验层拒识（确定性无效重试循环）

`domain/materials/source-relations.ts` `locatorRelation`/`sourceContains`/`sourceOverlaps` 只有 text/docx/pdf/image 四分支——`pdftext` 恒落 `false`。消费方：`source-use-tools.ts` `cite_materials`、`organization-tools.ts` `assertRefinedReads`→`propose_skeleton`/`propose_atlas`、`content-history.ts` 覆盖统计静默少报。工具描述却教模型用 `{kind:'pdftext'}`（`proposal-tools.ts`）；错误归因说「没读过」→ 模型重复读同一范围，与参数解析死循环同构。
