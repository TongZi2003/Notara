# 原生 Bash 文本操作与独立人格

日期：2026-09-23。工作树 `codex/notara-vault-clean`，Native Vault 0.14.8。

## 目标与实际改动

用户确认普通文本读写统一走原生 Bash，支持 `ls/rg/grep/sed` 组合和批量写入；同时要求大肥鱼人格在对话中可见，老师与各类子代理可分别设置人格。

- `agent-tools.js / installAgentTools`：仅主教学会话从模型清单移除 `read/write/edit/glob/grep`，旧名字被实际调用时也拒绝。普通编码预设与旧 Host 不受影响；只读工作员保留 `read/glob/grep/read_image`。锁定 rc.2 的 spawn 没有独立只读沙箱选项，不能给继承完全权限的只读工作员任意 Bash。
- `vault-cli.js / write-batch`：同一次 Bash 可保存1–50个不同Markdown文件；create拒绝覆盖，edit要求已读原文唯一匹配，保留其他内容后通过原生文件IO按当前revision做CAS。每个文件单独回执，部分失败退出非零且保留成功项；只重试失败项。普通shell并不自动获得这些保护。没有新增模型工具或普通文本读取包装。
- `resources/vault-teaching/`：共同规则和11份相关Skill同步到Bash读写；保留原题、学生认知演变、复习字段和PDF原图要求。每次Bash（包括第一次）都在description写中文用途标记，标记不得混进command，操作过程仍按既有小字折叠行展示。
- `persona.js`：纯文本装配，教师自定义人格替代默认形象；子代理人格追加到各自任务角色后，不继承教师人格。不加入随机数、时间或轮次提醒，同一配置的文本保持稳定。
- `teaching-state.js / teaching-client.js`：教学设置新增“老师人格”，按原生会话事件保存、重开恢复，空白恢复默认大肥鱼。上限4000字符，旧草稿缺字段不清空已保存值。
- `solver-runtime.js / classroom-client.js`：各工作预设独立保存“工作员人格”。省略字段保留原值，显式空串清除；旧配置缺省为空，模型/工具范围和其他角色不被改动。`index.js` 的Remote精确字段表同步允许persona。
- `persona.md`：把角色设定转成具体互动行为。首次介绍放在工具完成后的最终可见答复中，中途只报告操作进度；避免介绍被原生工具过程折叠隐藏。

## 人格注入诊断

旧真实请求已经包含大肥鱼人格，并非完全漏注入。源码中常驻 `notara:teaching` 段位于后部，每次组装读取当前设置；子代理使用自己的persona段且排除教师教学段。旧真实请求使用 `systemPromptUpdate: in-history`；教法和人格改变时由原生机制更新系统提示。

浏览器发现另一个具体原因：模型把自我介绍放在第一次工具调用前的进度消息里，整轮结束后它随工具组折叠。第一次加强提示后仍出现该现象；第二次明确“中途不介绍，介绍留给最终答复”后，新课堂最终可见答复以“我是大肥鱼，接下来陪你一起学”开头。没有重写原生对话分组或用界面硬拼一句假模型回复。

人格冷恢复、同课设置切换的实际请求和子代理隔离已有测试；压缩后持续风格稳定性本轮未做真实长对话验证。不能将一次介绍成功宣称为所有场景都不会偏离人格。

首次集成19/22通过；两个失败来自测试误认为原生grep在行号后自带空格，另一个误把系统临时目录视为沙箱禁止路径。修正测试事实后通过，没有修改沙箱迁就测试。真实RPC还暴露configureSolver字段表漏persona，已补精确可选字段与回归检查。

首次批量试跑耗时73秒，产物与核验成功，但有一次用途标记被放入command，以及macOS不支持的`cat -A`探测；后续命令退出0掩盖了中间诊断。没有声称首轮零错误。规则现明确标记位置、平台适配和核对stderr，最终新课堂7秒读取回放未再出现这两项问题。两张题卡未编造学生作答，但“学生理解”用了未作答占位语而非严格空白，记录为内容质量限制，不扩大成整体教学质量通过。
