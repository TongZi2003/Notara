# 2026-09-16 教法透明化：教法树页面、工作区覆盖与人机共创

## 目标

用户要求「把教法文件彻底暴露在前端，左边栏加一个新页面，里面展示教法树，并且教法可编辑，做到人机共同创作，以及完全透明」。同时把上一轮讨论过的「教法进化」缺失环节接回：方法蒸馏入口 + 规划召回 + 收课沉淀约定。

## 设计决定

- **内置文件只读，用户改动存工作区覆盖**。`packages/host/lib/teaching-resources` 是构建产物，直接改它既会被构建覆盖也无法跨设备。生效规则：`effective = override.body ?? bundled`；`overridden = 有覆盖行且正文 ≠ 内置`。
- **恢复默认 = 把内置正文写回覆盖行**，不是删记录。`RecordStore.remove` 对被删 id 是终态（同 id `create` 会 `record_exists`），删除会让「恢复后再保存」失败；写回内置则留下一条「恢复」版本痕迹，CAS 照常工作，学生也能在记录历史里看到曾经覆盖过。
- **collection kind 定为 `teaching`**，让 `objectRef('teaching', 'preset_socratic')` 与提案/收据里的 target 完全一致——收据指向一条真实可读的记录，不是假 ref。
- **AI 改动走既有提案确认**：`propose_teaching` 产生 `teaching-override` effect（冻结 nodeId/title/body + target/baseline），学生确认后 executor 用 `saveTeachingOverride` CAS 落盘。直接编辑（页面）与 AI 提案共用同一个写函数，但提案有独立的校验段（node 可编辑 + target 一致 + baseline 未漂移）。
- **覆盖读取在每个注入点生效**：`teachingBody`（课程 preset 正文）、`system-prompt/assemble` 的 base/guided、`studyforge-teaching` provider `get()`、`studyforge-tasks` bundled 技能正文、`TeachingDelegation` 的 persona。已安装教法作品（`artifact/` 节点）只读展示——版本冻结的作品去作品页出新版。
- **委派帮手不获得这两个工具**：`read_teaching`/`propose_teaching` 进 `helperForbidden`；工具披露归新「教法」组。教法正文永远只是 persona 文本，不放宽子代理的 `ToolRestriction`。
