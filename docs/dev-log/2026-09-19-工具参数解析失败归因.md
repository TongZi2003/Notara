# 工具调用参数解析失败：静默降级链修复

日期：2026-09-19
来源：真实试用导出 `notara-conversations-2026-09-19.json`（Windows 试用机，会话「帮我安排数学分析习题课讲义」「保存通道是否已恢复」）

## 现象与根因链

试用机 k3 系模型发出的工具调用参数在三层容错中全部静默落成 `{}`：

1. `@earendil-works/pi-ai` `parseStreamingJson`：partialArgs → JSON.parse → 修复 → partial-json → 最终兜底 `{}`，零信号（`dist/utils/json-parse.js`）。
2. 流式累积 `block.partialArgs = "" + toolCall.function.arguments`：若 provider 把 `arguments` 以已解析对象下发，字符串拼接产生 `"[object Object]"` 永久污染（`dist/api/openai-completions.js`）。
3. `dsh-llm-pi-ai` `parseArguments` 注释即 "tolerate model malformations with {}"。

门面 `callShape.parse({})` 抛「method 缺失」→ 模型被指向「换参数格式」这个无效方向 → `dsh-repeat-tool-reminder` 数到 5 次 identical 调用后注入 guardrail → 模型继续无效重试。用户侧只看见「保存通道故障」并跨会话持续（配置级问题，换会话无效）。

## 实际改动

**上游补丁** `scripts/patch-tool-args.ts`（挂进 `patch-sdk.ts` postinstall 链，sha 校验 + 幂等 reversal）：

- `dist/api/openai-completions.js`：
  - 累积处非字符串 `function.arguments` 归一为 `JSON.stringify` 再拼接——对象型参数直接修好；
  - 收尾处 `partialArgs` 非空（且非字面 `{}`）却解析出空对象时打 `{__malformed_arguments: <截断原文>}` 标——静默 `{}` 变显式可检失败。
- `dist/api/anthropic-messages.js`：收尾处同款 marker（Anthropic `partial_json` 恒为字符串，无累积污染面）。

**门面归因** `packages/host/src/tools/tool-facades.ts` `execute`：`callShape` 前先检 `__malformed_arguments`（报「参数未能通过解析——模型与工具传输格式不兼容，如实告知用户并建议切换模型，勿重复同一调用」）与空对象参数（报「参数在送达前丢失」同款指引）。错误仍走 `rejected()` 信封。

**回归测试** `tests/integration/tool-disclosure.test.ts` 新增用例：`[tools]` 驱动 `find` 带 marker 与 `{}`，断言 isError 与归因文案（`未能通过解析`/`切换模型`、`参数在送达前丢失`）。

## 覆盖边界与未完成项

- **k3 的具体 wire 畸形形态未经实机确认**：对象型 `arguments` 这条已修；若是其它形态（截断、非 JSON envelope），marker 会把原始片段透传给模型与日志，下次导出可直接读根因。
- 其余 provider 文件（`mistral-conversations`、`openai-responses-shared`、`bedrock-converse-stream`、`pi-messages`）有同款静默兜底，未补丁——主流 OpenAI/Anthropic 兼容路由已覆盖，需要时再补。
- 试用机需 `npm install`（postinstall 跑补丁）后生效。
- 关联未修项（同份导出暴露，另行处理）：委派帮手全只读但提示词未教「提案只能主会话提交」；内部注入消息（guardrail/`[model changed]`/runtime context/agent UUID）进了「visible」导出边界。
