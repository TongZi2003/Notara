# 2026-09-17 真机演示三个缺口的修复

## 目标

学生故事真机演示（见 `2026-09-17-学生故事真机演示.md`）暴露三个工具面缺口，用户要求补齐：

1. 老师想拉「鸣人」进教室时 `update_classroom_context` 不能建角色——角色只能走学生侧 bench 编辑或插件安装，没有「老师提议 → 学生确认」通道。
2. `guided-learning.md` 已教模型把 web 找到的资料用 `create_markdown_material` 存库，但该工具不在 `tool-disclosure` 目录——`load_tools` 会报 `tool_not_in_catalogue`。能力存在但不可达。
3. **最要命**：`note_memory` 没要求先查重，21 条学情出现 6 对近重复；`revise_memory` 存在但从未被用。

## 设计决定（含一次被推翻的方案）

- **学情查重 = 常驻索引 + 成文约定，不做代码侧相似度门**。最初实现了 bigram 包含度候选扫描（`memory-index.ts`），用户指出 Claude Code/Hermes 式记忆不做这种写侧拦截——复核后认同：base.md 第 15 行本就写明「标签或词面匹配只是线索，相关性由阅读正文后的判断决定」，`MemoryIndex` 注释也声明 never ranks。真实根因是模型「盲记」——记忆里有什么它根本看不见。最终方案是把记忆面变成「一开始就在上下文里」：`studyforge:teaching` 段每轮注入**学情索引**（`[kind] 标题/正文头（ref）`，上限 40 条、超出提示分页），同一对象的再次观察直接落在对应 target 的 revise_memory 上；再配 `note_memory`/`revise_memory` 工具描述协议与 `base.md` 成文约定。空学情不注入；无 memoryService 的 harness host 落回无索引。domain 代码未改。
- **资料缺口是披露缺口，不是提案缺口**。`create_markdown_material` 本就允许老师把读到的 web 内容存库（`references` 携带原始 URL），与学生确认边界一致——资料层不走确认，挂进课程/路线才走 `route-edit`/`route-add` 提案。修法是把三个 markdown 工具加进「资料与卡片」目录组。
- **角色走新提案 effect `classmate-role`**。角色属于世界书文档（学生所有的配置），必须学生确认：effect 冻结 `id`（工作台贡献 id）+ 完整 `role`（`ClassmateSchema`），target = `worldbook:` + packageId(id)，baseline = 世界书记录 revision。确认时校验 target 一致、baseline 未漂移、无同 id/同名角色；`addRole` 复用 `writeContext` 的 CAS 写路径（expectedVersion=0 时 create，否则 update）。模型输入剥掉 `avatar`（上传派生）与 `route`（不该由模型发明 provider/model）。

## 实际改动

- `packages/contracts/src/proposals.ts`：`ProposalEffectSchema` 增 `classmate-role` 成员（编辑类，`effectTargetProblem` 自动要求 target+baseline）；import `ClassmateSchema`。
- `packages/host/src/plugins/classroom-runtime.ts`：`addRole(context, id, expectedVersion, role)`——启用校验、同 id/同名拒绝、CAS 写回 `document.classroom.roles`，entries/rules/既有角色不动。
- `packages/host/src/classroom-service.ts`：`propose_classmate` 工具（`roleDraft` 输入剥 avatar/route；读 revision 定 baseline；提案标题「新同学「名字」」）。
- `packages/host/src/proposal-executor.ts`：validate（target/baseline/教室启用/角色不重复）+ apply（`addRole`）；`classroom_` 前缀错误码纳入 ProposalEffectRejected 映射。
- `packages/host/src/tools/tool-disclosure.ts`：「资料与卡片」组补 `create_markdown_material`/`read_markdown_material`/`update_markdown_material`；「教室参与」组补 `propose_classmate`。
- `packages/host/src/teaching/teaching-context.ts`：`helperForbidden` 补 `propose_classmate` 与此前漏列的 `adjust_classroom_intimacy`。
- `packages/host/src/tools/memory-tools.ts`：`note_memory` 描述写明查重协议（对照学情索引或 search_memory 同桶枚举、read_memory 精读、同一对象用 revise_memory；仅不同维度才新建）；`revise_memory` 描述明确「再次观察也并入此 target」。
- `packages/host/src/teaching/teaching-context.ts`：`studyforge:teaching` 段注入学情索引块（`studyforgeMemoryService.search` 空 query 取前 40 条，`[kind] 标题/正文头（ref）` 每行一条；无记录或 harness 无服务时不注入）。
- `resources/teaching/base.md`：第 15 行末补成文约定——「记学情前先按 kind 枚举同桶、精读疑似条目：同一能力、习惯或处境的再次观察用 revise_memory 并入同一档，旧措辞与依据随之保留；只有确属另一维度才 note_memory 另建新档。」
- `packages/client/src/proposals/ProposalCard.tsx`：`classmate-role` 的 effectLabel（新同学）、confirmLabel（加进教室）、`ClassmateSummary` 展示（名字/性格/用途/instructions 正文/开场白/关系列表/说明行）；不进可编辑名单（学生要改可在确认后用 bench 编辑）。

## 未完成项 / 下一入口

- 学情查重是约定层修复：若真机重跑仍出现近重复，再考虑兜底（如每会话首次 note_memory 前必须 search_memory 过一次——只约束工作流不做语义判断）。
- `propose_classmate` 只支持新建；角色的修改/停用仍走学生 bench 编辑，老师侧修改通道可按需后补同类提案。
- 单会话连上多节课时只有第一次收课能进 handoff（一节课只能收一次）——真机演示遗留的设计边界，未在本次范围。

## 追加：常驻上下文面扩展（同日）

学情索引落地后用户推进同一原则：「还有一些信息适合常驻上下文」。逐项取舍后只加两块，明确不注入的也记录在案：

- **方法与知识索引**（`studyforge:teaching` 段，`teaching-context.ts`）：`studyforgeKnowledgeRecords.list` 取前 40 条，每行 `[category] 标题（knowledge:ref）`——ref 即 `revise_method` 的 target。配文「正文用 read_method 精读，同一主题的增补用 revise_method 并入对应 target，不另建新档」。这同时补上「规划端不召回方法」的旧缺口：方法面现在一开始就在上下文里。空记录不注入；无 records store 的 harness host 落回无索引。
- **学习目标行**：`course.learningGoal` 存在时注入一行「学习目标：标题（截止 X，每天 N 分钟）」，guided 之外也可见。
- **明确不注入**：到期卡片（学生不主动复习则每日清单是噪音，`list_cards(state=due)` 按需即可）、资料库摘要（体量无界，`list_materials`/`search_learning` 按需即可）。取舍原则：常驻面只放「不读也会写错位置」或「每轮都该知道」的信息；纯检索面维持渐进披露。
- 同步措辞：`note_method`/`revise_method` 工具描述补同款查重协议；`base.md` 第 15 行末补「记知识同样先对照上下文里的方法与知识索引……同一主题的增补用 revise_method 并入同一档」。

验证：`memory-index.test.ts` 新增第二用例——首轮无两块 → `[tools]` 驱动 `note_learning_goal` + `note_method` → 下一轮 prompt 出现目标行、`本学生已有方法与知识 1 条` 与 `knowledge:kn_*` ref。PASS。回归：assistant-boundaries 6/6、teaching-current 3/3、typecheck/build PASS。
