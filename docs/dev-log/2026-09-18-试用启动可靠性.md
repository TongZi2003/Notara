# 试用启动可靠性（trial launcher）

## 目标

用户反馈「有时候 404 网页打不开」，截图实证为 `ERR_CONNECTION_REFUSED`——端口上没有进程在听，是服务常驻问题而非 HTTP 404。另一环境（Windows，Codex 处理）确诊：包装启动器靠 PowerShell 解析终端输出找登录地址，`Notara 试用实例：` 中文行在 GBK 控制台乱码导致误判退出并带走服务。本轮把登录地址交接从 stdout 解析改为文件，并让 trial 自己开浏览器。

## 实际改动

### `scripts/dev-isolated.ts`

- `ready()` 的 `launcher.json` 写入挪到 authUrl 就绪**之后**，并增加 `authUrl` 字段（含登录 token）。隔离/试用根目录本就持有 DSH_HOME 机密（会话 cookie、签名密钥），token URL 同一信任级别；`redact()` 只管日志输出不受影响。
- 效果：任何包装层读文件拿登录地址，不再需要解析 stdout——对中文 Windows 控制台编码差异免疫。`restart()` 路径自动重写新 authUrl。

### `scripts/trial.ts`

- `openBrowser(url)`：平台感知打开（win32 `rundll32 url.dll,FileProtocolHandler`——绕开 cmd 对 `&token=` 的分词坑；darwin `open`；linux `xdg-open`），detached+unref、失败静默（URL 已打印，可手动开）。`--no-open` 参数可禁用（无头环境）。
- 输出新增明示：「此终端窗口即 Notara 服务本体——窗口关闭服务即停止」——直接回应 CONNECTION_REFUSED 的根因认知。

### `README.md`

- 试用步骤同步：自动开浏览器、launcher.json 的 authUrl 供脚本读取、窗口即服务本体与「重新 npm run trial」的恢复路径。

## 背景排查记录（本机隔离实例实测）

HTTP 层的 404 机制与本次症状无关但已记录在案：`dsh-host-frontend-static` 无任何 Cache-Control 头（旧 index 引用已消失哈希资源会 404）；无 SPA fallback（未知路径裸 404）；`/api/` 未注册 remote 名返回 404（版本错位场景）。这些是上游 `dsh-*` 包行为，若日后出现「页面 404 但服务在跑」的反馈再评估补丁。

## 验证

- `./node_modules/.bin/tsc -p scripts/tsconfig.json` PASS
- 实测 `tsx scripts/trial.ts --port 0 --no-open`：启动成功打印三行输出；`.trial/launcher.json` 含 pid/parentPid/workspace/node/**authUrl**；`lsof` 确认端口监听；`GET /` 无 cookie → 401（鉴权栅栏正常）；SIGTERM → 子进程干净退出；`.trial/` 已清理
- `openBrowser` 的 macOS/Windows 实际弹窗未验证（避免在本机弹浏览器；分派逻辑仅 spawn 平台命令）
