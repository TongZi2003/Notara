# 自由课「编成路线」钩子

## 目标

学生随便新开的自由课（不在路线、没有接续）收课后，需要一个钩子提醒他「可以进行下一步学习，并编成一条路线」。拍板结果：钩子分两侧——学生侧是 HandoffEditor 的一行条件提示，教师侧是 guided-learning 的收课规则；不做自动弹窗或自动提案，仍守提案-确认模式。

## 改动

- `packages/client/src/classroom/HandoffEditor.tsx`：新增 `onRoute` 状态——小结就绪后经 `studyforgeOrganization.route()` 查被看小结所属课（`view.sessionId`，非当前课）是否被某路线节点的 `session` 绑定；`onRoute === false` 时在操作区下渲染 `handoff-route-hint`（「这节课还不在任何路线里——想让老师把接下来的学习编成一条路线……它会先回看之前的经历再提一份安排」）。读失败/进行中不显示（不错误提示）。
- `resources/teaching/guided-learning.md`「续接与下一段」补一段：收不在路线上的自由课时，目标未完且下一步不止一节，小结的下一步建议里写清可编成路线；学生要求排路线时先 `open(method=journey)` 再 `propose(method=route)`；学生没提出时不替他决定。

## 判定语义

- 成员判定按「小结所属课的 sessionId 是否出现在某节点的 session 绑定」——不是「路线是否存在」：自由课在已有路线的工作区里仍提示（e2e 已覆盖此边界）。
- 路线课（含已绑定未开完的）不显示提示；接续课看到的是上一课的小结，判定仍落在来源课的 sessionId 上。
- 提示只指方向不代操作：学生在新课里说出来后，教师走 journey 索引 → `propose_route` 的真实链路。

## 验证

- typecheck / build：PASS（`lib/client.js` bundle 含新代码——注意 client 改动必须跑 `npm run build` 出 esbuild 产物，`tsc --build` 只出 types 层，e2e 曾因此吃到旧 bundle 假失败）
- e2e `coauthor-handoff.spec.ts` 新增用例 PASS：自由课小结提示可见 → 路线出现但绑定的是别的课，提示仍在（成员判定）→ 路线课经真实收课后切到其工作区，提示不显示；spec 全量 5/5 PASS
- 无单测层（条件在 React 组件内，由真实浏览器断言覆盖）；live 未运行
