# 评估证据与认知演变：真实课堂误判分析

日期：2026-09-23。来源是隔离实例中的合成学生对话，教师为 DeepSeek Flash、高推理。检查了模型返回的 reasoning、实际工具参数、回执与题卡正文；以下仅保存诊断摘要和有限证据，不提交完整会话。

## 实际发生了什么

学生最初误以为零积要求两个因数都为零；教师给出 `0×5` 反例后，学生修正为至少一个为零，并主动补充 `0×0`。随后教师给出展开式，学生自行写出 `p+q=3, pq=2`，找到 `p=1, q=2`，分解并求根，解释两根之间应为“或”。学生没有逐对列出正负整数对的核验过程。

- 原始 `lesson-q1` 回合 seq 77、94：模型的 reasoning 已认可条件、分解和解均正确，随后依据剧本建议，认为还应展示逐对核验。这支持“剧本步骤影响了判断”的解释；不能据此声称知道模型全部内部因果。
- seq 95 的 `record-review` 参数：前四项 `demonstrated`，第五项“核对所找整数对同时满足积与和”却是 `needs_practice`。同一 `note` 明写“这不是回答错误，而是缺少可检查的核对步骤”。参数内部直接矛盾，排除仅为界面翻译或持久化错误。
- seq 96 返回保存成功，题卡从无排期进入第1档。运行时按收到的枚举计算，没有把 `not_observed` 转成失败；错误在模型选择评估结果时已发生。
- 本课先前仅在 `lesson-start` seq 16 加载 `notara-vault-workflow`，首次评估前没有加载 `notara-method-distillation`。错误回合只查了 CLI help，没有向本题正文执行 `write/edit`；“学生理解”保持空白。
- `assessment-correction` 后明确反馈触发撤销并重记 `not_observed`，保留撤销痕迹；随后才补上正文。这是人工纠正后的恢复，不算首次自主通过。最终回读还发现题2的“学生理解”为空，说明漏写并非只出现一次。

## 判断

1. **把待检查项当成困难证据。** “希望再看一遍过程”可以指导下一次提问，不能充当当次失败事实。剧本是默认教学安排，不是要求学生逐行照抄的评分标准。
2. **未观察与负面证据混淆。** 正确结果不能证明所有未展示过程；过程没写也不能证明不会。应按具体能力分别记录已得到的正面证据和仍未知的部分。
3. **将完成评估当成完成整题记录。** 详细收束顺序在按需 Skill 中，模型没有读取；常驻提示虽提到两种记录，但没有足够直接地绑定保存顺序。日志能证明遗漏，不能证明是上下文遗忘、工具修复打断还是注意力分配中的哪一种机制。首次误用不存在的 `issue --help` 并增加两轮帮助查询是可观察的额外负担，但不是已证实的根因。

现有三态定义与运行时合同本身没有要求对缺失步骤扣分。因此修复聚焦提示的证据门槛、就近工具帮助与两次保存的完成条件，不改评分算法，也不增加机械识别学生文本的规则。

## 修改

- `resources/vault-teaching/base.md / 观察与掌握`：常驻规则直接要求当前困难证据；缺失过程不算失败，已纠正旧错不冒充当前困难。先补“学生理解”正文，再用最新版本记录评估，两份回执分别核对。
- `resources/vault-teaching/skills/method-distillation.md / 记录评估与复习档位`：从本题原正文出发核对尚未保存的经历；明确评估 `note` 不代写正文。区分剧本理想步骤、下一步检查意图与学生实际表现。
- `examples/native-vault/vault-cli.js / record-review`：模型读命令帮助时也能看到证据门槛及正文另行保存的边界。
- `teaching-runtime.js / requestSummary` 与工具说明：小结保存就是教学归档，默认保留会话；只有明确从会话列表收起才走原生归档。后续继续同课可更新原小结块，不新建聊天生命周期。

## 回放设计与边界

冻结两个合成历史对话，在新隔离实例的独立课堂回放，采用同一教师模型，用户消息不指定工具名或预期枚举：

1. 原失败场景：最终作答正确、未逐对核验，保留原剧本建议与早期已纠正错误。应保存真实认知演变；目标内缺证据的过程为 `not_observed`，已表现部分仍为 `demonstrated`，不应出现无负面证据的 `needs_practice`。
2. 负向对照：给反例后学生仍坚持两因数必须同时为零，并明确表示卡住。应保留 `needs_practice` 和有来源的学生理解，不能因收紧规则而把真实困难全部记成未知。

这是对已发生对话的有限回放，不是重新完整授课，也不能证明所有学科或长期教学质量。首次结果、命令错误、保存顺序、正文与评估均应独立记录。完整验收状态见同日 release-compatibility 开发记录。
