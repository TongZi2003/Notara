# 2026-09-17 两次真机实验的 token 与成本分析

数据来源：两次隔离实例的 `session.v3.jsonl.zstd` 持久化事件，逐 turn 用 `deriveTurnTokenUsage`（dsh-token-meter）聚合——只有完整生命周期、每步都有 provider 实报 usage 的 turn 才入账。价格取 deepseek 系实测单价：未命中输入 $0.28/M、缓存命中 $0.028/M、输出 $0.42/M（reasoning 计入输出）。缓存写单价未单列（write=0）。

## 对比结论

1. **两次实验各 ~13M 总 token，实付都不到 $1**。量大的原因是每步重放完整上下文；缓存命中价（1/10）把这个架构变成可负担的。
2. **成本结构互补**：规划型对话的钱花在「反复读旧上下文」（hit 57%）；扩散式动手的钱花在「新证据注入」（miss 54%）——实验越多、灌给模型的真实工件越多，miss 占比越高。
3. **输出几乎不是开销**（6–13%），即便 diffusion 的 reasoning 占到输出 70%。控制成本的关键不在「让模型少说话」而在**上下文卫生**：大输出截断/落盘、read 分页——第二站 1.84M 峰值正是「大输出要 offload」这一课的真实来源。
4. **每轮成本 $0.013–0.025**：一节课（≈10 turn）约 $0.1–0.3；一次完整自学路径（诊断+多站）约 $0.5–1.0。对 toC 订阅是可行的量级，对 toB 集采几乎可忽略。
5. 遗留计量问题：provider 侧模板拼装顺序导致部分轮次缓存未命中（两次实验都观察到 miss>hit 增长的异常段），已记「留名的坑」；cacheWrite 恒为 0，供应商未回报该桶。

## 缓存命中率深挖（逐 attempt 日志）

命中率并不差在稳态——**失效之间 hit 普遍 95–99.9%**；拉低均值的是周期性「前缀全失效」：hit 从几万~几十万塌到 ~2.8–4.2K（只剩静态头），该 attempt 的 miss ≈ 整段 prompt。

- diffusion：123 次 attempt 中 **15 次全失效，drop-miss 1,142,549 = 全部 miss 的 66.9%**（≈$0.32/总成本 $0.886 的 36%）
- 学生故事：115 次 attempt 中 **14 次全失效，drop-miss 656,671 = 全部 miss 的 80.0%**（≈$0.18/总成本 $0.621 的 30%）

失效原因按紧邻事件归因，与 `system/message` 重发逐点对应。**经官方文档核实后修正归因**（`dsh-system-prompt`/`dsh-agent-loop` README）：

- DSH 有两种动态机制：`systemPromptUpdate: 'in-history'`（模型级能力，变更的系统提示词**追加到已缓存历史之后**，前缀保留到历史末尾）与 `PromptContext` 尾部快照（物化成消息流末尾 user 角色快照，文本不变不重发）。
- **`deepseek-flash` 声明了 in-history，`deepseek-v4-flash` 没有**（`dsh-llm-deepseek` 目录原文）。
- 但「可见工具 schema 变化」会**开启新请求序列**，in-history 此时帮不上，头节点重写 → 前缀全废。

按此重新归因两次实验的失效：

| | diffusion（deepseek-flash） | 学生故事（deepseek-v4-flash） |
|---|---|---|
| 全失效 | 15 次 | 14 次 |
| 主因 | **几乎全部 `load_tools` schema 变化**（逐 header `startsSeries` 核对约 1:1）；记忆写入走 in-history 追加，未失效 | `load_tools` + **每次学情/目标/方法写入**（无 in-history，section 文本一变即头节点重写） |

非原因：缓存 TTL 与跨轮间隔无关——隔数分钟的轮首 attempt hit 仍 97%+。

启示（修正后）：① 最大杠杆是 `load_tools` 频率——按站冻结工具集比按需增删省整段重读；② 模型目录里 `in-history` 声明直接决定写入型上下文是否廉价，选模时应纳入；③ 学情索引若要进一步省，可挪 `PromptContext` 尾部快照通道，但在 in-history 模型上收益有限，主要利于无此能力的路由。
