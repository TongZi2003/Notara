# 2026-09-17 层级归属铸结构（anchored content mints structure）

## 目标

拆书流程审计暴露的根本矛盾：卡的 `chapter` 必须是已保存骨架路径，否则 `card_chapter_missing` 拒绝——备课精读时正是制卡挂层的时机，但骨架还没长到那层，卡只能堆书根或被拒；挂书根的卡不进任何章节复习范围（`selectCardRows` 按 chapter 前缀匹配）。用户要求根本解而非提示词补丁或同提案排序。

## 架构决定

**翻转依赖方向：锚定内容自己铸造结构，结构不再是内容的前置条件。**

一张卡的 `sources` 经过字节级锚点校验（`resolveAnchor`），它自己就证明所引层级存在——这是本轮的支点（用户原话：「卡是建立在原文事实上的，他在解释上不会出问题，唯一会出问题的可能就是对于这本书的层级」）。所以单源卡声明缺失 `chapter` 时，写卡的**同一个原子单元**顺带铸出该层的 `outline` 节点，锚点用这张卡自己的来源。

归属因此是「按当前阅读先入为主的假设」，配套完整勘误链（全部既有能力，未新造）：

- 卡挂错 → `update_card` 换 chapter，新层同样顺带铸
- 结构错 → `propose_skeleton` 的 `repath` 整层改名/移位，挂靠卡的 chapter 原子跟走（`SkeletonAuthoring.dependencies` 级联）
- 烂层 → `removePaths` + `detachDependents`，卡的 chapter 清空回书根
- 铸出的 `outline` 层日后被拆书精读 → `refined` 正常替换（merge 同路径覆盖）

## 实际改动

- `packages/domain/src/organization/chapter-deriver.ts`（新）：`ChapterDeriver implements ChapterPlacement`。`plan(ctx, claims)` 按书聚合——同一本书一批缺失层级合并成**一次**骨架变更（防 `duplicate_atomic_target`），节点 `{path, sources: 卡内该书锚点, detail:'outline'}` 经 `SkeletonNodeSchema` + `reader.validate` 再校验；骨架不存在时 `prepareCreate`，存在时 `prepareUpdate` 以当前 revision 为 `expectedVersion`，子操作号 `${opId}:skeleton:${materialId}`。`atomic` 直转 workspace publisher。
- `packages/domain/src/cards/card-service.ts`：
  - `ChapterClaim`/`ChapterPlacement` 端口；构造函数第 5 参 `chapters?`
  - `CardRecordStore` 接口补 `prepareCreate`/`prepareUpdate`（真实 RecordStore 本有）
  - `create`/`edit`：有派生计划时改走 `chapters.atomic([...骨架计划, 卡计划])` 同一原子单元；`edit` 只在 `change.chapter||change.sources` 被触及时评估（与 `prepare` 重校验条件一致，避免无关元数据编辑被陈旧 chapter 拖累）
  - `assertChapter`：路径不在骨架时——`chapters` 已接 + 恰好一本来源书 + `SkeletonPathSchema` 格式合法 → 放行待铸；其余（无来源/多书/坏路径/未接派生器）照旧 `card_chapter_missing`
  - 新公开 `placementPlans(ctx, contents)` 供批量写卡方并入同一原子批
- `packages/host/src/index.ts`：`CardService` 注入 `new ChapterDeriver(skeletonRecords, skeletons, owner)`
- `packages/host/src/tools/card-tools.ts` `register_cards` 与 `packages/host/src/teaching/native-delegation.ts` `proposeProblems`：原子批前并入 `placementPlans`（后者当前卡无 chapter，是语义统一的空操作）
- `packages/contracts/src/cards.ts` chapter 描述、`packages/host/src/tools/proposal-tools.ts` `propose_card` 描述同步新语义
- `resources/teaching/guided-learning.md` 备课段：chapter 直填层级路径缺层顺带铸 outline + 勘误路径说明
- `tsconfig.base.json`：`@studyforge/domain/chapter-deriver` 补 src 映射（漏配会解析到 lib/types，与 src 的 `RecordStore` 私有字段双声明冲突——已踩并修）
- `packages/domain/package.json`：导出 `./chapter-deriver`

## 保持的不变量

- 每个骨架节点仍 ≥1 个真实锚点，锚点仍过 `resolveAnchor` 字节级校验
- `detail:'outline'` 如实标注「这是卡的落点声明，不是全章精读」；`refined` 的 Host 读取凭证校验不受影响
- 原子性靠 `owner.atomic` 的 before-fingerprint 复查：plan 到 publish 之间骨架被并发改动 → `version_conflict` 如实拒绝，调用方重跑重规划
- 幂等：同 operationId 重放 → 卡 duplicate 返回、骨架路径已存在不重复铸
- 逐项确认与版本冲突语义不变；`bindTaskCard` 拆书任务内更严的 chapter 规则不动
- 无来源卡/多书卡/坏路径仍拒绝——派生只在归属无歧义时发生
