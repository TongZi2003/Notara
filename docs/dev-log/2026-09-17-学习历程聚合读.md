# 学习历程聚合读（read_journey）

## 目标

用户要求：「ai 如何读到上一段经历，包括之前所有经历的结果，只要有了这个，就能无缝衔接」。核心不是推荐 UI 或自动开课，而是给教师模型一份「全部既有经历结果」的连贯读面，续接/规划下一段由此自然发生。

## 关键设计取舍

- **历程不是新记录**：全部派生自已存在的不可变源（handoff 记录、路线绑定、卡片账本、学情/知识记录），读是投影不产生写入。
- **渐进式披露（用户拍板）**：视图收成索引——小结只有 `ref+version+title` 与事实清单，能力信息本就沉淀在学情里，正文一律按需读。典型返回从 10~50KB 降到 ~5~15KB；`JOURNEY_BODY_CAP`/`truncated` 随之下线。
- **read_handoff 不被替代**：本课 pin 语义照旧；journey 里每份小结给当前版本 + `continuedFrom` pin，链可追，全文由它按需读。
- **无注入式快照**：没进 assemble 自动注入——发现路径靠 facade 速查 + guided-learning 指引。
