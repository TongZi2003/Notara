# 2026-09-16 开发规则提炼（AGENTS.md）

## 目标

从母仓库 Oh-My-Student 的开发制度与 Codex 开发会话中提炼仍然成立的经验，充实本仓库给开发 Agent 的规则文件 `AGENTS.md`。

## 经验来源

- `Oh-My-Student/CLAUDE.md` 维护规则：状态文件只记当前事实、逐轮交接进 dev-log、锚点用文件+函数名、验证状态只表达证据不表达信心、证据分层互不替代。
- `Oh-My-Student/AGENTS.md` 红线中可迁移的部分：不杀自己跑在其中的服务进程、批量写入走工具不手写循环、参数形状照抄文档不靠猜。
- `~/.codex/sessions` 中 `cwd=Oh-My-Student` 的 40 个主会话（2026-08-28 至 09-15）与 `cwd=DSH` 的 2 个会话。主要提炼点：
  - 用户全局工作约定（每个会话注入）：最小完整改动、比例化验证、能发现就不追问、诊断不修代码、不造流程仪式、主 Agent 保留核心判断、探测派子 Agent。
  - 评审消化方式：审计与计划结论逐条对照原文核实再执行；计划评审抓出过合同级矛盾（顺带通道归属、confirmationId 确定性推导、sourceDigest 语义悬空）。
  - 「旧进程给假绿」：改服务代码必须重启验收——与 DSH 旧课堂绑定同一教训。
  - 学生文案事故：「服务端/落盘/体检零错零警」泄进学生端，由此产生文案边界规则。
  - 空态三态区分（零卡/过滤为零/搜索为零）与「没有任何测试断言过空态」的缺口教训。
  - 过度防御误伤：交接提示清洗把「1.5:2 的比例化简」当成路径清掉——防护收窄到明确边界。
  - 「同一合同分散多处」导致已注册工具漏进调用检查名单——合同单源派生。
  - `passWithNoTests:false`：空套件是设计内红灯，不用兜底伪装 PASS。
  - 隔离根目录不回收残留会话凭据——本仓库 `dev-isolated.ts` 的 `stop()` 已含 `rm(root)`，规则保留为执行要求。
  - 术语规范的起源：用户指出「账」是 AI 中文——用正式专业名称。
  - 内测规模裁决：跑得动不串账户即可，工程规模对齐当前阶段。
  - DSH 数学工作台会话：隔离环境误解、实例混淆、版本锁定、悬空绑定、未复现就报修复（上一轮已收录）。
