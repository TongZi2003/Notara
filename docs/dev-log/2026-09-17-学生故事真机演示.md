# 学生故事真机演示（Devin-in-the-loop）

日期：2026-09-17 ｜ 模型：deepseek-v4-flash（官方 API）｜ 实例：隔离 DSH_HOME + 临时课堂目录

## 目标

把「迷茫高中生自学」的核心链路在**真实模型**上完整演一遍：不带资料开场 → 诊断 → 定目标 → 排路线 → 导入材料 → 上课 → 沉淀卡片/锦囊/学情 → 复习留存 → 新旧知识连接 → 低自信识别 → 世界书角色鼓励。不由固定剧本驱动，由 Devin 扮演学生、根据模型每轮真实反应决定下一句。

## 方式

- `zz-story-up.mts` 常驻隔离实例（testModel:false，DEEPSEEK_API_KEY 注入，不落盘）；`zz-story.mts` 逐轮驱动（say/status/confirm/transcript/material）。
- 学生侧每轮先读 transcript + 工具调用 + 待确认提案，再决定回什么。提案一律由"学生"点确认。
- 世界书插件经 `studyforgePlugins/prepare→installPackage`（开发目录）装进课堂工作区，`useWorldbook` 绑定到会话；鸣人角色由学生侧 `saveWorldbook` 写入 `classroom.roles`。

## 实际发生（按天）

1. **诊断日**：模型不上来就排课，先问资料、假期、日期纠错（"寒假"与系统日期不符被它自己抓住），出一道 x²−5x+6>0 做四关口探针。学生故意写错解集方向，它用代入 x=4/x=0 让学生自己发现；再出 −x²+5x−6>0 让口诀现形；逐步推到顶点、单调区间、无实根的图象含义。`note_learning_goal`、`note_memory`（带 basis 引用学生原话）、`note_method` 落知识笔记，最后 `propose_handoff` 出《诊断小结》待确认。
2. **路线**：`list_plans/list_sets/read_route` 后 `propose_route` 出 5 课（每课带 stance 引用诊断依据、检验方式、"学生点头才算"）。学生确认后 5 条 route-add 全部 applied；讲义经 `importText` 导入后由 `read_material` 读入并确认挂进第 3 课（materials 里钉住 versionId）。
3. **第1课（f′↔图象）**：学生带学校原题 x³−3x，模型点破老师板书省略的中间步；学生独立完成单调区间并自创"没 f 可代就代 f′ 抽查"。模型声称"留一张卡给你点"但未调工具——学生戳破后自我修正 `propose_card`（洞察卡：检验≠证明）。
4. **第2课（定义法）**：学生复述卡片内容成功（隔夜留存），并独立想出"任取两点比较"——即单调性定义；判掉 x² 在 R 上递增的假命题并给反例；证明 1/x、x+1/x 的单调性，自己点破"基本不等式取等点=单调性分界点=f′=0 处"是三回事一回事。
5. **第3课（基本不等式）**：从 (√a−√b)²≥0 推出不等式；"先写第一反应"环节学生第一反应已是正确方向（昨天方法迁移）；乘1法走通。`route-edit`×2 把学生选的第4课改向"跟住学校进度"。
6. **情感与世界书**：学生自述"被说不是学数学的料"+喜欢鸣人。模型 `read_classroom` 发现角色为空，`update_classroom_context` 只能写 entries（设计如此：角色不在该工具的写入面）——它如实告知"椅子是空的"并给出甲/乙两条路。学生走甲：saveWorldbook 把 naruto 角色写进 roles。再说泄气话时模型 `ask_classmate` 成功——鸣人开口："上周参数那节我也一整节没跟上……没弄懂，但笔没停。"符合全部禁令（不讲题/不报答案/不评价）。
7. **第5课（验收）**：模型出 f(x)=x³−3x²−9x+a 三问，第(3)问"恰好两个实根"正是学生昨天那句"极值点和零点撞在一起"的闲话变成的工具。学生无提示做完，且**核出模型推理中的真错**：模型追问"什么时候零个根"（其内部 reasoning 认为 a<−5 或 a>27 时零根），学生答"不存在——三次曲线两端通向相反无穷且连续，至少穿一次轴；那是恰好1个根"。模型验算确认。第二张卡（三次函数根数↔极值位置）经确认落库。

## 落账（持久层实况）

- 卡片 2 张；锦囊/知识笔记 4 条；学情记忆 21 条（ability 观察均带 basis 指向学生原话；situation 含"长期被否定经历"的情感记录）。
- 路线：route-add×5 + route-edit×2 全 applied；诊断小结 handoff applied。
- 材料：讲义导入并以 versionId 钉进第 3 课。
- 世界书：绑定会话，entry（关键词触发：不想学了/撑不住/跟不上…）+ naruto 角色 enabled；`ask_classmate` 全链路走通。
- 工具调用面：list_materials/search_*/note_*/propose_*/read_route/read_material/read_classroom/update_classroom_context/ask_classmate/read_thoughtmap/summarize_stage 等，全部真实发生。

## 发现与限制

- **模型诚实性超出预期**：日期矛盾自查、"这次是我说得太满"、承认差点误判学生答案、被学生戳破"卡没发出去"后自我修正。
- **发现一处真实缺口**：`update_classroom_context` 按设计只能写 entries，不能建 roles——老师工具面里没有"建角色"的入口，导致鸣人首次触发时 `ask_classmate` 返回"教室里没有这个角色"。这暴露了工具面的不对称：世界书角色目前只能经学生侧 saveWorldbook（bench 编辑）或 creation→install 写入。若要"老师可提议角色、学生确认"闭环，需要新增一条 proposal effect（如 classroom-role）——记为后续工作。
- **模型也会犯错**：最后追问的"零根区间"是错的（连续三次函数必有实根），被学生抓出——恰好成了故事最好的验收：方法迁移到了"核对老师"上。
- 演示为隔离实例，数据根在临时目录；DEEPSEEK_API_KEY 仅经环境变量注入，未落盘。
- 未验证：卡片复习调度界面（复习发生在一夜之间由学生自述完成）、语音鼓励、番茄钟——后两者本就不在现有机制内。
