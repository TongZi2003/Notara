# 多角色教学回合（TeachingRound）

## 目标

把「出题→学生作答→同伴评审→助教勘误」做成持久化的 Host 编排：三个角色各绑定一个真实原生子会话，学生有自己的作答回合与专用面板，参考标准只进助教 brief，子会话身份不出 Host。这是计划四件套的第四件（前三件：前端搜索面、Atlas 页内编辑、PDF 文本层）。

## 实际改动

### 合同 `packages/contracts/src/teaching-rounds.ts`

- `TeachingRoundRecordSchema`：sessionId、topic、materials（帮手唯一可依据的原文片段）、standard（隐藏参考标准）、stage（`writing|answering|awaiting_correction|completed|failed|stopped`）、cardRef/questionTitle/questionFront、answer、三个 `RoundActor`（role/state/childId/text/detail）。
- `TeachingRoundViewSchema`：学生视图——剥掉 `standard` 字段与每个 actor 的 `childId`；`RoundActorViewSchema` 由 record actor `omit({childId})` 派生，单一合同源。
- `RoundOpenInputSchema`/`RoundAnswerInputSchema`/`RoundRefInputSchema`：open 输入含 topic/materials/standard/constraints/sources（`SourceAnchorSchema` 复用，题卡挂真实来源）。
- `contracts/package.json` 补 `./teaching-rounds` 显式 export——typert 生成器不解析 `./*` 通配，只有显式条目能被 remote 边界引用（本轮实际踩到的坑）。
- `tool-facades.ts` 加 `round` 门面（open/read/answer/correct/stop 五方法）；host 侧 `tools/tool-facades.ts` 同步门面描述；`docs/runtime/tool-disclosure.md` 常驻计数 11→12。

### Host `packages/host/src/teaching/rounds.ts`

- `TeachingRounds`：`teachinground` collection 持久化；`tail` 串行队列保证同一 Host 内阶段变更不交错。
- `open`：先落 `writing` 记录再跑 `delegation.proposeProblems`（复用「子代理产草稿→Host 校验→原子登记」链），成功后 stage→`answering` 并把 `cardRef/questionTitle/questionFront` 落库；失败 stage→`failed`、problem actor 记 detail，**不补写题目**。
- `answer`：学生原话逐字入库 → peer 跑 `peerTask`（只给 materials+题面+学生原话，无 standard）→ stage→`awaiting_correction`；peer 失败不阻塞勘误，actor 记真实原因。
- `correct`：assistant 跑 `assistantTask`（materials+standard+学生原话+同伴原话）→ stage→`completed`；失败保持 `awaiting_correction` 可重试。
- `stop`：interrupt 仍 running/queued 且持 childId 的子会话，全部停成才把 stage→`stopped`；有未停成的如实报错。
- `viewOf`：唯一的学生视图出口，剥 `standard`/`childId`。
- peer 的 `question` 传 `questionFront ?? topic`（本轮修正：评审应见真题面）。

### 学生 remote `packages/host/src/rounds-service.ts`

- `StudyForgeRounds`（`studyforgeRounds`）：list/read/answer/correct/stop；全部经 `studentContext` 绑定会话派生上下文，mutation 自带 `round:<tag>:<uuid>` operationId，answer/correct 带 180s AbortSignal。
- 学生侧没有 open——开回合是教师动词（`round_open`/`round(method=open)`）。

### 模型工具 `packages/host/src/tools/round-tools.ts`

- `round_open/round_read/round_answer/round_correct/round_stop`，全部经 `teacherContext(host, execution)` 派生上下文，长操作透传 `execution.signal`；输出过 `TeachingRoundViewSchema` 校验。

### 装配 `packages/host/src/index.ts`

- `registerDelegationTools` 返回值捕获为 `delegation` → `new TeachingRounds(ctx, owner.collection('teachinground', …), delegation)` → `provide('notaraRounds')` → `ctx.plugin(StudyForgeRounds)` → `registerRoundTools(ctx)`。

### 客户端

- `workspace-layout.ts`：`VIEWS` 加 `'rounds'`（第四个工作台视图，布局树/停靠/持久化自动兼容）。
- `RoundsPanel.tsx` + `rounds-panel.css`：回合列表（>1 时下拉选择）、阶段徽章、题卡面（含「已收进卡片库」提示）、作答输入、求勘误按钮、三角色原话逐字呈现（problem 的产物是卡本身故无 text）、active 阶段的停止按钮；4s 轮询 + focus + `studyforge:learning-changed` 刷新。空态/失败态如实显示。
- `LearningWorkspace.tsx`：`BASE_LABELS` 加「回合」、`ViewIcon` 三圆点图标、渲染分支 `view==='rounds'`。
- `client/index.tsx`：`registerLearningWorkspace` 的 inject 加 `'remote.studyforgeRounds'`——cordis 要求每个 remote 命名空间单独 inject，漏了就报 `cannot get property without inject` 并导致 slot 崩溃（e2e 抓到的真错）。
- `styles.d.ts` 加 `*/rounds-panel.css` 声明。

### 提示词 `resources/teaching/guided-learning.md`

- 备课段新增回合规则：何时 `round(method=open)`、materials/standard 的填法、出题失败不代写、学生可在面板作答与求勘误、不替他转述角色意见。

- `npm run typecheck` PASS；`npm run build` PASS；`npm run generate:remotes` PASS（生成物含 `studyforgeRounds` 命名空间与全部方法）。
- `npm run test:integration -- tests/integration/teaching-rounds.test.ts`：3/3 PASS——全链（出题→作答→同伴→助教）+ 真实请求日志证明同伴请求无 standard、助教请求有 standard + 视图字段级边界（无 `standard` key、无 `childId`）+ 卡恰登记一次 + 失败回合诚实 + stopped 终态拒答。

- 回归：`test:unit` workspace-layout 3/3（种子树改 4 叶）、tool-disclosure 5/5；e2e classroom-trace 4/4、workspace-docking 5/5。

## 验证中发现并修正的设计点

- **助教 `text` 含标准不算泄漏**：合同是字段级（视图无 `standard`/`childId`）；勘误原话本就在学生作答锁定后才产生，揭示答案是勘误的职责。时序上 `writing/answering/awaiting_correction` 任何阶段视图都不可能有助教文本。测试断言相应改为字段级。
- **命题帮手无 `text`**：其产物是登记的题卡（questionFront 呈现），`proposeProblems` 不返回散文，actor.text 留空是正确语义。
