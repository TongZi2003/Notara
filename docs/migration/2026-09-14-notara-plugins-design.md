# Notara 插件系统第一版

用户已确认按本方案写文档、计划并直接实施；子智能体仅侦查，主 Agent 负责实现。

## 学生体验与完成标准

在“插件”页选择本地插件包或开发目录，先查看名称、版本、新增能力及权限，再安装。安装后技能进入同一套“＋”和 `/` 候选，工作台进入课堂视图并复用拖拽、关闭、恢复和两主题。停用或卸载移除入口，已保存的笔记仍在资料库。

必须实际验证：外部包安装 → 技能与工作台出现 → 使用 → 确认保存笔记 → 停用 → 卸载 → 原笔记可查看，以及重复安装、失败升级、重启恢复和既有课堂版本不被替换。

本体仍独立提供拆书、学习、记笔记、沉淀记忆；对话、思维图、资料工作台不可卸载。扩展出题技能与复盘笔记工作台组成示例包。世界书、动态课堂与新增帮手执行合同不属于本次能力实现，声明未知能力必须拒绝，不能只展示名称冒充支持。

## 包与版本

采用标准 npm `package.json` 的 name/version/dependencies，增加 `notara` 声明：`apiVersion: 1`、title、description、skills、workbenches、teaching、subjects。各贡献声明稳定的局部 id、title、description、entry；subject 另声明科目列表。工作台入口为自包含 HTML，可声明 `save-note` 权限。技能、教学模式、教法正文按需读取，不全量注入课堂。

安装器只接本地目录与 `.tgz`/`.tar.gz`。依赖处理使用锁定的 DSH `plugin` 命令及其 pnpm 通路，在每次安装独立的 DSH_HOME/profile 解析，不修改运行 profile。预置空 bundles，关闭安装脚本，要求代码包预构建。目录先复制为快照，忽略 .git/node_modules，拒绝符号链接与路径越界；包名不用于拼接任意系统路径。

准备阶段生成不可变快照与安装预览；确认阶段按预览 digest 安装，不重新读取开发目录。包身份由名称派生，版本内容由 digest 标识。同名同版本不同内容拒绝；相同快照重复提交幂等；更新保留旧快照，先验证新版本，失败保留旧版可用。

## 原生加载与状态

纯声明包的能力由产品贡献登记层加载。带 `dsh.bundle.patch` 的包可执行可信 Node 代码，安装预览必须明确该权限并要求确认；不是 HTML 沙箱。使用 DSH `loadProfileDirectory` 解析组合，在顶层 Loader 下创建独立 Include，不写运行 profile 的 Include。安装与加载串行，不重写 pnpm 或 Cordis Loader。

状态区分 installed（已安装但未启用）、enabled（实际加载完成）、failed（加载失败）、restart-required（需重启才能完成原生加载变更）。不能把 pnpm 成功当启用成功。原生 Host 插件以 Loader 子树实际状态判定；原生客户端插件在缺少可确认的浏览器生效协议时明确拒绝，不承诺支持。运行中课堂涉及原生代码变更时保留当前加载，持久保存待重启动作；本次不让安装器自行重启服务。

Remote 使用 `installPackage`/`uninstallPackage`，避开原生客户端服务的保留方法名。首次安装成功但加载失败时，返回已保存的安装记录且 `state=failed`、`issue` 可操作；`enabled` 只表示请求设置，客户端必须按 `state` 显示结果。升级失败回滚旧版本，不把新版本标成启用。主包文件与贡献正文做摘要校验；依赖按 pnpm 独立安装保留，未做依赖文件逐字节防篡改，原生代码仍属可信本机代码范围。

停用阻止新选择和新保存；卸载移除激活登记与依赖加载。为既有课堂保留必要的只读版本快照，不删除用户成果、不删除原生会话。插件损坏不阻止本体启动，管理页显示具体可操作的恢复入口。

## 作品与已有版本

创作者的技能、HTML、教学模式和学科教法经同一安装服务生成标准包并安装。已有 creation 引用继续可读，历史固定版本不改写。Markdown 讲义和原文编辑仍走资料发布，因为它们是用户内容，不是运行插件。旧作品安装记录可在管理页查看、停用和卸载；升级时采用新通路。

## 工作台与保存桥

基础 view id 保持 chat/thoughts/materials，插件 view id 从已启用登记生成。布局解析接受已登记视图，未知/停用视图只从当前投影移除，不清空其他布局；重启登记完成后再恢复。新工作台复用独立稳定挂载容器，移动不重建对话。

HTML 继续使用 opaque-origin `sandbox=allow-scripts`，禁止网络、同源、表单导航及宿主直接访问。宿主只向工作台发送主题与明确课堂上下文；不暴露 Remote、路径、凭据或整个学情。SDK 仅提供 ready、主题通知、请求保存笔记和保存结果；通过 iframe 的实际 contentWindow、一次挂载 nonce、严格消息形状校验，其他窗口及旧挂载消息被忽略。

请求保存只生成待确认内容。宿主原生确认区显示标题和完整正文，学生可编辑或取消，确认后由宿主绑定课堂和 operationId 调用现有 CardService，保存为 note，不记复习和掌握。重试沿用同一操作号；插件不能指定卡 id、旧卡覆盖、课名归属或复习结果。保存后刷新资料库，卸载不删除该卡。

## 界面

“插件”是明确的导航入口。页面采用列表与详情，避免卡片墙和多重标签栏；头部一个“安装插件”，详情列出新增技能、工作台、版本和权限，再提供启停/更新/卸载。开发目录放在安装表单的独立选项内。错误用可行动中文，不泄露底层错误堆栈；开发日志保留排障信息。

字体、字阶、颜色与圆角使用 `docs/ui/themes.md` 现有 tokens；现代和手帐共享信息层级。支持窄屏详情与工作台，禁止重新引入访达、终端或内部轨迹导航。
