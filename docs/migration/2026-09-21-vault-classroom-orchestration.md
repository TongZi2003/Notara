# Vault 教室与子代理编排方案

状态：总方案与首版范围。工作分支 `codex/notara-vault-clean`；承接已实现的 Vault 教学、记忆、路线与课堂日志。

## 0. 用户后续收敛的首版

首版只做固定两个角色，完整世界观、公开同学和自动参与规则留在后续设计中：

- **大肥鱼**：爱吃白饭的鲸鱼娘女仆、DeepSeek 拟人化教学人格，沿用当前主教师的教法、画像、锦囊和课堂日志机制。
- **解题者**：用户指定 `gpt-5.6-sol`，后台独立解题、核验、拆解教学小问题，结果交给大肥鱼授课。未接入所选模型时明确提示，不能继承教师模型当作替代。
- 教师先读题并供料，解题者零工具、不接收父对话；首版每次使用原生 one-shot spawn，同步返回分析，跟进需要重新供应必要材料。取消后不返回迟到分析，重启后未完成任务显示中断，不自动重跑。
- 0.12.0 的供料与预算以[卡片与独立备课工作流](2026-09-22-card-preparation-workflow.md)为准：完整题面/原文答案和选定PDF原页进入独立研究任务，Host按revision生成图像附件；独立生成上限默认32768，可在教室设置调整。不是把文件路径交给零工具助手自行读取。
- 模型路由独立配置并按原生 session 保存，教室 bench 展示固定角色和任务状态，后台报告不直接展示给学生。首版不建立完整角色创作器、世界书条目库或持续驻留的公开同学。
- 用户追加要求可以点击查看子代理做过什么：复用原生子会话与轨迹，提供“查看分析（含完整解法）”。默认列表与对话不内联后台解答；主动进入分析页后允许查看完整材料和结果。这一选择覆盖下文总方案中完全隐藏后台导航的建议。

以下章节保留总方案；与首版冲突的默认空白、角色模板、continuable、自动规则等不属于首版实现承诺。实施与验证记录见 [大肥鱼与解题者](../dev-log/2026-09-21-whale-teacher-solver.md)。

## 1. 已确定的产品边界

- 用户确认教室同时管理可点名互动的同学/助教，以及教师后台检索、核验、备课任务；公开发言与后台结果分开。
- 原生对话保留唯一消息流与输入框；教室是可分屏的独立 bench，展示成员、任务、参与状态，内部管理情景与规则。点名只进入原生草稿，发送后再派发。
- 主教师负责选择教学策略、供料、判断任务结果与推进课堂。长期学情仍只有画像与锦囊；原则性教法沿用 Skill。
- 子代理不写学习事实。需要保存的结果由教师核对，通过已有 Vault 版本校验和原生工作区写批准落盘。
- 教室可关闭、默认空白；模板显式选择。跨课可复用角色配置，不能把上节课的原始子会话当成本节课成员。

| 核实项 | 当前事实与实现锚点 | 对迁移的影响 |
| --- | --- | --- |

## 3. 推荐结构：角色可复用，任务固定本次边界

选择在原生 subagent 上增加一层课堂任务管理。直接搬旧 Host 会重新引入插件绑定、提案、卡片记录和两套回合状态；只添加几个 subagent 提示词又不能保证信息边界、取消和结果去向。

**角色配置**回答“谁以什么方式参与”：姓名、职责、人设、可用教法 Skill、默认模型与推理等级，以及必要的情景关系。它不是常驻子会话，也不是学生画像。

**任务**回答“这次做什么”：目标、所选角色（后台临时任务可无角色）、材料、允许读取的范围、工具能力与回复去向。运行时绑定身份、父课堂、子会话、来源版本和时间。模型选择已返回的角色或资料引用，不生成这些权威字段。

同一角色可以做不同任务；角色名不代表权限。后台看过解答的子会话不能把回复去向改成公开后继续发言。更换信息边界或跨课时新建独立子会话，同一任务的补充提问才续接原会话。

| 任务 | 默认上下文 | 工具与信息范围 | 结果去向 |
| --- | --- | --- | --- |
| 公开同学/助教发言 | 角色指令、教师选择的题面/学生原话/已公开片段、明确可见的情景条目 | 默认无工具；不继承父聊天、画像、私有备课和完整 Skill 目录 | 完成后以角色署名进入原生对话一次 |
| 检索与经历召回 | 要找的问题结构、当前学生想法、必要检索线索 | 在派发时指定的学习集或资料范围内渐进检索与精读；显式分配才可读画像/锦囊/日志 | 交给教师：候选、证据、适用条件、反例与缺口 |
| 核验与备课 | 待核验命题或草稿、必要原文，可含参考答案 | 按需分配只读资料/检索能力；不自动获得整份个人经历 | 交给教师判断，默认不公开全文 |

读取范围与工具名单是两个约束。只禁止 `learning_read` 不能防止从 `vault_read` 或通用文件工具读取同一份记忆；所有可达读取入口都要遵守本任务范围，不能可靠收窄的通用入口不授予。公开任务使用独立 spawn，不能用 fork 后声称已删掉父上下文。

这里的隔离保证“没有交付私有材料”，不保证模型不会从题面独立解出答案。公开角色仍需按教学任务控制回答深度，例如只质疑一个关键条件，不能把信息隔离当成防剧透的充分条件。

## 4. 编排与参与规则

- 主教师按需要派发，后台临时任务不要求先创建一个虚拟同学。公开发言必须绑定本课已启用角色。
- 本教学 preset 的所有委派统一登记，公开/后台可以有不同便捷入口，但共同检查范围与持久任务身份；不以工具名、label 前缀或角色文案判断权限。普通非教学预设继续使用原生通用 subagent。
- 暂不允许子代理再派子代理。建议同课最多三个执行中的子任务；串行依赖由教师收到实际结果后推进，超限任务显示排队。该限制不等于每轮安排三个角色。
- 手动点名优先。自动规则只生成教师候选；沿用每个真实学生教学回合至多一次自动公开参与，系统通知和子任务结算不增加教学回合，不自触发无限对话。
- 保留每 N 轮与教学环节候选。环节完成来自教师明确标记的实际检查点；普通 Markdown 保存、卡片新建和后台任务结束都不自动代表教学环节完成。无剧本课堂也可使用临时检查点，不强制建立完整路线状态机。
- “命题 → 同学尝试 → 核验”按同一任务系统串联，各步按需供料。不迁回旧 `TeachingRounds` 的第二套持久编排与自动登记真卡逻辑。
- 情景/世界书为编排背景：先披露目录与本次命中候选，教师按需读正文。角色只接收明确允许的条目。关键词只帮助查找，不把命中视为当前适用结论；关系和亲密度仍是情景设置，不进入学情。

## 5. 持久化、续接、取消与发布

教室配置建议作为可编辑 Vault 资产保存（角色、规则、情景共用一份配置事实源），便于跨课引用；复用空白、日常自习、推理讨论、变式训练资源。具体格式在实现时复用现有 Markdown/frontmatter 与版本校验，不再引入旧安装登记和 digest 作为第二份内容权威。

本课选择的配置、任务与 child 绑定、派发时的范围快照、跟进和取消/发布记录写入原生 session 的 `notara/*` 扩展事件，复用 `appendTeachingEvent` 的 `ignorable` 信封。正文与原始子会话输出留在原生日志，不复制成新的聊天记录库。运行状态从原生事件与活动状态投影；“等待/运行/完成”不能由模型自己填。

续接规则：

1. 读取本课持久任务表，确认仍属于当前父课堂、尚未取消、范围不变；不要求模型记住 childId。
2. 复用原生 continuable 与冷恢复；需要先解析/恢复父课堂，不能把离线父会话误报为永久损坏。
3. 子代理重建时恢复任务范围检查与工具限制；无法恢复时拒绝续接并说明缺口，不回退为不受限助手。
4. 角色编辑只影响后续新任务，已有任务保留派发快照。配置停用与取消必须即时阻止新增工作和迟到发布。

取消先记录任务失效，再中断和释放对应执行；拦截遗留队列、绕过入口的续接及迟到结果。公开结果用确定性的任务/回复身份去重；断线或重启只能补投尚未投递的完成结果，不能重跑模型冒充恢复。失败、拒绝和中断不标为成功发言。

后台结果通过运行时完成事件可靠回到教师，不依赖子模型自觉调用消息工具。一次任务可有多次跟进，按每次真实回复边界交付；教师可看完整证据，学生投影只看必要的任务名称与状态。

## 6. 学生界面与既有教学机制

- 教室 bench 默认只显示成员和当前任务，可与对话、资产、路线分屏。成员点名、停止、更多设置使用小图标/菜单；角色编辑、情景与规则按需展开。
- 教室没有第二输入框或第二消息列表。公开回复在原生对话署名出现；后台区域只显示“查阅相关经历”“核对一个条件”等适当标题与进度，不直接显示私有材料和解答。
- 学生投影覆盖普通消息、工具结果、原生 settlement/relay、顶部 lineage 与子会话入口，不能只隐藏一个面板。原始会话标识与后台日志不进入普通课堂界面；调试视图另行保留。
- 调用 Skill 是采用教法原则；读取锦囊是召回真实经历与方法。子任务结果是建议或证据，不能自动变成学生思维模式或掌握结论。
- 路线剧本可提出“此时请同学质疑”等默认安排；是否执行由教师判断。收课仍走现有课堂小结：有剧本追加原文，否则独立小结，两者索引到 `lesson_log`。总结只记录实际发生的互动，不把预备任务当成课堂事实。
- 用户要求归档时协调取消/收束本课尚在运行的任务，再按当前真实课堂截止点保存小结；归档后不得被迟到任务继续插话。

## 7. 用解题策略讨论验收设计

学生说：“这题没有明显对称结构，我想改用参数方程。”

教师可并行安排后台任务：在明确指定的几何学习集中，查找过去“极点极线”和“参数方程”的使用经历，返回原题/学生原话，以及适用与不适用的证据。它不预设学生总爱某种方法，也不把搜索结果直接归纳成画像。

同时可请公开同学只根据题面和这句原话提出一个质疑：“不用对称结构，你准备通过哪个量减少参数？”这位同学没有拿到历史画像和后台完整解答。教师结合学生回答与后台证据推进，必要时再展开一个旧锦囊；之后经正常批准修订锦囊。

这个过程分别验证：召回是否有用、供料是否独立、公开互动是否推进思考。不能用“成功启动了两个子代理”替代这三个结果。

## 8. 实现与验收顺序

1. **任务边界**：统一登记、角色快照、材料绑定、工具及数据范围、只读限制、取消、冷恢复。新增确定性合同与真实 Host 集成验证。
2. **可见教室**：配置编辑与 CAS、模板、点名草稿、分屏、署名回复、后台状态和完整学生投影。运行隔离浏览器用例并捕获控制台异常。
3. **教学编排**：参与规则、检查点、世界书渐进披露、串联任务、记忆召回、路线与归档协调。先确定性集成，再用真实模型跑上述正常学习场景。

必须单列验证：跨集越界读取（包括通用文件工具和伪造 ref）、子写与递归委派拒绝、公开子不含父私有上下文、后台转公开须新任务、配置中途变化、同任务追问、父子冷恢复、取消后排队/迟到回复、重启去重、唯一 composer、原生导航不暴露后台结果、没有角色和没有任务的空态。

运行遵守 `scripts/dev-isolated.ts`，使用临时 DSH_HOME、合成 Vault 和随机端口。本轮仅完成源码探查与设计整理；类型/构建/确定性测试/浏览器/真实模型均未运行，不复用上一轮教学迁移的 PASS 作为教室证据。
