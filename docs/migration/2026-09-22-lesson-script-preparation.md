# 课堂剧本与备课资料结构

> 当前补充合同：0.14.0 的学科分离、知识型课本研究、目标驱动备课及五工作预设职责以 [学科关注点与通用工作流分离](2026-09-22-subject-workflow-separation.md) 为准。下文保留该阶段的设计与验证记录；旧模式或学科列表不作为当前调用指引。

本合同收敛本轮已讨论的设计。实施在 `codex/notara-vault-clean`，Native Vault 0.10.0；行为验收按用户要求暂停，不能把构建结果当作教学质量证据。

## 现状差距与改动范围

| 能力 | 本轮开始时 | 本轮改动 |
| --- | --- | --- |
| 课堂剧本 | 阶段提纲模板，教师 HTML 原样显示 | 一份 Markdown，默认折叠教师参考，展开后沿用公式、高亮、链接和媒体渲染 |
| 开课加载 | 截取开头 1200 字，目录也来自这段快照 | 从真实文件生成公共阶段目录，正文通过带 revision 的阶段读取加载 |
| 备课规范 | 一份简短通用 Skill | 通用备课规范、按需学科 Skill、本课动态备课说明 |
| 多 Agent 协作 | 解题者只按解题任务处理 | 同一个零工具助手接受 solve / plan / draft / review，文本结果由主教师接力 |
| PDF 结构 | 主要通过卡片嵌入表达来源 | source 原书结构、topic 教学专题，可复用并绑定真实页段和区域 |

继续复用路线绑定、原生会话、同文档追加课堂小结、lesson_log、原生文件读写与批准。没有新的数据库、课堂生命周期或通用文件工具。

## 一份文件，两种阅读状态

- `type: lesson`；`##` 划分公共阶段，`###` 为题目或小步骤。
- 公共部分是目标、材料、题面、作答提示；教师部分就近放 `<details data-notara="teacher">` / `<summary>教师参考</summary>` / `</details>`。标签独占一行，正文使用 Markdown。
- 第一个教师块是本课备课说明：目标、相关画像和锦囊的证据及不确定点、教学取舍和检查点；题目旁的教师块包含教学意图、递进提示、完整解答和诊断。
- 默认折叠；展开是只读预览，“编辑教师内容”回到同一文件的源码，显式收起结束编辑。折叠是阅读方式，不是权限隔离或答案保密机制。
- 公式、图形与答案的准确性仍需教师核对。界面能渲染不能证明备课内容正确。
- 课后有剧本则在文末追加当前课堂小结，无剧本则新建小结。原始 PDF/讲义不能因为被引用而变成小结目标。

新 `lesson-script.md` 模板补充到 `_templates/`，已有同名模板不覆盖。旧 `lesson.md` 的用户自定义内容保留。

## 上下文加载

1. 开课背景包含学习目标、临时要求、公共阶段目录、已绑定前课进度与材料引用，不包含剧本正文或教师答案。
2. `lesson-outline` 返回真实文件 revision、派生的阶段 key、标题、行范围与教师块数量。目录默认 40 项、最多 100 项，按 `nextOffset` 继续读取。
3. `lesson-section` 必须同时提供目录的 `readPath`、`section` 和 `expectedRevision`。只读这个阶段及其就近教师内容，默认 6000、最多 12000 个 Unicode 字符；长阶段用 `nextOffset` 续读，不能把半段证明当作完整解答。
4. 目录不包含教师参考中的标题、代码围栏和已追加的课堂日志。教师块不闭合时报告格式问题，阶段读取拒绝继续。
5. 阶段 key 是程序派生的导航键，不能当成路线节点 ID，也不用写回 Markdown。文件改动后旧 revision 不能继续读取；已绑定剧本需核对改动并重新绑定。
6. 保留历史事件字段名 `scriptSnapshot`，投影仅含出处；旧截断正文不再进入设置返回值和新模型请求。不提供可回读的完整历史版本库。
7. 跨学习集保留绑定范围，使用 Host 提供的绝对 `readPath`，不以当前集同名文件代替。CLI 只接受当前集相对路径或已绑定剧本的绝对路径。

这些都是通过原生 Bash 调用的确定性辅助命令，不增加专用模型工具。`DSH_NOTARA_LESSON` 由 Host 注入位置和版本，不由模型提供执行身份。

## 备课规范与协作

通用备课 Skill 约束资料核对、单份剧本、动态备课说明、保存与绑定；数学、理科建模、人文语言 Skill 按需要读取，不全部加入常驻提示词。画像和锦囊只读当前任务相关部分，其判断要保留证据与不确定性。

普通课堂即时讲练由主教师推进；按资料备课与拆题卡先用 `ask_solver` 在独立上下文逐题研究，再组织产物。`task` 默认 `solve`，按需接 `plan`、`draft`、`review`，主教师显式交接完整前序材料，不要求固定调用次数。解题者使用独立生成上限（默认32768）及较高推理等级，保留用户显式设置；PDF原页以 `sources` 交接，由Host按revision核验并转成原生附件。助手不继承父对话、没有工具、不保存文件、不另选模型回退。卡片三段、原文参考答案优先、一题一卡与共性父节点，以[卡片与独立备课工作流](2026-09-22-card-preparation-workflow.md)为准；写回仍服从原生权限。

每次调用仍是同一个后台解题者，沿用原生子会话与轨迹回看。结果被返回不代表数学或教学质量已经核验。固定 Skill 的修订依据实际课堂或用户修订，不能把一次备课自评自动提升为通用教法。

## 备课时整理 PDF

- 只整理这节课涉及的范围；定义、完整定理及证明、例题、练习是语义单元，跨页的一道题保持一个节点并列出多个嵌入引用。
- `type: source` 记录原书结构，`parent` 指向原书 PDF 或同类章节；`type: topic` 记录教师归纳，父层只属于专题，引用原书用 reference。
- 资料节点都是普通 Markdown，无复习状态；卡片可以挂在资料节点下。图谱详情分别列出子资料和子卡片，资料不进入卡片统计。
- 原书结构用已有 split 边，专题引用、路线与剧本引用用 reference；文件是唯一事实源，不另建目录数据库。
- 有数学、表格或图形的资料先看原页图像。`pdf-page` 返回页面/区域的真实 locator 和可直接使用的 embed，包含物理页码与 revision；区域需要看裁切图核对，标注 ID 只能复用真实标注。
- PDF 页和区域都保留版本定位。改版后须核对，不把旧坐标当作新页准确位置；无效区域不静默扩大成整页引用。

## 验证边界

本轮只做源码审阅、语法与资源检查、构建。已更新相关断言并准备阶段解析的回归用例，但不执行 unit/integration/e2e、真实浏览器和真实模型。教师区展开/编辑、跨集阶段读取、资料树跳转和真实备课效果均不能报为行为验收通过。

现存浏览器实例不热改、不重启；新版本需下次安装或启动后才加载。
