# 学科关注点与通用工作流分离：设计与实施方案

**状态：0.14.0 已实现；确定性验证通过，真实模型质量验证受阻。** 2026-09-22 补充确认：知识型课本以知识单元研究为主线，`general` 承担独立研究与解释，不能降为摘录或摘要。实施前 Native Vault 包版本为 0.13.0；验证与发布状态见同主题开发日志。

**目标：** 保留书籍拆解、课程编排的通用流程，把各学科“应关注什么、怎样判断内容成立”移入按需加载的学科 Skill，使同一套主教师与工作员编排能用于数学、物理、化学、计算机、语文和英语。

**架构：** 通用工作流负责范围、顺序、分工、产物与完成条件；学科 Skill 负责内容判断；教法 Skill 负责引导方式；材料来源和本次任务背景独立组合。沿用 Markdown 资源、manifest 注册和 `ask_worker`，不增加工作流引擎。

**技术与全局约束：** Node `>=24.0.0`，DSH `0.1.5-rc.2` 系列，现有 JavaScript/TypeScript 与 Markdown；不引入依赖。继续使用原生 session、spawn、模型配置和权限。保留五种工作预设、每课堂同时一个后台任务、至多 4 个显式 Skill，以及工作员 none/read 工具边界。学科选择不授予资料或学情读取权限。

## 1. 审计摘要

建议采用“通用流程 + 独立学科关注 Skill + 本次任务重点”。相比每科复制整套流程，这能让拆分、交接和写回规则只维护一套；相比继续往通用提示词增加学科条款，它能控制上下文并减少跨科误用。当前按需资源机制足够承载，不需要新的自动路由服务。

本轮实现范围：

- 两种可独立进入的流程：书籍拆解、课程编排；后者可以按需调用前者，也可以从目标直接开始。
- 六科独立关注 Skill；保留现有理科、人文入口作为未细分领域的兜底，避免删除生物、历史及其他语言已有指引。
- 主教师、五类工作员和课堂模板采用一致的任务交接规则；非题目资料也有明确的整理出口。
- 新规则通过现有注册、构建和子请求组装进入真实运行链；新模板只替换未被用户修改的旧内置模板。

本轮不新增角色、并发队列、学生画像 schema、卡片类型或自动评分服务。计算机教学支持生成代码与评分测试点，并由主教师通过既有执行能力核对；运行环境缺失时如实保留“未运行”。

## 3. 每一层负责什么

| 层 | 回答的问题 | 放在哪里 | 不承担的职责 |
| --- | --- | --- | --- |
| 通用工作流 | 何时开始、处理多少、怎样拆任务、谁审阅、何时保存 | `material-outline`、`route-planning`、`lesson-preparation`、`worker-orchestration` | 不规定所有任务都要证明或建模 |
| 学科关注 | 哪些信息不能丢、怎样解释、怎样判断合理 | `subject-*` | 不发工具指令，不设权限，不安排下级代理，不规定保存路径 |
| 原则性教法 | 怎样引导学生观察、解释、推理 | 现有 socratic/feynman/lecture/structural | 不替代学科事实与本次教学目标 |
| 材料与工具 | 从哪里获得证据、怎样读取和定位、怎样写回 | 现有 `material-search`、`vault-workflow` 与实际工具合同 | 不把 PDF、网络或上传设成所有课的前提 |
| 本次任务背景 | 这次针对谁、做什么、重点和约束是什么 | 现有 `goal`、`focus`、`materials`、`sources` | 不复制全课堂、全画像和整套工作流 |

主教师保留总框架、范围确认、任务分配、轻量审阅、父节点归纳与最终写回。子任务只完成交接的一项工作。流程描述是职责与顺序约束，不是每次必须跑完五个角色的固定流水线。

### 3.1 来源独立于流程和学科

- **用户资料：** 书籍、讲义、题目、文章、代码、实验记录。先辨认资料结构，再选范围；图文关系、公式和表格按实际介质核对。
- **网络资料：** 主教师通过已有 `web_search/web_fetch` 获取所需内容，核对出处、版本及正文，把相关片段与来源交给工作员。只有链接不等于已经读到。
- **无预置资料：** 可以根据明确目标设计概念例子、问题或代码。明确其为教学生成内容；遇到版本、标准、数据等需要外部证据的事实再检索，不伪装成书中原文。
- 三者允许组合。缺书不阻止目标驱动课程；需要的原题、实验数据或听力音频缺失时，不用模型想象替代。

PDF 原图和 revision 合同保留：`sources` 仍仅承载最多 4 个真实 PDF embed；文本、网页正文、代码及其来源说明通过 `materials` 传递。工作员无 Bash、无联网，不要求它自行渲染 PDF 或联网找证据。

## 4. 两个通用工作流

### 4.1 书籍拆解

1. **略读结构。** 读目录、代表内容、题目与答案位置；先形成章节和资料类型的概览，不先研究整本书。
2. **确定范围与用途。** 沿用已明确的章节、题目及目标；缺少会影响工作量或产物的信息才询问。独立拆书按用户范围进行，备课中的拆解只处理该课需要的部分。
3. **选学科重点并列清单。** 清单包含语义单元、真实来源范围、预期产物、处理状态。由实际内容决定按题、概念、实验、代码示例或文本任务拆分，不预设卡片数量。
4. **交独立任务。** 一道题及关联小问交 `problem`；知识型课本主要交 `general` 独立研究完整知识单元：它解决什么问题、为何需要、定义与条件、先修依赖、解释或推导、例证及误用边界。仅交必要原文、原答案、原页及当前学科重点，不先由主教师做完整批研究，不把研究降为摘录。
5. **轻量审阅并保存。** 核对事实完整性、来源、解释依据和产物合同；疑点只退回相关项或交 `review`，不默认重做整批。
6. **归纳父节点并核对覆盖。** 完成一批后，由主教师归纳共性、差异和适用边界，建立真实子卡链接。知识型课本还要解释概念的依赖、区别及它们共同回答的问题；原书目录树与理解上的知识树分别保留。分清已保存、待核对、缺材料和未完成。

语义单元边界：一道阅读题保留回答所需的完整语境；一次实验保留有关条件、步骤和观察；代码示例保留能理解行为的上下文和依赖。不可为了短而拆断因果或引用关系，也不要求每个单词、公式或代码行成为卡片。

### 4.2 课程编排

1. **明确目标、基础证据与约束。** 可以从“学习 C 的数组”或“练习有依据的阅读解释”开始，不要求先上传书。
2. **确定学科重点与材料策略。** 选择已有资料、网络取材、现场构造或其组合；只取本课相关的画像与锦囊证据。
3. **主教师建立框架。** 多课时由 `route-planning` 组织目标、先修、阶段与检查点；一节课直接给本课框架。规划不等于把每节课都完整备完。
4. **按需准备资产。** 需要可复用卡片时调用书籍拆解或单元整理；已有核验产物直接复用，不为每节课强制先拆书。
5. **课时完善与练习。** `lesson` 完善一节课；`exercise` 设计小测、变式或编程测试；`problem` 研究必要题目，`review` 处理明确疑点。
6. **主教师统一衔接与写回。** 维持单份 Markdown 剧本，公共阶段对应具体任务，教师参考就近折叠。按实际课堂证据调整未来路线，沿用当前小结和 lesson_log 机制。

教师参考按任务交付足够检查的内容：封闭题需要完整解答；阅读和表达需要依据、示例与评价标准；实验需要条件、现象与解释；编程需要参考实现、关键行为与测试。不能把“通用任务”用作省略解题细节的理由。

## 5. 六科学科 Skill 的内容合同

统一段落为“适用任务／共同关注／拆书重点／课程编排重点／核验依据”。这些是供教师判断取舍的关注点，不要求每个任务穷尽所有条目。文件用短正文，相关样例按需读，不把整套课程样例附进每次子请求。

| 学科与 ID | 拆书要保留什么 | 编排时优先关注什么 | 判断依据与常见误用 |
| --- | --- | --- | --- |
| 数学 `notara-subject-math` | 定义与量词、定理假设、证明依赖、完整题干与原解、必要图形 | 计算和推理基本功、方法发现、结构识别、触发与失效条件，适时提出问题 | 条件、定义域、等价性、边界；数值检查不替代证明，答案正确不代表论证正确 |
| 物理 `notara-subject-physics` | 研究对象、过程、模型假设、忽略因素、量的含义、图像及实验数据 | 现象→模型→表示→推断→检验；比较不同近似下的结论 | 单位与量纲、守恒前提、极限情形、与观察一致性；公式相似不等于模型相同 |
| 化学 `notara-subject-chemistry` | 物质与结构、反应条件、操作顺序、实验现象、数据与来源 | 结构—性质—反应联系，宏观现象与微观解释，变量控制和证据推理 | 物料/电荷守恒、可发生条件、操作与现象是否支持结论；配平不等于反应能发生，涉及真实操作时核对实验约束 |
| 计算机 `notara-subject-computing` | 语言版本、语义、状态与内存、代码上下文、输入输出和依赖；算法的对象与约束 | 语言特性用预测→编写/修改→运行→解释→变式；算法用数学问题→离散表示→有限步骤→正确性→代价 | 类型、边界、溢出、内存行为、不变量、复杂度和测试覆盖；跑过样例不等于普遍正确，未运行不声称执行成功 |
| 语文 `notara-subject-chinese` | 必要原文与语境、文体、语言细节、篇章结构；区分原文/注释/译文/解读；范文保留写作任务 | 文本依据与解释、表达效果、论证组织；文言字词句式结合语境；写作保留学生意图并支持修改 | 原文支持什么、推断跨了哪一步、表达是否完成任务；参考答案忠实保留，但有依据的开放解读不要求逐字一致 |
| 英语 `notara-subject-english` | 有语境的表达、搭配、语法对比与篇章用途；区分规则、常见用法与特殊情形 | 形式—意义—使用；阅读策略、交际任务、准确自然与语域；写作修改结合真实目的 | 语义、语法、搭配、语域及任务完成；允许多种正确表达，听力和发音评价必须有实际音频依据 |

计算机首版在同一 Skill 中区分语言特性与算法重点，不新增“C 教师”“算法教师”角色。出题员可交参考代码、测试输入、预期结果或评分脚本，并说明各测试针对什么错误；实际运行由主教师通过既有原生工具在任务临时目录完成。先用参考实现和典型错误实现检查测试点；缺少编译器、依赖或执行条件时标明未运行，不自动安装系统依赖或给工作员开放 Bash。

### 5.1 未细分领域的保留方式

- 保留 `notara-subject-science`，描述调整为“其他自然科学与综合探究”，保留原有通用建模、数据和实验观察原则供生物等使用。物理、化学任务优先选专门 Skill。
- 保留 `notara-subject-humanities`，描述调整为“其他人文与语言学习”，保留历史史料来源、文本证据、推断与表达原则。语文、英语任务优先选专门 Skill。
- 旧 ID 继续可解析，不做静默重定向，不迁移旧会话，也不把兜底内容说成已经完整支持各个未细分学科。
- 通常选一个具体学科；跨学科只选确实相关的两个或少数入口，不默认叠加具体学科与其兜底文件。`skills` 的总上限仍为 4，教法也占其中名额。

## 6. 卡片与工作员合同

### 6.1 保持的卡片事实

所有卡片继续使用页头 tags 与“内容／参考理解／学生理解”，不增加学科专用 schema。

- **内容：** 完整可检索的原题或语义单元、必需语境和材料。真实原文参考答案折叠保留，来源索引不能替代正文。
- **参考理解：** 有依据的解释、方法归纳与适用边界；区分原文答案、模型补充和待核对疑点。开放任务给评价标准与可成立的不同路径。
- **学生理解：** 保留真实认知演变，包括早先不完备或错误的理解、转折与帮助、后续实际表现；补充新阶段不覆盖旧阶段，缺失过程不补编，无真实表达时留空。记录与诊断召回以 [0.14.1补充合同](2026-09-23-cognitive-history-and-diagnosis.md) 为准。

题卡仍原则上一题一卡，同一题的关联小问不拆断；非题目内容围绕一个完整语义单元。原书结构使用 `source`，跨单元共性使用 `topic`，其边界和 parent 规则不变。不是所有资料都变成 `card`，复习仍只在实际评估后进入已有调度。

“原文答案为准”在这里指忠实保存和作为核对依据；不意味着隐瞒其矛盾，也不意味着开放任务只接受这一种表达。

### 6.2 五种工作预设如何接不同学科

| preset | 固定职责 | 本轮调整 |
| --- | --- | --- |
| `problem` | 一道完整题及关联小问的研究或题卡 | 保留完整研究；让核验方式来自学科 Skill，支持阅读、实验分析和编程题 |
| `general` | 一个有边界的知识单元研究或资料任务 | 知识型课本的主要工作员，独立研究概念、实验、文本或代码单元，交付有解释依据的完整知识卡；纯检索任务交证据报告，不强造卡片；不承担课程总框架和整书归纳 |
| `lesson` | 按给定框架完善一节课 | 用“学习任务 + 对应教师参考”，不固定为计算题 |
| `exercise` | 小测、变式及检查任务 | 支持开放题评价标准、代码测试点；自解/自检与实际执行分开记录 |
| `review` | 核验明确疑点 | 按学科证据给判断、依据及最小修改；不自动审完全部产物 |

三段格式等跨角色产物规则集中到工作员公共规则的“当任务要求卡片时”段落，角色正文只保留本角色特有要求；主教师工作流引用相同合同，不继续复制相互漂移的格式说明。`general` 的局部草稿能力需要同步更新其目录描述，不能只改提示词而仍对外宣称只能检索。

## 7. 按需加载与交接

已核实当前机制：`teacher.js / apply` 从 manifest 提供 Skill 索引和正文；`teaching-runtime.js` 的主系统提示不自动附所有学科正文；`solver-runtime.js / selectedSkills、workerPersona` 只组装显式选定的教法与 `subject-*`。本课 `subjects` 只是自由文本科目线索，不是自动选 Skill 的开关。

`teaching-catalog.js` 在生成目录存在时优先读取 `examples/native-vault/teaching/`，不会自动选择较新的源文件。因此资源变更后先构建并核对副本，再开启新的测试进程；只测旧副本不能证明这次修改有效。工作流和学科仍放在 manifest 的 `skills`，不放入代表教法选项的 `choices`。

拟定加载顺序：

1. 主教师根据当前请求及实际资料识别任务；科目标签可辅助，但不能覆盖实际内容。
2. 按需读取流程和一个主要学科 Skill，必要时增加跨学科关注。信息已足够时不要求用户选下拉框；只有歧义影响下一步才询问。
3. 主教师提出本次的少量重点，写进 `focus`；有关目标、先修、学生真实困难和资料写进 `goal/materials`。固定学科规则无需整段再复制。
4. 调 `ask_worker` 时显式传 `skills`。工作员得到“公共规则 + 当前角色 + 选定原则 + 本次任务材料”，不继承父历史，也不加载书籍拆解、保存等工作流 Skill。
5. 返回产物后主教师按清单收口；任务或学科明显变化时重新判断关注重点，相关正文仍在上下文中则不机械重读。

一次编程备课的拟议交接示例（新学科 ID 需实施后才能调用）：

```json
{
  "preset": "lesson",
  "goal": "按给定框架完善一节 C 数组入门课，返回单份 Markdown 剧本草稿。",
  "focus": "帮助学生区分下标和值，理解有效下标范围；暂不引入指针算术。",
  "materials": [
    {"title": "本课框架", "text": "先预测 int a[3]={2,4,6}; 的合法访问结果，再修改循环输出数组，最后做一个独立检查任务。"},
    {"title": "基础与边界", "text": "已确认学过变量和循环；数组理解尚未检查。采用 C17，不把未定义行为当成可预测输出。代码及测试需由主教师另行实际运行核对。"}
  ],
  "skills": ["notara-subject-computing", "notara-socratic"]
}
```

`focus` 是本次取舍，不是新的长期学情；课程中的临时改法不能自动覆写学科 Skill。通用工作流仅要求教师选用适当关注，不增加按科目硬编码的 if/else 路由表，也不承诺模型一定遵循提示词。

### 9.2 内容与真实模型验证

准备六份短的合成资料，每份同时包含一个题目/任务与一个非题目语义单元；每科分别跑“限定范围拆解”和“按目标备一课”两种请求，共 12 个有界场景。计算机备课明确不提供教材，英语包含同义正确表达，语文包含可成立的不同解读；另用确定性用例覆盖旧 ID 与跨学科加载。不给请求预先写出期望调用的工具名。

先跑数学拆解与无教材的计算机备课两个场景，验证既有质量要求保留、目标驱动入口成立，再扩展其余十例。前两例发现系统性遗漏或重复研究时先修流程，不继续消耗整套测试预算；执行前列出采用的既有模型、预算和预期调用规模，不擅自抬高生成上限。

| 样例 | 重点判断 |
| --- | --- |
| 数学：条件有差异的两道题与相关定义 | 单题完整；比较假设和方法触发；没有因为“通用化”省略证明或原答案 |
| 物理：受力模型与一组实验数据 | 对象、假设、单位和图像含义保留；结论对应真实数据 |
| 化学：反应条件与实验记录 | 区分方程式成立和实际反应条件；不补造实验现象 |
| 计算机：数组/循环代码；无教材的数组入门课 | 保留版本和边界；任务有预测、运行及解释；测试点能识别指定错误，未执行不称已运行 |
| 语文：短文、阅读任务及参考解读 | 保留必要语境；解释有文本依据；不把原文参考答案变成唯一措辞 |
| 英语：有语境的表达对比与写作任务 | 区分形式、意义、使用；接受合理变体；无音频不评价发音 |

拆解和备课都核对：主教师是否选对学科、交接材料是否充分、子任务是否实际收到对应 Skill、是否把局部研究隔离、是否只对疑点返工、是否保留学生理解空态与真实来源。主教师的整批重复推导、无关学科大段注入、虚构原文或把未核验结果标成功，都记为失败。

记录每次模型与配置、输入输出用量、耗时、工作员调用次数、重试与人工发现的问题；能取得缓存/推理用量时单列，取不到就标未知。使用同模型、同预算的可比旧流程样例才能声称节省成本。首轮每场景只运行一次，修复后只重跑失败场景；预算不足时停止并列未验证项，不以不断重试抹掉失败。

这些样例只能证明限定场景，不等于“六科教学质量全面通过”。真实学生的理解与迁移效果仍需课堂观察，静态检查和合成模型不能替代。

## 10. 建议重点审计的四处边界

以下均为已确认并落入当前资源与接线的边界：

1. **知识单元研究由 `general` 承担。** 对知识型课本，它是主要工作员，研究问题动机、定义条件、先修依赖、解释与例证边界，交付完整可核对的知识卡；保留 `problem` 的单题职责，不增加“知识研究员”。主教师负责全书结构、跨单元联系和最终综合。
2. **六个专门入口与两个兜底入口并存。** 避免静默丢失旧领域支持；不把兜底 Skill 默认叠到每个具体学科上。
3. **编程测试仍由主教师执行。** 出题员负责设计，主教师运行核对并保留实际结果；本轮不扩展子任务工具面，也不建设独立判题平台。
4. **原文答案忠实保存，解释是否成立按学科判断。** 数学不能用答案掩盖错误证明，语文与英语也不能把参考答案变成唯一表达。

用户已确认按任务一至四实施；各层实际结果写进开发日志，不由本方案推定通过。
