# 路线规划：课程设计与局部调整

> 当前补充合同：0.14.0 的学科分离、知识型课本研究、目标驱动备课及五工作预设职责以 [学科关注点与通用工作流分离](2026-09-22-subject-workflow-separation.md) 为准。下文保留该阶段的设计与验证记录；旧模式或学科列表不作为当前调用指引。

目标：路线能够说明学习终点、起点依据、教学主线、讲练梯度、检查点和后续调整；课序图上的每个节点都对应可以开展的课堂。用户已认可此方向，以“迭代数列专题”作为样板。本轮直接实施，保留原生会话和 Vault 文件事实源，不建立第二套学情或掌握账本。

## 规划的内容

课程总述记录目标、适用范围、起点证据与未知项、时间约束、阶段安排和检查方式。每个课堂节点只存一份 Markdown 规划正文，公开部分说明目标与任务；折叠教师部分说明安排理由、代表例题的用法、递进练习、判别依据及补练/跳过/拓展条件。完整课堂剧本仍按需单独备课，远期保留方向和检查依据。

知识先修与直接前课分开：前课决定课堂接续，先修说明知识依赖，不表示已经掌握，也不成为自动锁课条件。主线、补练和拓展是可见性与关系类型，不是能力等级。真实课堂的学习事实继续由画像、锦囊和课堂小结持有。

## 文件合同

路线仍为 `type: route`。`lessons` 除原有身份、标题、前课、材料、剧本、课堂与日期字段外，只扩展 `stage`、`pathway`、`prerequisites`：

- `stage`：课程阶段的名称，用于分组，不创建阶段会话。
- `pathway`：main / remedial / extension，默认 main。
- `prerequisites`：本路线中真实节点的身份列表。
- `brief`：读侧返回的 Markdown 正文，唯一持久位置是文件内 Host 标记的节点块，不在 frontmatter 重复保存。

节点标记为 `<!-- notara:route-node "真实节点身份" -->` 与 `<!-- notara:route-node:end -->`，由写者生成；模型不编身份。课程 overview 是这些节点块外的总述。日期调整、课堂绑定、重开路线均须保留正文和节点身份。

创建沿现有 `create-route` 辅助命令，增加 overview 和每课规划。局部修订用 `revise-route`：要求真实 revision、修订原因和变动字段；已绑定课堂的节点保留，新目标新增节点。省略表示保留、允许的 null 表示清除、空数组表示清空。所有校验在单次 CAS 保存前完成，Host 写入修订日期和受影响标题。不自动删除节点、改写小结或把有小结当作学会。

这两个辅助命令仍通过原生 Bash 批准；原生文件编辑继续可用，不声称命令校验能防止任意 Bash 或人工改写文件。普通正文修订也要保留 Host 身份和已开展课堂。

## 教师执行过程

1. 明确目标与范围；只补问真正影响规划的缺项。已有证据足够时直接规划，基础未知时安排适当的小范围检查，不一律做全科诊断。
2. 阅读资料骨架、相关画像与锦囊，区分原书结构和教学重组，记录未核对资料与未知学情。
3. 构造阶段主线，检查先修、认知跨度、负担和时间约束。没有真实可用时间就不擅自排日期或许诺课时。
4. 为每个关键目标选代表任务、变式与观察点，安排撤掉提示后的独立选路和后续复现；不靠章节名或漂亮解释声称规划有效。
5. 复杂路线可让现有高级模型助手 plan / review，主教师选择和核对。任何助手自评都不产生掌握事实。
6. 保存路线并能在面板打开。开课只加载当前节点的有界规划、必要先修入口及前课小结，不把全路线或完整画像注入每轮上下文。
7. 课后根据真实作答与小结提出局部修订，保留已开展课堂。未获得证据只记录未知，不自动把学生送进补练或拓展。

## 证据边界

样板是可供审阅的课程设计，不是学生已经学过的记录，也不证明达到某位网课教师的水平。恢复验收后应按目标覆盖、先修合理性、题目准确性、练习梯度、调整依据逐项评审，并观察真实课堂。用户此前暂停行为验收，本轮不运行单测、集成、浏览器或真实模型，不重启现存服务。
