# 找卡片、教学沉淀与学习复盘

用户确认三个入口的分工。0.14.5沿用原生文件工具、教学 Skill provider、指令菜单与 `general` 工作员，不新增长期记忆类型、专用搜索工具或子代理生命周期。

| 入口 | 判断对象 | 产物 |
| --- | --- | --- |
| `notara-material-search`（找卡片与资料） | 当前描述与真实资料是否相关 | 少量候选、出处、原文依据、相关性及差异 |
| `notara-teaching-reflection`（教学反思与沉淀） | 老师的教学判断与引导是否合适 | 有依据的反思与必要的局部更新；可以没有修改 |
| `notara-learning-review`（学习复盘与建议） | 学生接下来值得重点学什么 | 有优先级的方向、依据及可立即开始的小任务 |

## 搜索

从自然语言意图展开概念、结构、条件、策略和认知经历等检索线索，先候选后精读，可沿真实父节点和链接补查。原生 glob/grep + 模型语义判断不等于向量索引，不保证找全措辞完全不同的内容。旧错必须连同后续修正读取。需要独立上下文时把查询、目的、真实范围和输出要求交给 `general`；只读配置下自主查找，无工具配置下只处理显式材料。工作流 ID 不进入 `ask_worker.skills` 的教法/学科白名单。

## 教师反思与沉淀

回看实际作答、帮助程度、教学取舍及后续表现，审视老师原判断是否成立。学生做对不直接证明教法有效，做错也不直接证明教法无效；同时保留反证和情境差异，不按提示次数抹去学生的认知贡献。

沉淀按对象路由：学生当前状态进入画像，方法/教法/经历/触发条件进入锦囊，节奏和内容安排进入路线或剧本，流程性问题才形成 Skill 修订建议；待检验假设留在已有课堂小结。无新发现可以不更新。反思不是新作答，不重复记评估、不覆盖认知演变或复习字段。

当前教学预设仅注册内置教学资源，未启用原生个人文件 Skill provider。不能靠在 `.dsh/skills` 写一个文件就声称生效，也不修改安装快照。涉及内置 Skill 的修订先留可审阅建议，应用它仍需产品更新。此轮不增加个人 Skill 自动覆盖或热更新机制。

## 学习复盘与建议

复用诊断的证据方法，但有独立入口：兼顾优势、进步、困难、兴趣、目标与知识联系，不只是列错题。最近少量课堂开始、按决策需要精读；跨已知且获授权的学习集时明确覆盖范围，不全库注入。`lesson-log`仍是当前集索引，没有自动发现所有学习集的模型工具；外集使用原生文件检索，有剧本的小结不能漏查。未观察不是薄弱，不跨学科拼一个掌握总分。

建议一般为1–3个方向，每项含“为什么现在值得学、预期收益、下一步任务或检查点”。可以提出现有资料之外的探索方向，但说明依据与未知先修。选定方向或已明确要求规划后才交路线规划；不因请求建议就自动排课、开课、改排期或更新画像。

## 发现、触发与权限

找卡片和学习复盘在指令菜单直接展示；教师反思在“更多技能”，三者均可搜索和原生调用。共同规则只加入口，不常驻注入三份正文。归档请求增加简短教师反思要求，仍保存到原小结，不强造问题或新记忆。普通助手不挂教学技能。所有写入服从原生权限，已授权范围不重复确认。

## 验证边界

资源/菜单/真实Host装配验证与教学质量分开。人读审稿使用：旧错已修正、老师代做关键步骤、个人偏好误改通用规则、未观察科目被说成薄弱四类场景。真实模型的召回质量、反思有效性、方向建议价值仍需实际课堂验证。
