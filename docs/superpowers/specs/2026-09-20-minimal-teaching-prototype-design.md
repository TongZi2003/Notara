# 最小教学原型设计

## 目标

先把 Notara 收缩成一套可以真实试用的学习基础设施，观察真人使用时的教学效果，再决定是否恢复更多能力。

默认产品只保留：

- 知识库；
- 对话内路线图；
- 世界书；
- 只读子智能体；
- 完整路线规划。

对话本身当然保留，是这些能力共同工作的入口。具体教学质量、提问方式和教师风格暂不写成固定验收合同，由真人试课后继续调整。

## 默认产品边界

### 知识库

保留资料、方法、卡片、学情和证据的读取，以及现有受控写入、确认、版本和来源绑定。

知识库是默认课堂的主要事实来源。模型看到的工具只覆盖当前任务需要的读取和写入能力，不因为 Host 注册了全部方法就把全部 schema 放入默认上下文。

### 对话内路线图

保留当前课堂的阶段、思维节点和分支投影，让学生能在对话中看到正在进行的路线，并回到已经形成的节点。

路线图复用已有 Session、ThoughtGraph 和 ClassroomTrace，不新增第二套对话生命周期。

### 世界书

保留课堂背景、教学约定和可选同学配置。世界书继续通过 Host 的动态 context 接入课堂，不把原始插件协议暴露给学生。

### 只读子智能体

保留主教师委派的检索和辅助判断。子智能体可以读取它被交付的材料并返回结果，但不能读取整课学情、写入卡片或学情、提交提案，也不能继续委派。

### 完整路线规划

保留学习目标、路线节点、计划和课程接续。路线规划与对话内路线图分工如下：

- 完整路线规划管理跨课的目标、节点、材料和后续安排；
- 对话内路线图呈现当前课堂实际走过的阶段和分支。

这两者继续复用现有课程、路线和 Session 绑定，不建立第三套计划系统。

## 移出默认产品的能力

以下能力保留代码、协议、存储和测试样本，但不进入默认安装组合、默认课堂 UI、默认教学提示词或默认模型工具集合：

- `board.*` 和数学工作台插件；
- `round.*`、回合面板和独立出题/作答/同伴/助教流程；
- Seminar 及多角色独立研讨；
- 其他插件工作台；
- Atlas、复杂实验插件和暂时没有明确入口的附加能力。

移出只改变默认启用和默认可见性，不删除实现。以后恢复某项能力时，再单独评估它的学生入口、工具 schema 和实际效果。

## 默认学生入口

默认课堂突出：

- 对话；
- 资料/知识库；
- 当前课堂路线图；
- 完整路线规划。

世界书作为课堂配置和背景能力存在。插件管理页可以继续保留，但默认课堂不因为已安装插件自动增加工作台标签。

当前 `LearningWorkspace` 的插件工作台动态渲染逻辑可以保留，默认视图集合需要改为显式实验配置控制。数学工作台和回合不应出现在默认课堂的入口或顶部视图列表中。

## 模型工具边界

默认模型面只提供五类能力对应的最小工具组：

- 知识库读取和受控写入；
- 当前课堂阶段和路线图读写；
- 完整路线规划的读取和提案；
- 世界书需要的课堂背景读取；
- 只读子智能体委派。

其余 74 个 method 仍可以留在 Host 注册表内，但不应全部进入默认 schema。`board.*`、`round.*`、Seminar 和其他实验工具从默认披露中移出。

## 验收范围

本轮只验证产品边界和基本接线：

- 全新实例的默认课堂不出现数学工作台、回合和其他实验工作台；
- 知识库可以读取实际资料和已有记录，并通过既有合同进行受控写入；
- 当前课堂路线图可以显示和恢复已有阶段；
- 完整路线可以读取、创建提案并与课堂接续；
- 世界书能按当前课堂配置提供背景；
- 只读子智能体能返回检索或判断结果，不能越权写入；
- 默认工具 schema 不包含被移出能力的工具集合。

真人试课中的具体教学质量问题单独记录和调整，不在这轮设计文档中预先规定答案。
