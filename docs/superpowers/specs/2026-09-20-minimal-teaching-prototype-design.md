# 最小教学原型设计

## 目标

先验证一条完整、可观察的教学闭环：学生进入课堂后，教师能从学生当前表达出发，用一个可完成的小动作推进理解，根据实际回答调整步幅，并在有证据时沉淀知识库记录。

这轮的目标是教学质量和学生可理解性，不是展示插件数量，也不是一次完成完整的课程管理平台。

## 默认产品边界

默认课堂只包含以下能力：

- 对话：学生和主教师的真实课堂。
- 知识库：资料、方法、卡片、学情的检索、阅读和受控写入。
- 对话内路线图：当前课堂阶段、节点和分支；只记录实际形成的阶段，不预先生成完整课程计划。
- 世界书：课堂背景、教学约定和可选同学配置。
- 子智能体：先支持只读检索和辅助判断；子智能体不能直接写入学习事实，结果回到主教师判断。

数学工作台、round、Seminar、多角色研讨、完整路线规划、Atlas 和其他插件工作台不属于默认课堂。它们的代码、协议、存储和测试样本保留，但不进入默认安装组合、默认课堂 UI、默认教学提示词或默认模型工具集合。

## 学生入口

默认课堂只突出“对话、资料、路线图”三个可理解的入口。世界书作为课堂配置和背景能力存在；它是否提供独立编辑页不影响学生完成学习闭环。

默认课堂不展示“回合”入口，也不把插件工作台作为课堂主导航。数学工作台若以后重新启用，应作为明确的实验能力单独加入，并能在同一套验收中与未启用版本对照。

现有 `LearningWorkspace` 的插件工作台发现和动态渲染逻辑保留，但默认视图集合不得因为已安装插件自动扩大。插件能力必须经过显式实验配置才能进入课堂。

## 教学行为合同

首轮和恢复教学遵守以下顺序：

1. 先接住学生当前表达，不从材料索引、旧小结或世界书自动推断学生已经准备好学习什么。
2. 学生只打招呼或没有提出目标时，先自然回应并询问想学什么、遇到什么问题，不能直接开始讲材料。
3. 学生给出目标或困难后，一次只给一个可执行的小动作。问题应要求学生写式子、做动作、指出关系或说明理由，而不是只让学生猜术语。
4. 学生表示听不懂、答非所问或无法起步时，先区分是术语、题意、表示方式还是方法步骤卡住；必要时给一个最小例子、对照或局部示范，再让学生完成下一小步。
5. 连续独立完成后才合并步骤；没有独立表现时只记录接触、讲解或提示后的表现，不宣称掌握。
6. 学生明确要求完整讲解时可以完整讲解，但讲解后必须安排一个独立小任务观察是否能迁移。

提示词负责表达教学原则，确定性的阶段状态、来源、版本、权限、幂等和写入仍由 Host、schema 和 domain 负责。

## 数据和工具边界

模型默认只看到最小课堂工具组：资料/知识读取、当前课堂阶段读取与推进、必要的受控记录或提案、以及只读子智能体委派。所有方法仍可在 Host 注册表中存在，但不因为注册存在就进入默认 schema。

知识库写入继续使用结构化合同。卡片、学情、方法和课堂小结分别保留来源、版本和证据边界；学生确认和版本冲突规则不因收缩 UI 而删除。

路线图第一版使用已有课堂阶段和思维节点投影，不引入第二套对话生命周期，也不把完整路线规划系统塞进每一轮课堂上下文。

子智能体第一版只做主教师明确委派的检索或辅助判断。它们不读取整课学情，不提交提案，不写卡片或学情，也不能继续委派。

## 明确移出的能力

- `board.*` 和数学工作台插件。
- `round.*`、回合面板和独立出题/作答/同伴/助教流程。
- Seminar 及多角色独立研讨。
- 默认暴露的插件工作台动态入口。
- 完整路线、计划、Atlas 和其他尚未证明能改善当前教学的高阶能力。

移出只改变默认可见性和默认启用，不删除实现。之后每次恢复一个能力时，必须有单独的启用开关、工具 schema 对照和教学质量对照。

## 成功标准

在全新隔离实例和真实浏览器课堂中，至少完成以下流程：

- 学生从“你好”或模糊目标开始，教师不会擅自选定材料和课题并连续讲解。
- 学生表达“听不懂”后，教师能先定位障碍，再提供一个学生实际能完成的小动作。
- 学生完成或部分完成后，教师能根据表现调整下一步，而不是机械推进预设问题。
- 课堂阶段路线在对话内可见，能回到已形成的节点，并且不会凭空生成未发生的学习阶段。
- 教师需要外部资料时能委派只读子智能体，结果回到主教师，不能绕过主会话写入学习事实。
- 学生明确要求沉淀时，知识库记录可读取、可回到来源，并保留确认、版本和证据边界。
- 默认课堂中没有数学工作台和回合入口，默认模型 schema 也不包含它们的工具集合。

## 质量验证

现有流程测试只能证明提示词装配、工具接线和记录落盘，不能证明教学质量。新增或改造验收时至少保留四类真实学生状态：

- 只打招呼，没有目标；
- 有目标但不知道从哪里开始；
- 明确说“听不懂”；
- 在提示后完成一步但尚不能迁移。

每个场景都记录学生可见回复、首个教师问题、是否先提供了必要支撑、学生是否完成下一步，以及是否错误地声称掌握。测试模型预写的正确回答不能替代这组证据。

## 后续恢复规则

恢复任何被移出的能力前，先回答三个问题：

1. 它解决的是当前学生闭环中的哪个具体缺口？
2. 它是否有清晰的学生入口和可见产物？
3. 启用后是否让首轮 schema、提示词、工具选择或教学步幅变差？

如果不能回答，能力继续留在实验区。
