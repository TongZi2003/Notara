# 调研

需要外部证据才能回答或准备的事都按这里做：学科或课程的难点与结构、公开课复刻、课程与考试大纲（备考另见 `notara-exam-prep`）、工具与版本事实，以及编写 Skill 之前的取证（见 `notara-skill-authoring`）。

## 先把问题写清

- 写明这次调研要回答什么、给谁用（本课、路线、学科层或学习集层 Skill）、要多深、什么程度算够。
- 拆成 3 到 6 个可检验的子问题，例如“这门课通常分哪几个单元”“学生最常卡在哪里”“用什么手段检验学会了”。
- 能从本 Vault 的资料、卡片、小结里回答的，先用 `notara-material-search` 查，不重复上网。

## 来源与等级

每条依据都注明等级、作者或机构、日期和位置。

1. 一手与官方：课程主页与教学大纲、学期日程、教材目录与前言、官方文档与标准、考试大纲。
2. 教学一线：名校公开课的讲义、作业与实验说明，任课教师写的教学文章。
3. 学习者经验：公众号、知乎、B 站、论坛、课程评价。用来发现“卡在哪里、常见误区、哪些资料好用”，属于二手，需要标明。
4. 机构与营销：培训机构的文章与课程介绍，只作线索，必须与前两级交叉核对。
5. 模型自身知识：可以作为起点和组织框架，不能当作事实出处；与来源冲突时以来源为准，没有来源的判断标“模型经验，待核对”。

## 检索做法

- 中文、英文分别查；同一个问题换两三种说法；加上学校、课程编号、教材名、版本年份这类具体词。
- 当前教师清单提供网页检索与读取工具时，用它们找候选并读取原文页；只有搜索摘要不算读到。没有工具或读取失败时说明缺口，不猜测页面内容。
- 公众号文章：有网页工具且能直接打开时可以读；需要登录、验证码或付费的入口不绕过，读不到就写“未读到”。
- 值得复用的原文，用 `write-batch` 存到 `知识/调研/`，写明来源、作者或机构、日期和链接。只存必要的摘录与自己的整理，不整站复制，尊重原作者的许可。
- 证据多时，把已经取得的原文交给 `general` 工作员整理成证据表，互不依赖的方向可以放后台并行（见 `notara-worker-orchestration`）。工作员能否联网取证按本次实际工具清单与权限判断；只有实际调用网页工具并核对回执后，才能说它已核验来源。无法联网或访问失败时，交接原文与来源并说明缺口。

## 综合

- 每个结论标注依据等级；几个独立来源一致才写成确定说法；来源冲突时并列保留，写明差异。
- 分开写“事实”（大纲规定什么、课程怎样安排）和“判断”（难点在哪、怎样教），后者说明依据。
- 写明缺口：哪些子问题没有找到可靠来源、哪些页面未读到。
- 按用途落地：学科层或学习集层 Skill 按 `notara-skill-authoring`；路线与一节课都按 `notara-lesson-preparation`；只是回答问题时，给出结论和来源即可。

## 公开课复刻

- 先找齐：课程主页、学期日程（讲座、实验、作业、项目、考试）、教材与阅读、作业说明与测试方式、先修要求，以及课程的许可证。
- 对应到路线：讲座按单元成为阶段和节点；实验与作业成为练习和代码任务；项目成为跨几节课的项目节点；考试成为阶段检查点。
- 许可证在原站核对。常见的公开课许可证会限制商业使用或改编。个人学习时，可以在 Vault 里整理笔记、写自己的练习；照搬原文或对外分享要遵守许可证；不确定时只链接原文。
- 复刻的是结构和难度，不是照搬节奏：按学生的学情与四档阶段调整。编程作业用本机已有的工具链，配合 doctest 或 pytest 自测。

## 边界

- 不编造来源、作者、日期或链接；不把搜索摘要当作原文。
- 不绕过登录、付费、验证码或反爬限制；不收集与任务无关的个人信息。
- 调研结论只是准备材料，不等于学生已经学会，也不自动改变路线或启用 Skill。
