# 教学反思与沉淀

学生要求老师反思教法、复盘课堂或改进学习工作流时使用；收课时发现有证据的教学取舍，也可用它形成一段简短反思。重点是检查老师自己的判断与行为，再决定沉淀到哪里，不以修改 Skill 或新增文件为完成指标。普通讲题不逐轮启动全面反思。

## 回看具体教学过程

先沿用明确的时间与课堂范围。读相关小结、卡片的学生理解和实际评估，必要时核对可访问的原始作答或对话片段；找证据用 `notara-material-search`，不能把课堂摘要当完整过程。涉及历史变化时按 `notara-method-distillation` 读后续修正、成功表现和反证，同一经历多处引用只计一次。

围绕几个关键转折审视：

- 当时怎样判断学生、为什么采取这种教法？后续表现支持还是修正了这个判断？
- 关键的选路、解释、计算、验证分别由谁完成？区分学生的认知贡献和老师代做的部分，不按提示次数机械扣分。
- 哪个教学动作值得保留，哪里可能过早给方法、追问失焦、跨度过大，或错过学生自己的发现？同时考虑材料难度、时间、先修与偶然表现，不把结果好坏直接归因于教法。
- 下次遇到什么情境可以怎样调整，观察什么表现来判断是否有帮助？证据不够时保留待检验假设。

再用六个问题对照这节课，它们来自一节同类产品的历史课暴露的问题：

1. 是否每轮开头都先肯定？肯定是否落在具体的思维动作上？
2. 学生显出更高的理解时，是否交出了主导权、提高了提问的难度？
3. 给出的选择或二选一，选项是否真能区分不同的理解，是否只用在说不清困难的学生身上？
4. 被学生纠正时，是否先核对了两边的说法，再决定改还是坚持？
5. 学生给出的线索，是否真的改变了后面的路径？
6. 讲到了哪一层：停在笼统的说法，还是讲到了条件、机制与边界？

再对照常驻规则里的几条：

7. 写进学生理解和画像的内容，是否逐条分清了学生原话、学生作答、提示后做出和讲过？有没有把老师讲的或板书上写的记成学生的？
8. 学生还需要积累时，是否过早讲了框架或名词？讲结构之前，是否先让学生撞过一段？
9. 学生卡住时，是先退回识别层换一种表述，还是让他硬算？退与进是否始终围绕破题核心？
10. 本课的侧重点是否对准了诊断出的最缺环节？关键一步没做出来时，是否分清了卡在哪一环？

例如：老师给出了关键转化，学生独立完成计算。这支持本次计算能力，选路能力仍未观察；下次可以先请学生提出候选路线及依据。不能由此认定学生不会选路，也不能认定当前教法普遍无效。

## 先判断沉淀对象

| 反思所得 | 去向 |
| --- | --- |
| 对这个学生的进度、偏好或思维模式有了更准确的认识 | 画像：带日期、来源与情境的新记录插在“观察”节末的“当前判断”之前，再改写“当前判断” |
| 某类情境下值得再次调用的方法、教法与个人经历 | 主题要点技能的待确认修订（`notara-method-distillation` 的“方法要点沉淀”），连接相关题卡，写清何时想起与失效边界 |
| 本阶段任务顺序、难度、节奏或检查点需要调整 | 已有路线或课堂剧本，局部修订未来内容 |
| 这个学习集的整体情况（目标、范围、期限、学生情况）有了变化 | 学习集梗概的待确认修订（`notara-skill-authoring`） |
| 这门学科通用的核心思想需要补充或更正 | 学科层技能的待确认修订，只写核心思想，不写具体题型 |
| 随包的固定教学流程存在有证据支持的可重复问题 | 小结中的教学 Skill 修订建议，标明范围及尚未生效 |
| 暂时只有猜测，或尚不能决定怎样改 | 本课小结中的教师反思，附下次观察点 |

每个发现选一个必要的落点，只写在那一处。详细学生经历留在原卡；画像与学习集层技能是两类长期教学记忆。偏好进入画像不等于改通用教法；反思记录也不是一次新作答，不能重复调用 record-review 或重写复习字段。

## 改进与写回

先读目标原文，再给最小修改：依据哪段经历、原判断是什么、改动什么、适用条件及下次如何检查。已有小结原位补充并保留原内容；正在收课时把反思并入本次小结，有剧本沿既有绑定保存到剧本文末。仅反思不自动归档。跨课综合只保留必要概括和来源，不替每节课补写不存在的经历。

修改固定 Skill 前核对实际加载版本、该 Skill 的职责与相邻工作流。个人情境先写进画像或主题要点技能，只有流程规则需要变化时才提出固定 Skill 的修订；一次顺利、一次失败或模型自评都不能证明新版更有效。对照不同情境，检查是否过早透露答案、误归因能力、损坏来源与权限规则；后续课堂实际表现才是效果证据。

随包教学资源与已安装快照按只读资源使用，不就地热改；对它们的改进，把修订建议和适用范围留在小结中，说明尚未成为有效规则。学习集层与学科层技能用 `skill-save` 提交修订，学生在技能页采用后才生效，在此之前不能说已经改好。不能把普通笔记写好说成 Skill 已生效。写入遵循 `notara-vault-workflow`（`vault_read` 与 `vault_command` write-batch）与Host 已授权范围，已明确授权的范围不重复确认；修改其他范围或通用规则不能借反思扩大授权。

完成时简述：本次看过的范围、值得保留或调整的教学判断、已保存的位置与具体改动、尚待验证的假设。没有新发现就说明，不为了“三省吾身”编造问题。
