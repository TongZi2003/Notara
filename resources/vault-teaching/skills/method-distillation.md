# 整理学习经历与方法要点

学生的认知演变记在对应卡片的“学生理解”里，每次评估记在题卡上，被真实表现验证过的做法写成本学习集的方法要点。原料是学生的实际作答、试错过程和明确反馈。学生的一次真实错误、困惑或局部修正，可以直接记进这张卡的学生理解；要写成可以复用的方法，需要验证过，见“方法要点沉淀”。

## 学生理解：保留认知演变

学生理解保存学生对这个具体题目、知识或方法的认识怎样变化。卡片保持三个二级部分，在 `## 学生理解` 内用普通段落、列表或三级小标题按实际先后记录；还没有学生证据时这一节留空。

- 记下最初怎样理解、为什么这样尝试，包括不完备和错误的认识；学生自己说出的理由才写成理由。每一条注明来源：学生原话、学生作答、提示后做出、讲过，与常驻规则「观察与掌握」同一口径；直接引语与基于作答的概括分开写。
- 记下转折的真实证据：哪个问题、反例、提示、实验或反馈让学生重新考虑，随后学生实际说了什么、做了什么，每个关键步骤由谁完成。老师讲过的内容记为讲过；学生在引导下做出的认知贡献照样记给学生。
- 迁移写清是学生主动做出的，还是老师指明方向之后做出的，两者分量不同。
- 学生说出自己是看到什么线索才想到这条路的，原样记下这条线索和他说的目的（“我想得到……”）；这是学生按目的建立索引的证据。
- 后续尝试、迁移、复习中的保持或再次出错继续往后追加。当前判断可以简短写在最后，与历史阶段分开，包括学生到了哪一层、下次要先查什么；旧错留在历史里，正确的新表现也留作诊断证据。
- 来源用可核对的题目、卡片、课堂或试卷，日期写实际已知的日期，缺失的环节标“未知”。记关键变化，整段对话和观察不到的内心活动留在记录之外。
- 更新前先读原小节，在旧记录之后补新阶段。发现误转写、误归因时，写明更正及依据再改正。学生明确要求更正或删除时，按学生的要求处理。

## 诊断时怎样使用历史

从当前错题或试卷的实际作答出发，按 `notara-material-search` 召回相关卡片的学生理解、画像、学习集层技能里的方法要点（旧的 `锦囊/` 一起查）和必要的课堂小结。按先后读提示程度、后续修正与最近表现，再比较结构和条件是否相同；已有的诊断结论是线索，原始作答才是依据。

综合时分列支持、反证或已改善的表现、情境差异与未知项。同一段经历在卡片、要点和小结里被多处引用，只算一次；多次观察的原因也要单独核实。

原作答说明发生了什么，原因是待检验的假设：结合本次表现和学生对当时思路、时间与帮助的补充来验证，必要时用一个能区分原因的小任务。结论写清适用范围、依据、仍不确定的部分和下一步；一次错误只说明这一次。

分工：题目或知识上的详细演变留在对应卡片；可复用的选路与教学经历写成方法要点；画像的“观察”按先后追加带日期、来源和条件的判断并指回证据，旧判断不删，留作修订来由；节末保留一段简短的“当前判断”，与历史分开，写法与卡片学生理解相同：新记录插在“当前判断”之前，再改写“当前判断”。系统每节课只注入各节末尾一段，所以“当前判断”必须在最后。用 `notara write-batch` 写到 `学情/`（见 `notara-vault-workflow`）。

## 记录评估与复习档位

**固定收束动作：一道题讨论结束、转入下一题前，主动记录本轮评估。** 按本题目标已讨论完、学生表示换题或即将切换学习任务来判断收束；中途追问和暂时停顿属于同一次讨论。同一段讨论只记一次，之后新的尝试或复习再追加新记录；记录前先核对已有记录与本轮的保存回执，下课总结时直接沿用。

1. 找到本题已有的 `type: card` 题卡，核对题面和来源后复用。还没有就按当前卡片模板一题一卡新建，保留完整原题事实、来源和三段结构；整本资料、专题或讲义保持原样，另建题卡。材料不足以可靠建卡时，说明评估这次还没落盘。新建的卡在参考理解里写好常见错法的预判；复用的旧卡还没有这一小节时，顺手补上。
2. 先读本题原“学生理解”，对照本轮有没有还没记录的真实尝试、认识或转折；有就先追加正文，保留旧记录和复习字段，确认写入成功再做下一步。写进去的是真实发生的环节：旧误解、引导或反例、学生后来的修正及实际表现；同一经历已经写过就沿用。评估的 `note` 另记，正文照常追加。学生踩中或避开了常见错法里的预判，或者踩了预判外的坑，同时在那一条下面补一行实见。
3. 用第 2 步 `notara write-batch` 回执里该文件的 `revision`（正文没有改动时，用 `notara review-queue` 的 `status: all` 查这张卡的 `revision`；默认的 `due` 只列到期卡），作为 `expectedRevision` 调用 `notara record-review`，写入本次的评估。只讲解、学生还没有尝试时，关键一步记 `unchecked`，说明里写“讲过”。
4. 评估追加到题卡页头的 `review_history`，复习档位和日期由命令在同一次写入中算好；正文由第 2 步负责。核对正文与评估两份回执，必要时回读本题；任一步失败就说明缺了哪一部分。

这些写入沿用当前Host 已授权范围，直接执行；学生明确要求不保存时照办。下一次复习先读学生理解的完整演变和最后的当前判断，据此选检查任务。

**评估怎样写**：

- 一次评估记关键一步和说明，关键一步决定复习档位。
- **关键一步**：`keyStep` 写这次检验的是这道题哪一步关键的思维步骤，`result` 记学生有没有独立做出这一步：
  - 学生独立做出来，记 `done`；讲解之后，学生在变式里独立做出这一步，也记 `done`；
  - 学生试了、没做出来，或最后由老师点出这一步，记 `missed`；
  - 老师直接讲、学生没试，记 `unchecked`，说明里写“讲过”；
  - 学生只报结果、追问一次后仍不想展开，按给出的结果记；
  - 拿不准的不记成 `missed`：结果对了记 `done`，实在拿不准记 `unchecked`，把能区分原因的小测试写进学生理解最后的当前判断，下次先查。
- 学生到了哪一层（推导、改条件、反例、边界、迁移）、踩了哪个坑、下次想查什么，写进卡片：层次和演变写在学生理解，踩中的坑补成常见错法的实见，下次要查的点写在学生理解最后的当前判断里。
- 看每一步由谁完成：老师点出关键工具、学生自己判断是否适用并提出替代方法时，适用性判断与替代方法记给学生；老师代做的那一步记给老师，能否不经提醒想到它，留到下次再看。提示次数本身不减分。剧本里的理想步骤只是计划，有效的简洁解法照样算数。
- 结果和过程分开看：正确结果支持它实际展示的部分；已经在后续表现中修正的旧错误，留在认知演变里。
- `note` 是这次的证据摘要：学生真实的认知贡献（原话或具体动作）、老师给过的具体引导，以及这次据以判断的证据。它只记当次，卡片正文的学生理解照常另写；早期记录里的其他字段只读保留。

**两种复习**：

- **简单复习**：
  - 学生随手点开一张到期的卡。请学生独立做这道题或它的关键一步；学生要求讲解时再讲。
  - 检查点只落在这道题关键的思维步骤上：想到用什么方法，关键那一步为什么这样走。说清思路就够，常规计算和抄写式子不另外要求。题卡的常见错法里有现成的区分追问，先从那里挑。
  - 结果区分不出原因时，追问一个能把几种可能分开的小测试，只测那一步。例如解 2(x+3)=10，两个学生都得到 x=3.5：一个把括号展开成 2x+3，一个展开对了、移项时只减了 3；问一句“先别解方程，单独把 2(x+3) 展开给我看”就分开了。结果对了也一样：换个数问关键那一步，就能分出是会做还是记得答案。
  - 学生只报结果、追问一次后仍不想展开，就按给出的结果记，这一步留到下次。
  - 评估只判关键一步，做出来就照常升档。
  - 关键一步做出来以后，再抛一纵一横两个问题（基本概念里的“纵向与横向”）：纵向问这一步为什么成立、再往下一层是什么，横向问同一个模式还在哪里出现。问题从题卡的参考理解、学生理解和父节点里找，比学生理解里已到的层次高一层。这是加深，不是检查点：答到哪一层写进学生理解，不改这次关键一步的记录；答不上来就讲清，把这个问题写进当前判断，下次再问。关键一步没做出来时不抛，先补这一步；学生只想快速过卡时也不抛。
  - 复习档位是“记得、熟练”的间隔，深度看学生理解。
  - 看解永远自由，账记在看解之后学生独立做出来的部分上。
- **精致复习**：排好的复习课，按 `notara-consolidation`（体系梳理）上。
  - 先请学生把相关的卡理成结构，再用新情境检验本质层：新情境请出题员按迁移距离出（同题换数、同类换条件、同学科换章节、跨学科、生活）。
  - 攻不动的地方，退回机制或特例补上。
  - 学生在新情境里到了哪一层（例如“迁移（主动）”“边界”），写进原卡的学生理解；原题的关键一步这次没考，评估就记 `unchecked`。
- 重做同一道题说明记得这道题，记在关键一步；本质层用新情境检验，写进学生理解。

**档位与排期**：由命令按关键一步的结果算出。

- 还没开始复习的卡：`done` 或 `missed` 都从第 1 档开始复习；`unchecked` 只留历史，暂不开始复习。
- 已在复习的卡：
  - `missed` 降一档（最低第 1 档）并重新排期；
  - `unchecked` 只留历史，档位和到期日照旧；
  - `done` 在已经到期（当天不早于 `next_review`）时升一档，提前做出来保持原排期。
- 五档是 1／3／7／16／35 天。
- 记错了用 `notara undo-review` 撤销最近一次评估；复习字段只由命令维护。

**用到的命令**（字段以各命令的 `--help` 为准；调用方式与 `notara write-batch` 见 `notara-vault-workflow`）：

- `notara review-queue`：查当前学习集的卡片候选，可按标题检索、标签、状态和分页，返回真实路径与 `revision`。默认只列到期卡；要找某张卡的 `revision` 用 `status: all`。
- `notara record-review`：按上面的步骤记录本题评估，传 `path`、正文更新后的 `revision`（作为 `expectedRevision`）、`keyStep`、`result` 和必需的 `note`。日期、记录 ID、课堂身份与排期由命令补齐；早期记录里的其他字段只读保留。
- `notara undo-review`：撤销最近一次还没撤销的评估，恢复它之前的档位；当前值已被外部改动时命令会拒绝，重新读取后再决定。
- `notara calendar`：按 `from`/`to`（`YYYY-MM-DD`）看路线安排、课堂小结、日记和到期卡片。

## 方法要点沉淀

方法要点写在学习集层技能里，一份技能对应一个主题，例如“圆锥曲线要点”。每条要点写六项：

1. **何时想起**：写成想得到什么，即要得到、要消掉、要判断或要比较什么，写到机制那一层，例如“要得到弦的中点与斜率之间的关系时”；不写章节或题型名（“圆锥曲线题”）。思维障碍也可以作触发，同样写到机制那一层。
2. **条件**：这个做法成立需要什么。
3. **做法**：可以再次执行的步骤，包括在这种情境里怎么讲、怎么安排任务。
4. **为什么成立**：写到机制那一层。
5. **在哪里失效**：已知的失效条件、反例和没走通的过程。先从目的推：这个做法是为了得到什么，哪些情形下得不到。
6. **依据**：哪次课、哪张卡；是学生主动发现的，还是老师给的。

易错规则也写成要点。它的触发往往是“操作碰上某种对象”，单看操作或单看对象都不触发，所以何时想起写这个交叉处（“去分母碰上符号不定的分母”），做法写检查动作（“先分类讨论”），在哪里失效写不检查会怎样失真（“丢解或增解”）。

- 还没有验证的写进这份技能的“待验证”。一次真实经历可以作为带情境的经历记下，写成方法要有验证。学生的详细经历留在卡片的“学生理解”，要点写概括并指回卡片；学生状态的认识写进 `学情/` 的画像。
- 技能说明按目的列出这个主题里的几种触发情形。一种做法可以挂在几个目的下；同一个目的下有几种做法时并列，写清各自的条件与代价，供选路比较。已启用技能的说明每轮都列在技能目录里，老师靠它想起这份技能。
- **写的时机**有三个：
  - 一道题收口时，问一句这次的选路或讲法下次是否值得想起；
  - 头脑风暴或体系梳理结束时；
  - 保存课堂小结时。
- **怎样写入**：
  - 先用 `notara skill-list`、`notara skill-read` 看本学习集已有的主题技能，同一方法的改进并入原要点，确认是新方法再新增。
  - 一节课的候选合成一份，用 `notara skill-save` 写入：这个主题的技能已启用就生成一份修订，还没有就新建草稿。格式见 `notara-skill-authoring`。这个主题已有待采用的修订时，在那份修订上合并，并告诉学生上一份还没采用（做法见 `notara-skill-authoring`「保存与生效」）。
  - 保存后告诉学生去技能页看，由学生决定采用和启用。
- **回写**：用过一条要点后，把这次管不管用补进它的依据；不管用就补“在哪里失效”。同样以修订交学生采用。
- **旧锦囊**：`锦囊/` 下已有的文件照旧可以检索和读取。用到一条时，可以建议把它并进对应的主题技能，由学生确认。新的方法经历一律写进主题技能。
- 混合教法里的几种讲法是一般的讲法；主题技能里写的是这个学习集里具体情境下的做法。用到一条要点时，按当前学生的情况取用，本课教法和画像照旧。

## 固定 Skill 的修订边界

内置的学科关注这类稳定技能，只在有真实证据时建议更新：学生在实际课堂里的独立表现与反复出现的障碍，或用户自己提出的修订。一课的动态 brief、一次顺利的讲解、工作员或子 Agent 的自评，先作为本学习集的方法要点保存，写清适用条件与失效边界；要改固定技能时先说明依据，由用户决定。

回看老师自己的判断和教学行为时读 `notara-teaching-reflection`；综合近期学习并提出后续方向时读 `notara-learning-review`。本技能负责认知演变、评估、画像与方法要点的记录。
