# 整理学习经历与方法（锦囊）

把本课或近期课堂里被真实表现验证、或被反复使用过的做法，整理成可召回的锦囊。原料是学生的实际作答、试错过程和明确反馈；单次顺利、你的推测或泛泛经验不构成依据。

学生的一次真实错误、困惑或局部修正本身可以记录在对应卡片的学生理解中，不必等到形成稳定模式或锦囊。一次经历是否支持更广的判断，需要另行核对。

## 学生理解：保留认知演变

学生理解保存对这个具体题目、知识或方法的真实认识如何变化。保持三个二级部分不变，在 `## 学生理解` 内用普通段落、列表或三级小标题按实际先后记录；没有学生证据时仍为空，不加入虚构示例或默认掌握结论。

- 保留最初怎样理解、为何这样尝试，包括不完备和错误认识；学生没有表达过的理由不能代猜。直接引语与基于作答的概括分开。
- 记录转折的真实证据：哪个问题、反例、提示、实验或反馈使他重新考虑；随后实际说了什么、做了什么，以及每个关键步骤由谁完成。老师已经解释过不等于学生已经形成新理解，受到引导也不抹去学生自己的认知贡献。
- 后续尝试、迁移、复习时的保持或再次出错继续追加。可以有简短的当前判断，但必须与历史阶段分开；不把旧错当当前状态，也不把正确的新表现从诊断证据中删掉。
- 沿用可核对的题目、卡片、课堂或试卷来源，日期只写实际已知的日期。缺失环节标未知，保留有证据的关键变化，不抄全段对话、不补写不可观察的内心活动。
- 更新前读原小节，保留真实旧记录后再补新阶段。修正误转写、误归因时说明更正及依据；这种记录错误不应继续充当学生经历。用户明确要求更正或删除时依其要求处理。

## 诊断时怎样使用历史

从当前错题或试卷的实际作答出发，按 `notara-material-search` 召回相关卡片的学生理解、画像、锦囊和必要课堂小结。读历史的先后关系、提示程度、后续修正及最近表现，再比较是否是相同结构和条件；已有诊断结论只是线索，不能替代原始作答。

综合时分别列支持、反证或已改善的表现、情境差异与未知项。同一题在卡片、锦囊和小结里的重复引用只算同一次经历，不据重复记录制造“反复出错”；多次观察也不自动证明同一个原因。

原作答说明发生了什么，原因是待检验假设。历史模式要结合本次表现及用户对当时思路、时间和帮助的补充信息验证；必要时用一个能区分原因的小任务。结论说明适用范围、依据、仍不确定的部分和下一步，不把单次错误升级为永久能力标签。

题目或知识上的演变详细记录留在对应卡片；可复用的选路与教学经历按下文整理为锦囊；画像只写带来源和条件的当前概括并指回证据，保留曾有判断的修订来由，不复制所有历史形成第三套记忆账本。

## 记录评估与复习档位

**固定收束动作：一道题讨论结束、转入下一题前，主动记录本轮评估，不等待学生另说“保存评估”。** 主教师根据本题目标已讨论完、学生表示换题或即将切换学习任务来判断收束；中途追问、暂时停顿不算新的一次收束，不为每次苏格拉底追问都记一条。同一段讨论只记一次，后续新的尝试或复习可追加新记录；先核对已有记录与本轮保存回执，避免下课总结时再次记录同一经历。

1. 找到本题已有的 `type: card` 题卡，核对题面和来源，复用该卡。若还没有，按当前卡片模板创建一题一卡，保留完整原题事实、来源及三段结构；不能把整本资料、专题或讲义直接改成题卡，也不因换一种讲法再建重复卡。材料不足以可靠建卡时说明评估尚未落盘，不编造题面或挂到另一题上。
2. 先读本题原“学生理解”，对照本轮是否有尚未记录的真实尝试、认识或转折；有就先追加正文，保留旧记录和复习字段，确认写入成功后再做下一步。包括旧误解、引导或反例、学生后来的修正及实际表现，只写真实发生的环节。已有同一经历不重复写，仅听过讲解的地方不补编学生观点。不能因评估的 `note` 已提到这些经历而跳过正文。
3. 用 `review-queue` 取得正文更新后的真实 `revision`，再以它作为 `expectedRevision` 调用 `record-review`，写入本次具体能力观察与必需说明。纯讲解、尚未取得学生作答或解释时，将本次检验点记为 `not_observed`，在说明中写清仅讲解、尚无学生证据；不为此强制加一道测试。
4. 评估追加到这张题卡页头的 `review_history`，复习档位和日期由命令在同一次文件写入中处理；命令不会代写正文。核对正文保存与评估保存的两份回执，必要时回读本题；任一步失败都说明缺失部分，评估成功不能替代“学生理解”已保存的确认。下课小结同样不能补偿漏写的题卡记录。

上述写入沿用当前原生权限，不额外设一轮“是否记录”的对话确认；学生明确要求不保存时服从。评估只覆盖本题本次要检验的能力，不拿一次课堂给整门课或全部能力下结论。下一次复习先读这些观察及学生理解的完整演变，据此选择检查任务；不强求每次引导后立即补测。

- 每项写一条 `ability` 和一个 `outcome`，1–8 项，能力名不重复。`ability` 具体到这次真正在检验的动作或判断（比如“自己判断极点极线是否适用并改用参数方程”），不写“数学能力”“基础扎实”这类笼统标签。
- `outcome` 看这一项在整段引导里由谁完成，而不是数提示次数：`demonstrated` 是学生自己完成了这项认知工作，`needs_practice` 是有真实困难或错误，`not_observed` 是这次没有取得证据。属于本次目标却这次没考到的能力保留为 `not_observed`，不删掉，也不把与本次目标无关的能力都列成未知。
- 写 `needs_practice` 前，必须能指出这项能力当前实际暴露的错误、失败尝试或学生明确表达的困难。若理由只有“未展示、没写出、跳过、还需检查”，只能说明缺少观察；属于本次目标的记 `not_observed`，与目标无关的不临时加成扣分项。剧本中的理想步骤和下一步想检查的内容不是学生失败的事实，不为凑齐步骤否定有效的简洁解法。
- 区分结果和过程：正确结果未必证明未展示的推导，但过程没展开也不能反推不会。分别记录实际支持的能力与未知项，不将整题一概降档；已经在后续真实表现中修正的旧错误留在认知演变里，不继续冒充当前困难。
- 社会性、组织性追问或提醒一个候选方法不天然减分。老师点出关键工具、由学生自己判断是否适用并提出替代方法时，适用性判断与替代方法可以是 `demonstrated`；老师代替学生做的那一步不算学生做的，能否在不再提醒时唤起同一能力留给下一次观察，这次记 `not_observed`。
- `note` 是这次的证据摘要：写清学生真实的认知贡献与原话或具体动作、老师给过哪些具体引导、这次据以判断的证据，以及还没观察到的部分。它只记当次，不覆盖卡片正文的学生理解，不因提示次数扣分，也不新增画像或第二套账本；早期记录里的旧 `passed` 只读保留。
- 档位与排期由命令按结果算出，不由你填：有任意一条真实 `needs_practice` 就降一档；没有困难但有 `not_observed` 只留历史，不改档也不推迟到期；全部 `demonstrated` 时首次从第 1 档起算，之后只有已经到期（当天不早于 `next_review`）才升一档，提前成功保持原排期。1／3／7／16／35 天的五档不变。
- 记错了用 `undo-review` 撤销最近一次评估，不新写一条相反记录，也不手改卡片 frontmatter 里的复习字段。

## 锦囊沉淀

锦囊是一体化的卡片，同一张里写清：何时想起（什么题目结构、思维障碍或教学决策值得想起它）、方法与教法（可再次执行的步骤，不写“多练习”式空话）、学生在具体情境中的经历、以及适用边界。已知的失效条件、反例或没走通的过程同样可以保存为带情境的经历，不因为案例没有成功就丢弃，也不设案例数门槛。

锦囊页头用tags，正文沿用“内容、参考理解、学生理解”：内容保留具体情境与真实经历（涉及题目就保留足够完整的题面事实及来源）；参考理解写方法、教法、触发条件与失效边界；学生理解按上面的演变规则记录，没有则留空。不要把模型自拟的感悟当作学生经历。一般同类内容的共性先归 `topic` 父节点，不凭资料整理就宣称形成了个人锦囊。

触发条件保留在参考理解下的 `### 何时想起`，这是现有渐进召回读取的小节；方法与边界写在其后的 `### 方法与边界`。不额外增加第四个顶层部分。

先用 glob 找到锦囊与学情文件、grep 缩小候选，再 read 已有锦囊正文核对：同一方法的改进并入原卡片，不新建平行条目；确认是新方法才新建。方法与教法是一体两面，具体情境里怎么讲、怎么安排任务同样属于锦囊；原则性教法 Skill（如苏格拉底、费曼、结构分析）是一般教学方式，属于教学预设的能力资源，不是第三类学生记忆。关于学生状态的认识（学习进度、相关水平、偏好、值得关注的思维模式）写进 `学情/` 的画像，不放锦囊。

保存用原生 write / edit 并走原生批准；没有被同意就说还没保存，不另设第二次收录审批。检索命中锦囊不自动切换本课教法，也不自动修改画像。

## 固定 Skill 的修订边界

稳定的学科与课型 Skill（数学、理科建模、人文语言等）只在有真实证据时才建议更新：学生在实际课堂里的独立表现与反复出现的障碍，或用户自己提出的修订。一课动态 brief、一次顺利的讲解、工作员或子 Agent 的自评都不能自动升格为通用教法，不能因为一次课堂就写进固定 Skill。个人有效的方法与经历先按锦囊保存，写清适用条件与失效边界；要改固定 Skill 时先说明依据，由用户决定。

需要回看老师自己的判断和教学行为时读 `notara-teaching-reflection`，由它判断沉淀对象；需要综合近期学习并提出后续方向时读 `notara-learning-review`。本 Skill 继续负责已有证据的认知演变、画像与锦囊记录，不另复制这两条工作流。
