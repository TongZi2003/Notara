# 板书

白板是你和学生共用的工作面，也是学生的练习纸。这份技能讲怎样组织板块、什么时候用哪一种作答题、各种任务作用和教学动作怎样落到板上，以及怎样回应学生在白板上的作答。

## 什么内容上板

- 需要一起看、一起想、一起动手的内容才上板：题面、关键条件、学生的尝试、推导、比较、结论、要学生表态的判断。
- 寒暄、一句话就能说清的回应、只对你有用的分析不上板。不必每轮都写。
- 板书只写学生当下应当看到的内容。折叠不是保密：提示、参考推导、答案在讲到之前不写上去。

## 板块与块

- 一道题或一个主题开一个板块：`section` 写板块标题，如“第1题 中点弦的斜率”“两种解法比较”。同名归入已有板块；不写就接着上一块所在的板块。
- 块要短，一块只做一件事：一段题面、一次尝试、一个提示、一段推导、一个结论、一道作答题。先输出 title 再输出 body，文字会在目标位置流式呈现。
- 真实用过的资料在正文以 `[[相对路径|资料名]]` 引用，知识面由这些引用生成，所以只引用读过、用过的资料。
- `size`：`narrow`（默认，一栏）放短段落和作答题；`wide`（两栏）放表格、较长的推导；`full`（整行）放长推导或要横向展开的比较。
- `placement`：`beside` 把学生的尝试写在题目旁边、把两种解法并排；`below` 把补充紧接在某块下面。只关联同一板块内的块。
- `kind`：`question` 题面与作答题，`note` 讲解、演示与结论，`hint` 已给出的提示，`reference` 已讲的参考推导，`attempt` 学生公开的尝试。后三种默认折叠，导出时默认不带；要学生当场看、当场动手的内容不要放进这三种，带 `predict` 的逐帧演示用 `question`。
- 纠错：先读取目标的稳定块 ID，再局部改原块；同名标题可以属于不同块，不能用标题猜目标。板上的内容改了时，可以在块里加一句“认识变化：……”，只说原来板上写的是什么、现在改成什么。它不评价学生的作答：对学生认识的判断写进题卡，不上白板。改写保留这一块的作答和学生拖到的位置，旧题目组件的指纹受保护。
- 学生拖过的块会钉住；学生高亮过的块，你改写前要先读一遍（保存会提示）。
- 收到保存成功的回执后，再说已经写上板；保存冲突时重新读取白板再修订。

## 自由白板与接续共建

学生可以自己创建文字、绘图、资料卡或导图，输入与拖动本身不会开模型回合。收到“请老师完善”时，只处理学生选定的块或元素；保留原稿、无关文字和手工布局。老师补全的推导不算学生独立完成，也不写成掌握证据。

白板 Agent 入口统一为 Bash 内的 `notara board` CLI。先 `notara board --help`，再 `notara board list` 找到稳定块 ID 和当前 revision。同名标题合法，不能用标题猜目标。当前课堂与身份由 Host 绑定，不能通过参数填写 session、actor、账号、路径根或时间。没有命令沙箱时 CLI 不可用，不能换普通进程或直接覆写白板文件。

1. `notara board read --block <目标ID>` 读取最新版正文、元素与导图关系，并在 Host 建立基线。场景默认每页 20 个元素，用 `--offset` / `--limit` 继续读取；图片只返回身份与类型。
2. 修改写成 UTF-8 JSON 文件，再 `notara board apply --input changes.json`；也支持 `--input -` 配合引号保护的 heredoc。不要把大段 JSON 拼成 shell 参数。回执统一为 `{ok,value}` 或 `{ok:false,error:{code,message}}`，非零退出表示失败。
3. 只有回执 `saved:true` 才说已保存。需要撤回一次老师贡献时 `notara board undo --change <回执commitId>`；学生后续重叠输入会受到保护。

创建、删除、连线与分组等结构操作必须带 `list` 返回的 `expectedRevision`。正文/图内 patch 按目标已读字段合并当前板，无关布局变化可以保留；冲突必须先重读，不能盲重试全量旧图。一次提交同时保存学生原稿、Host 贡献身份、必要前值和撤销回执，老师补全不能算学生独立完成。

```json
{"expectedRevision":null,"ops":[{"type":"create","ref":"new","title":"我的尝试","body":"公开内容","contentType":"text"}]}
```

上例的 `null` 仅用于尚无白板文件的首次创建；已有白板照抄真实 revision。正式块 ID 由 Host 分配，见回执的 `created`。旧六类组件仍写在 Markdown 正文里。

```json
{"ops":[{"type":"patch","blockId":"已读取的真实ID","patch":{"body":"保留学生已有内容，仅补请求的部分"}}]}
```

图内局部修改在同一个 `patch` 中用 `sceneOps`：`updateElement`（已读 `elementId` 与 `patch`）、`addElement`（临时代号 `ref` 与不含正式 ID 的 `element`）、`removeElement`。新元素 ID 由 Host 生成；不传全量旧场景。

导图节点用 `addNode`（`ref/element/parentId`）、`reparentNode`（`nodeId/parentId`）、`removeBranch`、`layoutBranch`；父子身份是元素 ID，不能靠箭头外观猜。跨支关联用 `addLink`（`ref/from/to/label`），移除用 `removeLink`，注释用 `setNote`（`elementId/text`）。它们只是同一次白板事务里的有限操作，不是新增工具。

`board_read_required` 要先读目标；`board_edit_conflict` 要重读并保留学生新输入；`board_undo_conflict` 保留后续内容并报告未撤销。失败或取消的临时预览不是已保存板书。内部内容文件、history 和 Markdown 提交根不经普通文件工具直接写。

## 作答题

需要学生表态或动手的封闭小题放进块里做作答题；开放的问题直接在对话里问。

- 同时挂着的未作答题最多一到两道。学生答完、你回应后再出下一道。
- 作答以学生消息到达，前缀〔白板｜板块｜题目〕标明是哪一题；每轮的白板概况里也能看到作答次数和最近一次的内容。
- 写法里没有标准答案。对错由你在收到作答后判断，不写在白板上。
- 学生交答案之前，对话里只说题在哪、要做什么，不讲解答案，也不暗示该选哪一项。
- 关键的一步（递推式、关键等式、选路的理由）先做成 `blank` 或一个小问题让学生建；建好或卡住后再讲解或放逐帧演示。学生明确说“直接讲给我”时才直接给。
- 每道题都自动附带“不确定”和“都不对，我觉得……”（补一步、排序是“我有别的想法……”）。学生选了它们也是有用的信息：选项没覆盖学生的想法，可能是学生走在前面，也可能是需要更小的一步。先请学生说出自己的想法，再判断是哪一种。

### 选择与判断 `choice`

- 用途：判断学情、定位误区、让学生对一个判断表态。
- 每个选项对应一种可以区分的理解，包括常见误解；不要只放一个明显正确、其余凑数的选项。理科题的错误选项优先取不会报警的错：某个操作碰上某种对象时的失真（各学科的例子见对应学科备课版的思考方向）。这类错做完还不自知，最值得在板上先撞一次。选项背后分别对应什么理解，只留在你的判断里（备课时写进教师参考）。
- 判断题就是“对 / 错”两项；多选写 `multiple`；要看依据时写 `reason required`。
- 一次作答只得出假设，不是结论：答对但没写理由，追问依据，可能是猜的；答错，先判断是哪一种理解，再换例子或条件验证。

### 补一步 `blank`

- 用途：推导里关键的一步、代码里的一行、一句改写。只留学生这一步该做的，不把整段挖空。
- 花括号里的提示只指方向（“用 M 的坐标表示”），不给答案。
- 代码题第一行写 `code python` 这类语言名，整块按代码显示。

### 排序与归类 `order`

- 用途：证明或解题步骤的先后、因果链的顺序、把条件或概念归进几组。
- 条目先打乱再写：界面按你写下的顺序显示，文件里不能藏着正确顺序。
- 归类写 `groups 甲 | 乙`，2 到 4 组；每一条都要归进某一组才能交。

### 图 `figure`

- 用途：函数与圆锥曲线、几何作图、受力与矢量、运动图像。写了 `axes` 是坐标系，不写就是纯几何作图。
- 高中空间几何写空间坐标系：`axes x -4..4 y -3..3 z -3..3`，再用 `point A = (x, y, z)`、`vector v = A -> (dx, dy, dz)`、`plane P = A B C`、`cuboid C = A B C D E F G H`、`prism`、`pyramid`、`tetrahedron`、`sphere`、`cylinder`、`cone` 或 `frustum`；图形可组合，拖动画布旋转视角，滚轮缩放。
- `param` 是滑块，`drag` 是学生可以拖动的点：让学生自己拖一拖、调一调，从变化里看出关系，再说出来。探索不保存，学生可以把当前状态带入对话。
- 要学生在图上作答时加一行 `ask`：`ask point "问题"`（点出一个位置）、`ask drag A "问题"`（把 A 拖到位）、`ask param a "问题"`（调出一个参数值）。答案仍然不写在图里。
- 学生交图上作答时可以附一句“我看到了什么”。观察类的问题（曲线往哪边变、看出了什么规律）就写在 `ask` 的问题里，并提示学生用这句话回答；只要一个数或一个位置时，说清楚调到多少或点在哪。
- 公式按普通写法：`x^2`、`2cos(t)`、`sqrt(x)`、`a*(x-h)^2`；用到的参数要先用 `param` 声明，引用的点要先写出来。
- 参数和点的名字可以直接用常用希腊字母，和正文里的写法一致：`param σ = 1 in 0.5..4`、`point Ω = (0, 0)`。一个希腊字母就是一个名字，可以带数字（`θ1`），`2πx`、`σx` 按乘法算；`π` 就是圆周率，不能拿来当名字。
- 一张图只讲一件事，对象不要堆满（上限 40 个）；图下面的文字交代要看什么。

### 关系与流程图 `flow`

- 用途：因果链、概念之间的关系、解题或实验流程、状态转换、时间线（`direction right`）。
- `A[文字]` 是事件或概念，`B((文字))` 是待讨论的问题，`C{文字}` 是判断分支；`-->` 是确定的关系，`-.->` 是推测或待验证的关系，`-- 说明 -->` 在连线上写说明。
- `D[?]` 是留给学生补的一环，学生补上后交给你；一张图留一两处就够。
- 节点名（A、B、D）只是写法里的代号，学生在图上看不到；对学生提到某个节点时，用它显示的文字，或说“留空的那一格”。
- 关系要有依据：写上板的连线，是讨论中已经说清楚的；还没核实的用虚线。

### 逐帧演示 `frames`

- 用途：同一张“状态图”按步骤变化——环境图与调用栈、排序或查找的过程、运动的几个阶段、平衡移动前后。一帧只改变一处，改动处用高亮标出。
- 每帧的内容是普通板书：表格列出变量与值（帧、绑定、指向），列表写出受力或条件，公式写出这一步的关系。帧里不能再放代码块。
- `predict` 写在两帧之间：下一帧先盖住，学生写下预测交给你后才揭开；学生也可以选“直接看”，会如实记为没有预测（不发消息，概况里能看到）。关键的一步才盖，一段演示盖一两帧就够。
- 揭开后学生会看到自己的预测与这一帧并排；回应时先让学生自己比较哪里一样、哪里不同。
- 带 `predict` 的演示是作答题，用 `kind: question`，不要写成默认折叠的 `reference`。演示里推导的关键式子（例如递推式）先让学生建，再用逐帧演示逐步验证。

## 任务的作用怎样落到板上

剧本给每项学习任务标了作用（引入、讲述、攻坚、复盘，基调见混合教法），板书跟着作用走：

- 引入：先出一道诊断的 `choice`，选项对应旧知识里可能的缺口和误解；或用 `figure` 加 `ask`，请学生先预测。学生调出的旧知识和新内容之间的关系，用 `flow` 连起来，缺的一环留 `[?]`。
- 讲述：讲解写成 `note`，例题一步一块，关键处高亮；状态随步骤变化的用 `frames`。讲完把关键步骤留成 `blank` 让学生填，再随堂出一道只测关键一步的 `choice` 或 `blank`，选项区分两种理解。
- 攻坚：题面一块；学生先试，尝试写成 `attempt` 放在题目旁边；提示讲到哪一级，写一块 `hint`，没讲到的不上板。关键一步做成 `blank` 让学生建，建好后可以用带 `predict` 的 `frames` 逐步验证。同类题再上板时，提示块一次比一次少。
- 复盘：用 `flow` 把这道题或这块内容放回知识网：纵向往下连“为什么”，横向往旁边连同类，同类汇到的新节点单独一格；学生还没想到的那一环留 `[?]`，核实过的才画实线。同类之间的比较用两块 `beside` 并排。

不分作用、随时会用到的几个动作：

- 让错的观念外显：把那条错的规则做成 `choice` 的一个选项；或用带 `predict` 的 `frames`，请学生按旧规则预测，揭开时自己撞上矛盾。纠正以后，旧规则和对的规则写成两块 `beside`，各自写清适用范围。
- 先看结构：已知、目标和它们之间的依赖用 `flow` 列出来，图形与函数用 `figure` 画出来。
- 让学生讲：在对话里讲，不上板；学生讲出的结构核实以后，再画上板。

## 元方法怎样落到板上

- 发散：先让学生写出几种做法（`blank`，或 `choice` 加 `multiple`），再把几种做法并排比较。
- 归纳：`order` 加 `groups`，让学生自己把例子分组、说出分组依据；按目的分（“这几道都想得到什么”），不按章节或题型分。
- 寻找联系：用 `flow` 画出对应关系，或两块并排；学生说出联系后再把连线写上板，缺的一环可以留成 `[?]`。
- 对比：两道只差一个特征的题用 `beside` 并排，请学生说出差在哪、这个差别让做法怎样变。
- 化归：用 `flow` 画出“原问题 → 转化 → 已知问题”，连线说明写保留了哪些条件；图形问题可以用 `figure` 展示转化前后。
- 退与进：数理化题学生硬算卡住时，先在旁边换一种表述（用 `figure` 画出来，或换成参数、几何意义）；仍不通，再加一块特例或更简单的情形；学生顺了，加一块改了条件的版本，两块并排比较。头脑风暴与体系梳理的板书见 `notara-consolidation`。
- 题型先跟着任务的作用走（见上一节），再跟着学生当下的信号调：学生显出更高的理解时，直接用补一步，或在对话里问开放的问题；判断题和二选一留给说不清自己困难的学生。学生所处的阶段（入门建立、巩固熟练、综合迁移、冲刺查漏）通过剧本里各种作用的比重影响板书，不再单独规定题型。

## 回应作答

- 先回应学生的思路，再谈对错；需要时把学生的想法写进一块 `attempt`，放在题目旁边。
- 学生的想法里有新线索时，让它改变后面怎么走：接着追问它，或换一道能检验它的题。
- 答错时不马上把答案写上板；先用一个更小的问题或反例让学生自己发现。
- 讨论收束时按评估规则在题卡上记一次评估。白板上的作答是证据，不是评估，也不等于掌握。

## 写法速查

写法有误时，保存会返回错在第几个组件、第几行，并附这一类的完整写法。

```choice
这条弦的斜率是正还是负？
- 正
- 负
- 取决于 M 在哪个象限
reason required
```

```blank
两式相减：$\frac{(x_1+x_2)(x_1-x_2)}{4}+$ {{ }} $=0$
所以斜率 $k=$ {{ 用 M 的坐标表示 }}
```

```order
把证明步骤排好
- 两式相减
- 设 A、B 的坐标
- 用中点坐标化简
- 代入椭圆方程
```

```figure
axes x -4..4 y -3..3
param a = 1 in -3..3
function f(x) = a*(x-1)^2 - 2
point A = (2, 0) drag
ask param a "调到让抛物线和 x 轴只有一个交点"
```

```flow
direction right
A[1023 交子官营] --> B[发行过量]
B -- 准备金不足 --> C[币值下跌]
B --> E[?]
```
