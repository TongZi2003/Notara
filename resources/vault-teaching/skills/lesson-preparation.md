# 备课

用户明确要求按学习目标或资料备课时写剧本；普通对话可以直接开课，不需要先备课，也不为了开课生成占位剧本。没有教材也能备课：从目标出发设计本课任务与例子，已用资料、网络取回的正文和现场构造的内容都能用，但要在 `materials` 里写清来源，并区分原文与生成内容；只有链接不等于已经读到，版本、标准、数据这类事实先检索核对。

## 三类来源，各用各的

- 常驻规则：persona 与 base 里的原则——观察与掌握、先看学生、动态地教、白板、主动召回、学生可见输出。
- 按需 Skill：课型与学科做法按本次内容读对应的 `notara-subject-*` 入口（选择方式见 `notara-worker-orchestration`），资料整理读 `notara-material-outline`，备考课读 `notara-exam-prep`；不把它们的规范整段抄进本课剧本。
- 本课动态背景：本课目标、绑定剧本的目录、显式前课小结与画像线索由系统按预算注入，是导航不是正文；要用的材料、画像或方法要点的正文自己读。

## 先做学情判断

备课先看人，再看材料。按常驻规则的四问逐项形成判断，写在备课说明最前面；每一项都注明依据来自哪里，没有依据就写“未知”，不为填满栏目编造。

- 学生情况：从教学设置里的目标与期限、学情画像、近期课堂小结和本次对话中取。身份、目标、期限、每次可用时间、偏好与学习习惯只写已经知道的；不为填满模板追问与本课无关的个人信息。
- 能力推断：先按本课主题用 `notara-material-search` 查相关卡片的学生理解、方法要点与小结，再分三档写。已证实：学生在独立作答或解释中承担过关键认知工作，附出处。推断：写依据，以及什么表现会推翻它。未知：还没有任何可用证据。区分学生自述、独立表现、提示后完成和从未检查；看过、听过、做过同类题都不是证据，旧错要同时看后来的修正。推断要落到具体能力，例如“会用定义判断单调性，还没见过需要分段讨论的情形”，不写“基础一般”。
- 需求：分开写学生明说的要求和你据证据判断的实际缺口。两者一致就照做；不一致时先满足明确请求，再用一个小任务让学生自己看到缺口，不驳回请求，也不悄悄换题。例如学生要“多刷题”而错因集中在概念，就在刷题里安排能暴露概念问题的那一道。
- 阶段：按本课主题判断，四档决定课型与节奏。
  - 入门建立：第一次接触，或概念还不稳。讲清它解决什么问题、为什么需要，用最小例子、直观表示和学生自己的预测建立理解；检查能否用自己的话解释，并独立走出最基本的一步。
  - 巩固熟练：概念已建立但不稳定，会看不会做、易错或很慢。安排变式、辨析和基本功，逐步撤掉提示；检查不提示时的正确率，以及错误类型是否收敛。
  - 综合迁移：单点会做，换了情境或跨章节就不会选方法。安排不标方法名的混合任务、选路比较、知识联系与化归；检查面对陌生任务能否选对方法并说明理由。
  - 冲刺查漏：有明确的考试与期限。按考纲覆盖、真题或模考、错因分类和时间分配组织，细则读 `notara-exam-prep`；知识性缺口仍回到对应阶段补理解，不只教技巧。
- 核对计划：挑一两个最影响本课走向的推断，设计能区分不同情况的小判断或小任务放在开头（例如比较两张图、一道只差一个条件的题），写明结果不同时本课分别往哪走。不做成大套前测。

判断随课堂更新：课上出现与推断不符的表现就按实际调整，不为走完剧本坚持原判断。课后小结写清判断怎样被证实或修正；有长期价值的，再更新画像。

## 用元方法设计任务

每个学习任务都先回答：这一步让学生亲自完成哪种思维动作。按阶段取舍重点，一课不必四种齐全。

- 发散：让学生先预测、猜想，或提出几种可能的思路与解释，老师暂不评判。适合入门导入和综合课选路。发散打开之后，核实过的部分归纳固化，固化下来的结构成为下一次的起点；要专门发散一段时读 `notara-brainstorm`。
- 归纳：给两三个挑选过的具体例子，让学生自己提炼共性，再用一个反例或边界情形检查规律的条件。适合入门建立概念和巩固期整理方法。
- 寻找联系：让学生说清新内容与已学知识、另一种表示或另一个领域怎样相连、差别在哪。适合巩固后期与综合迁移；联系清楚后可以落到共性父节点和板书的知识面。
- 化归：让学生把新问题转成已解决的问题或已知模型，并检查转化是否等价、有没有丢条件。适合综合迁移和冲刺；反复有效的化归经验，按 `notara-method-distillation` 写成主题要点。

教师参考的“教学意图”写明本任务练哪一种、学生要亲自完成哪一步。递进提示先提示动作（“换个表示试试”“这几个例子哪里一样”），再提示内容。各学科怎样落地见对应学科关注 Skill。

## 写一份本课剧本

完成学情判断后再读备课材料，理清本课重点和可能的教学路径。剧本是普通 Markdown 资料，frontmatter 写 `type: lesson`，用 `write-batch` 保存到 `备课/`（见 `notara-vault-workflow`）；新建时先用 shell 读 `_templates/` 里的 `lesson.md`（备课页），旧版备课页已经占用了这个文件名时用 `lesson-script.md`（课堂剧本），两者同构。

- `##` 是公共阶段：学生能看到这一步要解决什么。按学生实际反应推进，不做成必须逐项执行的状态机，也不用自己编号——阶段 key 由 `lesson-outline` 派生。
- `###` 是具体学习任务：写清这一步要学生做什么、依据什么材料；题目类的任务仍保留完整题面。
- 教师参考就近放在对应内容后面，固定写法是 `<details data-notara="teacher">` 单独一行，接着 `<summary>教师参考</summary>` 单独一行，空行，Markdown 内容，空行，`</details>` 单独一行。开始与结束标签都必须单独成行，也不能放进代码块。
- 最前面的教师块写本课备课说明，顺序是：学生情况、能力推断、需求、阶段、目标、考试依据（仅备考课）、策略取舍（含本课主要练哪种元方法）、核对计划、检查点、涉及资料。世界书互动只在确实要用时写时机与用途，不注入整本世界书。
- 每个学习任务的教师块就近写：教学意图（含练哪种元方法）、递进提示（从最小提醒到接近答案），以及这项任务需要的教师参考——封闭题给完整解答（条件、推导、结论与适用条件），阅读与表达给依据、示例与评价标准，实验给条件、现象与解释，编程给参考实现、关键行为与测试；最后写诊断（答对、卡住、答错分别说明什么，下一步往哪走）。
- 默认学生内容不露答案：题面与公共阶段可以直接给学生看，完整解答、提示链和诊断只写在教师参考里；要给学生看时由你按学生当下的需要讲。

不全文复制无关材料；本课采用的题目必须完整保留原题条件、图形、选项和小问，任务不是题目时保留必要语境、数据与代码上下文，附真实文件与页段引用。原文有参考答案时保留并以其为依据，将原文答案与补充解法分清；疑似矛盾保留原文待核对。只结构化本课涉及的范围，题卡、知识卡与父节点的三段结构见 `notara-material-outline`，不能用来源索引替代正文。

没有剧本时，课堂根据当前的问题和目标直接推进。输入的讲义或题目是备课材料，这份剧本才是本次备课的产物；不能因为课堂引用了一份材料，就把本次小结追加到那份原始材料上。

## 读已绑定的剧本

准备按剧本授课时，先读“本课导览”中的备课说明，再读取当前要讲的阶段。导览提供本课取舍和相关经历入口，不需要一次读完所有题目的教师参考。

开课时注入的是阶段目录与绑定版本，不是正文。要讲哪一段先用 `lesson-outline` 取目录，再用 `lesson-section` 读那一段正文与它就近的教师参考；`section` 用目录返回的 key（`section-1`、`section-2`…，程序派生，不在 Markdown 里手写），`expectedRevision` 与 `path` 照抄目录返回的真实 `revision` 和 `readPath`，跨集时也一样。长阶段按 `nextOffset` 续读，只读当前要讲的阶段，还没用到的答案留到讲到时再读。目录默认 40 条、最多 100；正文按 Unicode 字符分页，默认 6000、最多 12000。目录返回的 `stale` 表示文件与绑定版本已不一致：先重新读取核对、重新绑定，再按当前版本继续。Bash 的用途写 `[notara:lesson-read]`，`path`、`section` 与 `expectedRevision` 照抄上一条命令的返回：

```sh
printf '%s' '{"path":"备课/迭代数列.md"}' | "$DSH_NOTARA_NODE" "$DSH_NOTARA_CLI" lesson-outline
printf '%s' '{"path":"来自目录的 readPath","section":"section-2","expectedRevision":"来自目录的 revision"}' | "$DSH_NOTARA_NODE" "$DSH_NOTARA_CLI" lesson-section
```

绑定只记真实路径与版本，不冻结全文。剧本被改动后，`lesson-section` 会要求重新绑定：先重新读取核对，再用 `set_teaching_settings` 的 `scriptPath` 重新绑定后继续，不拿旧目录当成新版本。

## 按需准备资产

备课需要可复用的题卡或知识卡时，按 `notara-material-outline` 确定范围与清单：一张卡对应一个完整语义单元，题目交 `problem`，知识单元交 `general`，都由工作员在独立上下文完成研究与自检。不要先在主课堂解完整批题再交给工作员排版，也不为了每节课强制先拆书；已有核验产物直接复用。交给课时备课员完善课时时，附上你的学情判断（证据档次、未知项与阶段），不传完整个人历史。预设选择、材料交接与写回按 `notara-worker-orchestration`，`ask_worker` 的字段以工具 schema 为准，不自己造参数。

没有教材时按目标设计本课任务与例子，生成内容与真实来源分开标清；需要版本、标准、数据这类外部证据时先检索核对。编程或可执行任务的参考实现与测试由工作员设计，实际运行由你用 Bash 在任务临时目录执行；先用参考实现和典型错误实现核对测试，保留实际输入、输出和结论。缺少运行环境时标为“未运行”，不声称通过，不自动安装系统依赖，也不给工作员开放 Bash。

模型尚未配置时保留清单并说明需要在教室接入后台模型，停止批量研究，不在主课堂悄悄接管；用户明确选择由老师自行研究时才改变分工，并如实标明没有独立研究或审阅。缺材料先补关键的原文、原答案或代码上下文，不猜题；不要重复调用仍然不可用的配置。

工作员使用独立模型与生成预算，用户在教室设置中管理，你不在课内改动。上限是允许使用的空间，不是要求耗尽，也不保证正确。预算耗尽时没有可用的完整结果：缩小到一个单元或一个疑点后再继续，不原样重试、不把截断内容保存为完整答案，不自行提高用户预算或换模型。材料解析失败则按错误标明的字段修正，JSON 内的引号/反斜杠正确转义，不通过删除原文内容来规避。

交付完整原文、原文参考答案（若有）、必要先修与本次产物要求；PDF 原页通过 `sources` 照抄 `pdf-page` 返回的 embed，Host 验证 revision 后把原图交给工作员，网页正文、代码与实验记录用 `materials` 交接。工作员不继承父历史；仅交付材料模式必须附正文，启用读取模式可交接实际资料位置与范围。区分“原文参考答案”“学生实际作答”“已有分析”，不要把老师猜的答案伪装成原解。

返回后检查覆盖范围、证据与结论的一致性、来源和三段结构；不在主线程重新展开已完成的全部研究，有疑点精确退回该单元或交 `review`。批量保存用一次 `write-batch`、回读用 shell（`sed -n`／`rg`），服从原生沙箱与审批，不额外再派排版工作员。记录清单里每个单元的完成、待核对、缺材料与未完成状态，失败或预算耗尽不能标成核验通过。

## 保存与绑定

剧本用 `write-batch` 写到 `备课/`，frontmatter 写 `type: lesson`；目录、模板与复习字段规范见 `notara-vault-workflow`。用户明确这就是本课的剧本时，用 `set_teaching_settings` 的 `scriptPath` 指到实际保存的路径绑定本课（相对 vault，或已注册外集的绝对路径），`null` 解除绑定；为以后准备的课不要误绑当前会话。路线课程把剧本的真实路径写进 `create-route` 的 `scriptPath`，开课时由 Host 绑定具体版本。仅查看一份备课页不改变当前绑定。

## 课后

课堂小结沿已有机制：小结保存就是教学上的归档，默认保留原会话继续聊天；学生明确要把会话从列表收起时才传 `archive: true`。续课入口用 `## 下次从这里继续` 标题。有剧本时用 `save_lesson_summary` 把小结追加到原剧本文末，保留备课内容与其他课堂的小结，不覆盖也不重写；没有剧本时生成独立小结资料。不要把本次小结写到课堂引用的原始材料上。

小结保留本课有证据的理解变化：曾经怎样理解、哪里不完备或出错、哪些提示或反例促成改变、后来实际表现及仍未解决处；没有发生的环节不补。关联卡片已有学生理解时按 `notara-method-distillation` 补充演变，课堂小结给必要概括和真实引用；完整的认知历史在卡片里。保存小结时，列出本课值得下次想起的方法要点候选，按 `notara-method-distillation` 交学生采用。同一课堂的小结再次保存会更新它自己的段落，先读旧小结并保留仍成立的关键经历，不能只交新增一句而丢失前半课过程。

沉淀哪些经历、什么时候才值得改固定 Skill，见 `notara-method-distillation`；一课动态 brief 与工作员的自评都不能直接变成通用教法。
