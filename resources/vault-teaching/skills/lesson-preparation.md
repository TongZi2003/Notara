# 备课

用户明确要求按学习目标或资料备课时写剧本；普通对话可以直接开课，不需要先备课，也不为了开课生成占位剧本。没有教材也能备课：从目标出发设计本课任务与例子，已用资料、网络取回的正文和现场构造的内容都能用，但要在 `materials` 里写清来源，并区分原文与生成内容；只有链接不等于已经读到，版本、标准、数据这类事实先检索核对。

## 三层，不要重复

- 常驻规则：persona 与 base 里的原则——观察与掌握、教学动作、主动召回、学生可见输出边界。
- 按需 Skill：课型与学科做法按本次内容读对应的 `notara-subject-*` 入口（选择方式见 `notara-worker-orchestration`），资料整理读 `notara-material-outline`；不把它们的规范整段抄进本课剧本。
- 本课动态背景：本课目标、绑定剧本的目录、显式前课小结与画像线索由系统按预算注入，是导航不是正文；要用的材料、画像或锦囊正文自己读。

## 写一份本课剧本

先读备课材料、相关画像与锦囊，理清本课重点和可能的教学路径。剧本是普通 Markdown 资料，frontmatter 写 `type: lesson`，保存到 `备课/` 并走原生批准；新建时先读 `_templates/` 里的 `lesson.md`（备课页），旧版备课页已经占用了这个文件名时用 `lesson-script.md`（课堂剧本），两者同构。

- `##` 是公共阶段：学生能看到这一步要解决什么。按学生实际反应推进，不做成必须逐项执行的状态机，也不用自己编号——阶段 key 由 `lesson-outline` 派生。
- `###` 是具体学习任务：写清这一步要学生做什么、依据什么材料；题目类的任务仍保留完整题面。
- 教师参考就近放在对应内容后面，固定写法是 `<details data-notara="teacher">` 单独一行，接着 `<summary>教师参考</summary>` 单独一行，空行，Markdown 内容，空行，`</details>` 单独一行。开始与结束标签都必须单独成行，也不能放进代码块。
- 最前面的教师块写本课备课说明：目标、相关画像与锦囊证据及不确定点、策略取舍、检查点、涉及资料；世界书互动只在确实要用时写时机与用途，不注入整本世界书。
- 每个学习任务的教师块就近写：教学意图、递进提示（从最小提醒到接近答案），以及这项任务需要的教师参考——封闭题给完整解答（条件、推导、结论与适用条件），阅读与表达给依据、示例与评价标准，实验给条件、现象与解释，编程给参考实现、关键行为与测试；最后写诊断（答对、卡住、答错分别说明什么，下一步往哪走）。
- 默认学生内容不露答案：题面与公共阶段可以直接给学生看，完整解答、提示链和诊断只写在教师参考里；要给学生看时由你按学生当下的需要讲。

不全文复制无关材料；本课采用的题目必须完整保留原题条件、图形、选项和小问，任务不是题目时保留必要语境、数据与代码上下文，附真实文件与页段引用。原文有参考答案时保留并以其为依据，将原文答案与补充解法分清；疑似矛盾保留原文待核对。只结构化本课涉及的范围，题卡、知识卡与父节点的三段结构见 `notara-material-outline`，不能用来源索引替代正文。

没有剧本时，课堂根据当前的问题和目标直接推进。输入的讲义或题目是备课材料，这份剧本才是本次备课的产物；不能因为课堂引用了一份材料，就把本次小结追加到那份原始材料上。

## 读已绑定的剧本

准备按剧本授课时，先读“本课导览”中的备课说明，再读取当前要讲的阶段。导览提供本课取舍和相关经历入口，不需要一次读完所有题目的教师参考。

开课时注入的是阶段目录与绑定版本，不是正文。要讲哪一段先用 `lesson-outline` 取目录，再用 `lesson-section` 读那一段正文与它就近的教师参考；`section` 用目录返回的 key（`section-1`、`section-2`…，程序派生，不在 Markdown 里手写），`expectedRevision` 与 `path` 照抄目录返回的真实 `revision` 和 `readPath`，跨集时也一样。长阶段按 `nextOffset` 续读，不把整本剧本塞进上下文，也不跨阶段预读还没用到的答案。命令与分页上限见 `notara-vault-workflow`。

绑定只记真实路径与版本，不冻结全文。剧本被改动后，`lesson-section` 会要求重新绑定：先重新读取核对，再用 `set_teaching_settings` 的 `scriptPath` 重新绑定后继续，不拿旧目录当成新版本。

## 按需准备资产

备课需要可复用的题卡或知识卡时，按 `notara-material-outline` 确定范围与清单：一张卡对应一个完整语义单元，题目交 `problem`，知识单元交 `general`，都由工作员在独立上下文完成研究与自检。不要先在主课堂解完整批题再交给工作员排版，也不为了每节课强制先拆书；已有核验产物直接复用。预设选择、材料交接与写回按 `notara-worker-orchestration`，`ask_worker` 的字段以工具 schema 为准，不自己造参数。

没有教材时按目标设计本课任务与例子，生成内容与真实来源分开标清；需要版本、标准、数据这类外部证据时先检索核对。编程或可执行任务的参考实现与测试由工作员设计，实际运行由你通过原生工具在任务临时目录执行；先用参考实现和典型错误实现核对测试，保留实际输入、输出和结论。缺少运行环境时标为“未运行”，不声称通过，不自动安装系统依赖，也不给工作员开放 Bash。

模型尚未配置时保留清单并说明需要在教室接入后台模型，停止批量研究，不在主课堂悄悄接管；用户明确选择由老师自行研究时才改变分工，并如实标明没有独立研究或审阅。缺材料先补关键的原文、原答案或代码上下文，不猜题；不要重复调用仍然不可用的配置。

工作员使用独立模型与生成预算，用户在教室设置中管理，你不在课内改动。上限是允许使用的空间，不是要求耗尽，也不保证正确。预算耗尽时没有可用的完整结果：缩小到一个单元或一个疑点后再继续，不原样重试、不把截断内容保存为完整答案，不自行提高用户预算或换模型。材料解析失败则按错误标明的字段修正，JSON 内的引号/反斜杠正确转义，不通过删除原文内容来规避。

交付完整原文、原文参考答案（若有）、必要先修与本次产物要求；PDF 原页通过 `sources` 照抄 `pdf-page` 返回的 embed，Host 验证 revision 后把原图交给工作员，网页正文、代码与实验记录用 `materials` 交接。工作员不继承父历史；仅交付材料模式必须附正文，启用读取模式可交接实际资料位置与范围。区分“原文参考答案”“学生实际作答”“已有分析”，不要把老师猜的答案伪装成原解。

返回后检查覆盖范围、证据与结论的一致性、来源和三段结构；不在主线程重新展开已完成的全部研究，有疑点精确退回该单元或交 `review`。批量保存与回读可用原生文件工具或一次 Bash 处理当前已核验的小批草稿，保留原生审批，不额外再派排版工作员。记录清单里每个单元的完成、待核对、缺材料与未完成状态，失败或预算耗尽不能标成核验通过。

## 保存与绑定

剧本用原生 write / edit 写到 `备课/`，frontmatter 写 `type: lesson`，并走原生批准；目录、模板与复习字段规范见 `notara-vault-workflow`。用户明确这就是本课的剧本时，用 `set_teaching_settings` 的 `scriptPath` 指到实际保存的路径绑定本课（相对 vault，或已注册外集的绝对路径），`null` 解除绑定；为以后准备的课不要误绑当前会话。路线课程把剧本的真实路径写进 `create-route` 的 `scriptPath`，开课时由 Host 绑定具体版本。仅查看一份备课页不改变当前绑定。

## 课后

课堂小结沿已有机制：有剧本时用 `save_lesson_summary` 把小结追加到原剧本文末，保留备课内容与其他课堂的小结，不覆盖也不重写；没有剧本时生成独立小结资料。不要把本次小结写到课堂引用的原始材料上。

小结保留本课有证据的理解变化：曾经怎样理解、哪里不完备或出错、哪些提示或反例促成改变、后来实际表现及仍未解决处；没有发生的环节不补。关联卡片已有学生理解时按 `notara-method-distillation` 补充演变，课堂小结给必要概括和真实引用，不把最终正确结论覆盖过去，也不将小结当成全部认知历史。同一课堂的小结再次保存会更新它自己的段落，先读旧小结并保留仍成立的关键经历，不能只交新增一句而丢失前半课过程。

沉淀哪些经历、什么时候才值得改固定 Skill，见 `notara-method-distillation`；一课动态 brief 与工作员的自评都不能直接变成通用教法。
