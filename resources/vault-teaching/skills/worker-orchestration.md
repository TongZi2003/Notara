# 工作员编排

需要把一次独立研究或核验交出去时读这份规范。工作员在独立上下文运行，不继承本课历史；从材料到产物都由你交接与收口，它的能力与预算同样受教室设置约束。五个预设是分工选项，不是必须按序跑完的流水线：只派这次真正需要的一项，有疑点才用 `review`。

## 从哪条入口进入

- 独立拆书：用户给了章节、题目或资料范围就按范围做，不重复追问；先略读结构，列语义单元清单，再按单元交 `problem` 或 `general`。清单含语义单元、真实来源范围、预期产物与处理状态。
- 目标驱动课程编排：没有教材也能开始。先由你定目标、先修、阶段与检查点，再逐课用 `lesson` 完善；需要可复用卡片时按需调用拆书，已有核验产物直接复用，不为每节课强制先拆书。

## 选哪个 preset

- `problem`（题目研究员）：一道完整题及其关联小问的研究或题卡，交付完整题卡草稿。
- `general`（通用工作员）：一个有边界的知识单元或资料任务。知识型课本的主要工作员，独立研究概念、原理、文本、实验或代码单元，交付有解释依据的完整知识卡；纯检索任务交证据报告，不硬造卡片。不承担课程总框架与整书归纳。
  自然语言找卡片时按 `notara-material-search` 交接查询意图、线索和范围；启用 read 工具配置后可独立检索，没有读取工具时只能分析显式材料。近期复盘或教学反思也可交一项局部证据整理，最终判断和写回仍归主教师。
- `lesson`（课时备课员）：按你给的课时框架完善一份剧本草稿，交回公共阶段与就近教师参考。框架由你定。
- `exercise`（出题员）：根据来源题目或知识点出小测与结构性变式，先自解核验，交回题面与折叠教师参考，区分原题/改编题/新题。
- `review`（核验员）：只核验具体疑点或高风险条目，给出“结论—依据—最小修改”，不当作通用流水线跑。

任务不匹配时不要硬套：一次只派一件有边界的事，不并发派发多个工作员。当前每课堂同时只有一个后台任务，已经有一个在跑时等它返回或先处理它，不循环重试。

## 每次交接

参数：`preset`、`goal`，以及按需的 `focus`、`materials`、`sources`、`skills`；字段名与限制以工具 schema 为准，不自己造参数或包装层。

涉及学科内容的研究、备课、出题与核验，先从索引读相关学科 Skill，把本次取舍写进 `focus`，每次交接显式传对应 `skills`。通常选一个主要学科，跨学科才增加相关入口；具体学科与其兜底入口不默认叠加。纯目录查找等不涉及学科判断的任务可以不选。已读取且仍在上下文中的正文不机械重读，任务变化时重新判断；工作员不会继承你已读过的内容。

- `goal` 写清这次要什么产物、在总任务里起什么作用；`focus` 只写本次要核验或突破的那一处。
- `materials` 是 `{title, text}` 列表，保留必要正文；网页正文、代码与实验记录也走这里，并写清来源。区分“原文参考答案”“学生实际作答”“已有分析”，不要把猜的答案伪装成原解。工作员不继承父历史；仅交付材料模式必须附正文，启用读取模式时可交接真实资料位置和范围，由工作员实际读取，不能把给了路径当作读过。
- 诊断交接把当前作答与相关历史分开标注；历史包含原情境、实际先后、提示程度及后续修正，不能只摘错误句子。用户补充的信息只交给相关任务，返回结论仍由你综合核对；历史模式与原因假设不冒充当前事实。当前一次一个后台任务的限制仍有效。
- `sources` 只照抄 `pdf-page` 返回的 PDF embed（带真实页码、区域与 revision），Host 按版本核对后把原页图像交给工作员。每次最多 4 处，只选本次知识单元、题目或原解的必要页段；跨页或图文分离要带齐相关页段，超出时按有意义的研究任务分批。工作员不联网，也不渲染 PDF：只有链接不算交接证据。
- `skills` 只填资源索引里已公布的教法（`notara-socratic` 等）与学科入口（`notara-subject-*`），至多 4 个，没有需要就不传；ID 从索引取，不自己拼。工作流 Skill 会被拒绝，不要注入。学科选择只改变判断重点，不授予资料或学情读取权限，也不扩大工具、模型与预算。当前任务的学科线索与实际内容冲突时以实际内容为准。

## 研究顺序

- 拆书与资料整理：先略读整本资料，范围尚不明确时问清章节范围，已明确就直接沿用；列清单后按单元交付完整题卡或知识卡，不先在主课堂解完整批研究。主教师轻量审阅，最后集中归纳一次父节点。
- 备课：先由主教师定课时框架，再逐课用 `lesson` 完善，最后主教师处理课与课之间的衔接。
- 出题：用 `exercise` 出小测与结构性变式，先自解核验；编程与可执行任务由工作员交参考实现与测试设计，实际运行由主教师执行，未运行就标明未运行。
- 清单持续记录已完成、待核对、缺材料和未完成项及对应产物位置。返工只交接相关产物、必要原文与具体反馈；失败不会清空已完成工作，也不能把“待核对”在课程摘要里改成确定结论。

## 核对与写回

- 工作员返回的是给你的分析或草稿。先检查覆盖范围、证据与结论的一致性、来源和三段结构，再结合学生当下思路组织讲练；不在主线程重复展开已完成的全部研究，有疑点精确退回该单元。
- 工作员没有写入、Bash、联网与嵌套委派能力；联网取材与编程/命令执行由你完成。正式写回也由你负责：按原生 `write` / `edit` 保存并走原生批准，批量保存与回读可用原生工具或一次 Bash 处理当前已核验的小批草稿。保存前保留旧卡的学生理解与复习记录，不整批覆盖成空白模板。
- 工作员使用独立模型与生成预算，在教室设置中管理；你不从课内改预算或换模型。预算耗尽时缩小到一个单元或一个疑点后再继续，不原样重试、不把截断内容保存为完整答案。模型未接入、失败或被取消时如实说明尚未取得分析，不声称已经核验，也不换别的入口绕过配置。
- 读取成功、文件存在和工具返回成功都不等于内容正确；工作员的“未发现问题”只供参考，教学质量的裁决权在你。
