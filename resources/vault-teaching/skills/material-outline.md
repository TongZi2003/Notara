# 整理资料与讲义

这是书籍拆解与资料整理的入口。先略读目录、代表内容和答案位置，再确定本次范围与用途。动手前把单元清单和规模、花费一起告诉学生：页数、预计卡数、是否派工作员、大致用时，等学生确认后再开始；学生已经给出章节、题目或整本书范围也要这样确认，因为学生未必知道这件事要花多少。确认后按这个范围做，不再反复追问。独立拆书按用户范围进行，备课只处理本课需要的部分。PDF 按知识结构与题目分批处理，不按页文字层批量拆卡。

根据实际内容从 Skill 索引选择并读相关学科的技能，确定本次重点：学科有备课与拆书版（`notara-subject-*-prep`）时读它，没有就读学科关注；交给工作员时通过 `skills` 显式传入对应 ID，具体交接见 `notara-worker-orchestration`。

## 先核对已有卡片

列单元清单之前，先用 `source-cards` 查这份资料已经拆出了哪些卡：传资料页或原件的路径，资料页会连同它嵌入的 PDF 一起查。已有卡片以引用为准，按 PDF 页码、视频时间段或资料页锚点看每处有哪些卡、哪些页还没有卡；文件名不是依据，阅读器建的区域卡、学生改过名的卡都不一定带编号。

- 一页有卡不等于这页每道题都有卡：区域卡按选区对应，整页引用的卡读标题或题干对上具体题目。
- `materials` 列出引用这份资料的专题与源目录，其中 `uncitedCards` 是它们名下没带这份资料出处的卡，读正文核对是不是本批的内容；还不确定时，用题干里有辨识度的一句在正文里 `rg` 补查。
- 清单只列真正的空缺。已有卡要补内容时写“补充”，不写“新建”，原卡的学生理解和复习记录保留。
- 同一题已有两张卡时列给学生决定，不建第三张，也不自己合并。
- `otherRevision` 是按旧版原件引用的卡：仍算已有，不当空缺；旧坐标不当作新版位置，用到时重新核对。
- 给学生的清单里说明已有多少、这次只补哪些。

## 先核对原页

- `pdf-page` 按 `path` 与 `page` 读一页（可选归一化 `rect` 取一块），返回 `text`、`pageCount`、真实 `revision`、直接提供给模型的原页 image，以及确定的 `locator` 与 `embed`；它的 `revision` 只用来核对与引用。
- 有公式、图形或表格的页面先用 `pdf-page` 取页，直接核对工具结果中的页面图像；文字层只用来找位置，不当准确转写。
- 需要引用时就照抄 `pdf-page` 返回的 `embed`（它带真实页码、区域与 `revision`），不自己拼坐标、版本或按页码推算位置。页码写物理页。
- 工作员要核对原题或原文答案时，把返回的 `embed` 照抄进 `ask_worker.sources`（最多 4 处，只选本次题目及原解），Host 按版本核对后传原页图像；文字材料和卡片正文用 `materials` 交接。
- 卡片按题目或知识结构组织，保留原页或区域引用后再写核实过的内容；逐页的文字层只用来找位置。阅读器创建的区域引用卡保留 PDF 原版图像和定位，图层与批注由阅读器维护在 `.notara/pdf-annotations/`；用户或阅读器给了带标注的 locator 就沿用。原 PDF 版本变了，先核对原文位置再引用。
- 只用到整页内容时先引用整页；确实要引用某一块时，先看整页图选范围，再用归一化 `rect`（0..1，左上原点）请 `pdf-page` 裁切，看过裁切图确认内容后再用返回的 `embed` 写进资料。
- 批注只在用户或阅读器真的带进来 locator 时沿用它；没有标注 ID 就引用整页或区域，不编造标注身份。原 PDF 改版后旧坐标不能当作新位置，重新核对再引用。

## 语义单元

按实际内容决定拆分方式：知识型课本以知识单元独立研究为主线，题目型资料以一道题为单位，实验、代码示例与文本任务各自保留能理解它的完整上下文，不预定必须拆多少张。

- 题卡原则上一题一卡，这是最小的具体事实；同一道题的多种解法属于同一张卡，相互依赖的小问与跨页内容保留完整。没有题目的知识卡围绕一个知识点，不硬凑例题。
- 不把三道不同题合成“综合训练”一张卡。清单包含语义单元、真实来源范围、预期产物与处理状态；先列本次范围内的清单与页段，再逐单元核对、研究和保存，完成时核对是否遗漏。
- 按内容选交接对象，都由工作员在独立上下文完成研究与自检，你做轻量审阅与保存；不要先在主课堂解完整批题再交给工作员排版。先确认范围和页段清单，传本单元所需原文、原答案与必要原页即可，已核验同题复用。清单里互不依赖的单元可以用后台工作员并行处理，每课堂同时最多 5 个，分批派；各单元返回后逐个审阅，再用一次 `write-batch` 保存这一批。交接与写回按 `notara-worker-orchestration`。
  - 题目：一道完整题及关联小问交 `ask_worker` 的 `problem`，交付可保存的完整题卡。
  - 知识单元：概念、原理、文本、实验或代码机制交 `general` 独立研究，交付包含动机、定义与条件、先修、解释或推导、例证与边界的完整知识卡，不降为摘录或摘要。

## 卡片正文

页头 `tags` 使用简短知识与结构标签。需要独立学习与复习的题卡、知识卡用 `type: card`，按模板保留复习字段；目录节点和共性专题用下文的 `source/topic`。工作员的卡片合同已在它的共同规则中注入，你审阅和写回时守住以下事实：

- `## 内容` 保留完整可检索的原文或语义单元、实际条件、全部选项、小问与必要语境，必需图形随内容保留，公式用 LaTeX `$...$` / `$$...$$`；正文要能独立阅读并按内容检索，不能只写“第某题”“见原页”或用图片代替可转写的文字。来源 embed 放在附近用于回原页核对，索引不能替代正文；有原文参考答案时折叠保留、注明出处，题面与答案不混写。
- `## 参考理解` 给有依据的解释、可检查的推导、方法比较与适用边界；原文答案是参考依据，模型新增内容另标“补充解法”“独立求解”，不冒充原解。判断哪些内容不能丢、怎样算成立按本次选定的学科 Skill，而不是通用层的固定清单。最后的常见错法按 `notara-vault-workflow` 核对：预判要具体到机制和区分追问，笼统的“注意计算”不算；常见错法空着或只有笼统一条时，看是否按找坑步骤对照过原解和错误选项。
- `## 学生理解` 按 `notara-method-distillation` 的“学生理解：保留认知演变”写；拆书时还没有学生的实际表达，这一节留空。

区域引用暂未转写时明确“原题待核对转写”，不宣称完整题卡已经生成。若发现原文参考答案疑似错误，保留原文，在参考理解中列出具体矛盾并标“待核对”，不静默改题目、改答案或把推测说成勘误。

## 父节点归纳

同类内容挂在一个已有或新建的 `type: topic` 父节点下，子卡的 `parent` 指向该节点的真实 Vault 相对路径；父节点是共性解释，不加入叶子题卡的复习周期。不新造容器类型。同类不是只看标题像，要比较对象、条件、关键关系与触发条件。本批完成后集中归纳一次共性与子卡链接，避免每处理一个单元就重新总结全讲义。

父节点同样是“内容、参考理解、学生理解”：内容写这类内容的共同结构并列出真实子卡链接；参考理解解释识别线索、共同方法、先修条件、变式差异和失效边界，知识型课本还要说明概念之间的依赖与区别、它们共同回答的问题；学生理解记录学生逐步形成的实际认识。具体原文仍保存在每张卡，不挪到父节点后让叶子只剩索引。先复用能表达同一共性的父节点，避免重复专题；原书目录树与理解上的知识树分别保留。

## 保存前后核对

对照原图与材料检查转写与结论是否走样：原文、条件、数据、语境和代码要与来源一致，结论要与证据相容。特别检查“结论与推导或证据相反”“参考答案正确但论证有误”“为了匹配答案改了原题”的情况。具体核对哪些量、依据什么判断按本次选定的学科 Skill；不用某一种检查（如数值代回）当成通用证明。

保存后按本批清单回读实际文件，核对三个部分、可检索题干、原文答案与补充的区分、LaTeX、parent/子卡链接和来源页段；可批量回读，不为每个检查都启动一轮长推理。高风险疑点按需交给 `review` 工作员，附带实际正文、必要原页与明确核验点，不只交付计划，不默认审阅整批所有题。旧卡修改前保留学生理解和复习记录，不能整批覆盖成空白新模板。完成说明区分保存、研究、自检与独立审阅；审阅失败或预算耗尽不能标为通过，读取成功不等于解题正确。

## 资料节点

- `type: source` 对应原书本身：一节或一章一个节点，写清自己的页码范围，用 embeds 带上真实 PDF 页，`parent` 指向它这一层之上的节点（上一级章节或原书），留空表示直接挂在原书下。
- `type: topic` 是教学专题或同类题的共性父节点，可以来自同一本或跨书资料：用引用指向真实存在的 source 或具体页段，正文写清引用了什么；专题的 `parent` 只挂专题，不能让它看起来像原书的目录。
- 两种资料都是普通 Markdown，没有卡片复习字段，复习生命周期只属于 `type: card`；它们都可以挂子卡片，但自己不计入卡片。
- 已有节点能表达同一内容时复用并补充它，不新建平行条目。整理结果保留来源与版本，学生之后要能回到原件核对。

## 整理成讲义

要把已核对的内容整理成可编辑的 Markdown 讲义时用这一节。

先精读选定资料、已有卡片或本课实际讨论，确认讲义的用途和范围。组织为问题主线、必要概念、解释与例子、练习和来源。忠实保留原文的条件、语境、数据、代码与来源，不用通用知识填充尚未核对的材料内容；具体哪些内容不能丢、怎样算准确按本次选定的学科 Skill 判断。

先在对话中给出可审阅的讲义正文；学生明确要保存为讲义或教材章节时，用 `write-batch` 写入当前学习集的资料（新建用 `op: "create"`，追加或替换用 `op: "edit"`，见 `notara-vault-workflow`）。保存成功后按逐文件回执确认真实路径；需要再改时先用 `vault_read` 重读同一份资料再追加新内容，`oldText` 已不匹配就重新读取当前内容再改，保留学生已有编辑，不创建第二份正文或另一条创作线。

每完成一个连贯内容单元就保存一次；保存本身不表示掌握，也不表示结束。学生可在资料页直接编辑同一份 Markdown，AI 与学生共用同一个资料身份；刷新或重开后继续编辑并回到课堂。

引用保留原文版本和准确位置；一份讲义可以串联多份资料，不能伪称整本书已经教过。
