# 规划与调整学习路线

用户要求系统学习、专题训练、复习安排或修改已有路线时使用。产物是一份能解释教学取舍并能开课的路线；仅讨论一道题时不强行创建路线。普通课无需先做全面诊断，没有教材也能从目标开始规划。学科关注按本次内容读对应的 `notara-subject-*` 入口，选取方式见 `notara-worker-orchestration`；文件与命令操作读 `notara-vault-workflow`。

学生仍在选择“接下来重点学什么”时先用 `notara-learning-review` 给有依据的少量方向；已有明确方向就直接规划，不机械多跑一次复盘。

## 先确定规划依据

目标要写成学生能够独立完成的任务，同时说明深度与不包含的范围。查看已经明确的学习时间、截止日期、资料和偏好；能从上下文得到的不重问。只有目标、范围或时间会实质改变方案时才补问，未知信息保留未知，不擅自许诺天数或通过率。

先读资料目录和相关片段，结合当前学习集内的画像、方法要点与近期课堂小结。区别学生自述、独立表现、提示后完成和没有检查；材料中的解答不是学生作答。缺少关键基础证据时安排少量针对性检查，不能用一题决定整个人的水平。学生明确要求全面诊断时才按约定完成那个过程。

涉及旧错误或反复障碍时，按 `notara-material-search` 读取相关卡片的学生理解及后续变化，同时考虑已经改善和不支持该判断的表现。补练依据当前可支持的困难，不能只凭历史错误标签安排重复补课；画像概括需能回到真实演变证据。

规划前按常驻规则的四问形成判断，写进课程总述的“起点依据与未知项”：学生情况、能力推断的证据档次、明确需求与实际缺口，以及各主题所处的阶段。四档的含义与课型见 `notara-lesson-preparation`「先做学情判断」。阶段按主题分，决定路线在这一段的形状：入门建立的部分节点小，先建立概念再练；巩固熟练的部分以变式和辨析为主；综合迁移的部分安排混合任务与跨主题联系；冲刺查漏的部分按考纲与真题组织。学生会随课程前进换档，路线里写明换档要看到的表现，不按日期自动换档。

目标是一场具体考试（高考、高考模考、考研、公务员考试等）时，先读 `notara-exam-prep`：确认考试身份，按考纲与真题取证，再定主线；考点覆盖表是路线的一部分，不另建一份计划。

## 组织主线

先写课程总述：终点、起点依据与未知项、范围和时间约束、阶段主线、最终如何检查。结构化时只增加必要的关系，不把教材目录直接变成课程，也不为显得全面罗列无限知识点。按书学习时尊重书的范围，跨书取材要说明选择依据。

每个课堂节点的 brief 用普通 Markdown 写成一份规划：

- 公开内容：这节课能做什么、采用哪些材料、会经历什么任务或练习。
- 就近 `<details>` 教师内容：为什么安排在这里；代表题及它暴露的困难；基础练习、变式和独立迁移如何递进；观察哪些真实表现决定继续、补练、压缩或拓展。格式与 notara-lesson-preparation 相同。
- 远期节点可以简短，但必须有目标、先修依据和检查任务类型；近期节点应有可核对的代表任务。完整讲解留给按需备课，规划时不一次写完全部剧本。
- 学生需要练会选择方法：学习工具后安排不标方法名的混合任务，逐步撤掉提示，并在后续情境再次用到同一能力。不是多刷几个表面同类题就称为迁移。

stage 是阶段名称；pathway 为主线、条件补练或拓展；prerequisites 说明知识先修，parent 说明课序接续。补练和拓展的具体触发条件写在 brief，不能因为一次卡住或只是读完就自动分流；也不把先修列表当锁课条件。阶段本身不是课堂，不生成空会话。

上述 parent/prerequisites 是文件读侧字段。创建请求使用 parentIndex/prerequisiteIndexes，局部修订使用 parentId/prerequisiteIds；以命令 --help 为准，不把读侧字段直接塞进写入参数。

一个节点的建议学习量以实际任务为依据，允许结合课堂表现拆开或合并尚未开展的节点。没有时间预算时先安排先后，不填虚构日期。复习使用已有记录与调度，不另建掌握分数。

## 规划自查与协作

提交前检查：目标是否都有任务覆盖；节点是否缺前置或跨度过大；是否重复取材；代表题是否正确且来源可核对；训练是否从辅助走向独立；检查点是否真的区分理解与跟随；补练和拓展是否有证据触发；负担是否符合用户时间；未知项是否仍如实存在。

普通路线自己完成。复杂路线按需把具体疑点交给 `review` 工作员、把局部资料与证据整理交给 `general` 工作员：显式给目标、相关学情证据、资料摘要、候选路线和要检查的问题，不传完整个人历史。审阅结果只供主教师参考；自己核对并裁决，不把后台“未发现问题”当成教学质量通过。

## 保存与开课

路线文件本身是一份 Markdown：机器身份、关系、阶段、主线/分支写在 frontmatter 的 `lessons`，各课规划只在稳定标记的正文块里保存一次。用到的命令（字段以各命令的 `--help` 为准，调用方式见 `notara-vault-workflow`）：

- `create-route`：新建路线。overview 写课程总述，brief 写各课规划；stage 分组，pathway 分主线、条件补练与拓展，prerequisiteIndexes 表示知识先修。默认主线接上一主线，分支写明 parentIndex；已写好的剧本用 scriptPath 指真实文件。
- `route-outline`：读取节点身份、阶段、主线/分支、先修与真实 revision（不含规划正文）。默认 40 个节点，`nextOffset` 非空时接着读；局部修订用它给的 revision。
- `revise-route`：按真实课堂依据局部调整。传 path、expectedRevision、reason 以及 updates/additions；省略的字段保持原样，允许的 null 清除，[] 清空数组。改某节课的规划就在 updates 里传 brief。已开展的课堂保持原样，需要重学或新目标就新增节点；Host 保留修改原因与受影响的节点，没有变化时返回 saved:false。新节点要被后续节点引用时，先保存拿到真实 id 再调整。
- `schedule-lesson`：按学生给出的日期更新已有节点，`date` 为 `null` 清除安排；学生给了日期才调用。首次排课可以先用 `calendar` 看未排期节点与路线 revision。排课只写日期，开课、完成与归档另外进行。
- 节点块、`lessons` 和标记由这些命令维护；`write-batch` 只用来改节点块以外的课程总述。

overview 和 brief 是 Markdown，节点身份由命令生成；索引参数来自当前提交的数组，既有节点身份来自真实读取。材料和剧本只能指向实际文件。写入服从原生沙箱与审批，不再增加第二道统一确认。保存后用 shell 回读实际文件，核对目标、主线、分支和资料都在，不能只看命令返回成功。

学生要上某一节课时用 `open_learning_lesson`：参数是路线的 Vault 内相对 `path`（如 `路线/学习路线.md`）、节点的 `nodeId`，学生明确要再学一次时加 `repeat: true`。学生留在当前这节课里：当前课堂还没对应节点时，它就成为这一节的课堂，本课背景换成节点的规划与前课小结；当前课堂已对应别的节点，或这一节已有学生上过的课堂时，结果里 `bound: false` 并写明原因，照实告诉学生怎么做。节点身份由命令维护。

开课读取当前节点的规划、必要先修入口与前课实际进度；需要细讲时再读剧本的当前阶段。没有剧本也可按规划直接教学。学生界面不贴工具字段、模型报告、内部路径或未到时机的答案。

## 课后局部调整

先读对应课堂小结与相关实际作答，再判断原计划是否仍合适。说明观察证据、要改的未来节点及理由，例如“能解释示范的步骤，但还不会独立选择方法，因此增加一次选路比较”。优先更新未开展的课或增加一节有目标的补练，不重建整条路线。

已有 sessionId 的课程不覆盖，课堂、小结、原身份和日期保留。需要重学就沿原生重学入口或新增节点。没有实际变化就不写虚假的修订记录；记录错误先更正来源，再重新评估安排。有小结只表示已有记录，不表示达到检查标准。

固定规划 Skill 的修改要有实际课堂或用户修订依据；一条样板、一次顺利授课、模型自评均不能自动升级为通用教法。

内置内容蓝本（如迭代数列专题）的索引与适用条件放在对应学科入口里，通用规划只说明取法，不内嵌学科样例正文，也不套给无关课题。需要时按学科入口给出的索引读取随包分发的教学资源，读取方式与权限以 `notara-vault-workflow` 与命令 `--help` 为准，不自己拼路径或环境变量；读取失败就说明未读到，不能凭文件名声称参照过。它是内置内容样板，不是学生已有材料，不能把资源路径直接写成 Vault 的 materials，也不能整篇塞成一个课堂节点。
