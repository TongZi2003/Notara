# 编写技能

内置学科关注覆盖不到的学科或课程（例如模电、数电、操作系统、计算机体系结构），或者本学习集有值得长期沉淀的要点时使用。写出的技能先是草稿，学生在技能页读过并启用后，老师和工作员才会使用。

## 两层，各写各的

- 学科层（`scope: global`，所有学习集共用）：只写这门学科的核心思想，包括主线、共同关注、元方法在本学科怎样落地、本学科的退与进、深度怎样检验、拆书与课程编排重点、核验依据。篇幅短，不写具体题型技巧，也不写某个学生或某本书的情况。
- 学习集层（`scope: set`，本 Vault 的 `技能/`）：一份学习集梗概，以及按主题分的要点技能（例如“圆锥曲线要点”）。主题技能里的每条要点，就是一次可以复用的方法经历，写法见下面的“主题要点”。一个主题一份，用 `tags` 区分。
- 旧的 `锦囊/` 文件照旧可以读取；学习集层技能加载时，系统仍会附上与它 `tags` 相同的旧锦囊索引。新的方法经历写进主题要点技能。

## 主题要点

每条要点写六项：

1. 何时想起：可以判断的题目结构或思维障碍，写到机制那一层。例如“圆都过同一定点、要证共线或求轨迹时”“两个二次式相减、要找中点或斜率关系时”。
2. 条件：这个做法成立需要什么。
3. 做法：可以再次执行的步骤，包括在这种情境里怎么讲、怎么安排任务。例如“以该点为中心反演，把圆变成直线”。
4. 为什么成立：写到机制那一层。
5. 在哪里失效：已知的失效条件、反例和没走通的过程。
6. 依据：哪次课、哪张卡；是学生主动发现的，还是老师给的。

还没有课堂证据的要点写进“待验证”。技能的 `description` 写清这个主题里的几种触发情形：已启用技能的说明每轮都列在技能目录里，老师靠它想起这份技能。学生的详细经历留在卡片的“学生理解”，要点写概括并指回卡片。

## 学习集梗概

每个学习集有且只有一份梗概：学习集层技能，`id: learning-set`，每次对话开始时由系统读入本课背景。

- 页头必填：`subjects`（科目列表）、`coverage`（学什么，一句话范围）、`level`（学段或水平）、`goal`（目标）、`deadline`（期限；确实没有期限写“无”）。不知道的先问学生；一时问不到的写“待填写”，带占位的梗概不能启用。
- 正文写学生情况、主要资料和教学方法提示，简短即可；具体要点另写成主题要点技能，梗概里最多放一行链接指向它。
- 一个学习集涉及多个科目时，梗概仍只有一份，写共同的目标与涉及的科目；各科的具体要点写进各自的学习集层技能，用 `tags` 区分。
- 起草依据：本 Vault 已有的目录、资料标题与标签，加上学生本次的回答；推测出来的内容要让学生确认，不要当成事实写死。

## 取证

- 学科层先按 `notara-research` 调研：课程大纲与课程主页、经典教材的目录与前言、名校公开课的日程与作业、学习者经验里的常见卡点。
- 学习集层依据本 Vault 的真实材料与课堂：卡片的学生理解、课堂小结、已有的主题要点与旧锦囊、路线。还没有课堂证据的要点，写进“待验证”。
- 模型自身知识只用来组织框架；具体事实要有来源，写不出依据的判断标“经验，待验证”。

## 文件格式

页头使用扁平 frontmatter：

- `type: skill`
- `id`：小写字母、数字和连字符，最多 48 个字符，与文件名相同
- `title`：中文名称，最多 40 字
- `description`：什么时候使用、包含什么，最多 300 字
- `status: draft`
- `tags`：学习集层可选，用来区分主题，也用来附上标签相同的旧锦囊索引

学科层正文沿用内置学科技能的节：适用任务、主线、共同关注、元方法在本学科、本学科的退与进、深度怎样检验、拆书重点、课程编排重点、核验依据；末尾写 `## 来源`，列出等级、机构、链接与日期。

学习集梗概的正文：`## 学习集梗概`、`## 教学方法提示`。主题要点技能的正文：`## 要点`（每条按“主题要点”的六项写，可按小主题分三级标题）、`## 待验证`。两者是不同的文件，要点写在主题技能里，梗概里最多放一行链接。

## 保存与生效

- `skill-list`、`skill-read`、`skill-save` 都是本地命令行的子命令，用 Bash 这样调用，参数按 JSON 从 stdin 传入：`printf '%s' '{}' | "$DSH_NOTARA_NODE" "$DSH_NOTARA_CLI" skill-list`。每条命令的精确字段以 `"$DSH_NOTARA_NODE" "$DSH_NOTARA_CLI" skill-save --help` 为准。它们不是独立的命令，不要去 Vault 以外的目录或环境变量里找。
- 用命令 `skill-save` 保存，`scope` 为 `global` 或 `set`；新建的一律是草稿。`技能/` 下的文件不能用 `write-batch` 写。
- 保存后告诉学生：去“技能”页读一遍，觉得可以再启用。不要自己把 `status` 改成 `active`，也不要在对话里替学生确认。
- 修改已启用的技能：先用 `skill-read` 读原文，改好完整内容后，带上它的 `revision` 再 `skill-save`。系统会生成一份待确认的修订，学生在技能页采用后才替换原文。修订前后在对话里说明改了什么、依据是什么。`skill-read` 返回 `pending` 时，上一份修订学生还没采用：在 `pending.content` 上合并这次的改动，用 `pending.revision` 保存，并告诉学生这一份已经包含了上一份。
- 新学习集想沿用另一个学习集的技能时，请学生在“技能”页里选择“继承”，复制成新学习集自己的草稿。不跨学习集手工复制文件。

## 自查

- 学科层没有混进具体题型、某本书或某个学生的情况。
- 学科层写了这门学科里退与进具体长什么样，以及推导、改条件、反例、边界、迁移五个检验怎样落地；不靠推导的学科写清用什么代替推导（文本依据、史料、换一种语境）。
- 学习集层每条要点都有条件和依据；尚未验证的内容已经归入“待验证”。
- 每条要点的“何时想起”具体到可以判断，写到机制；依据写清是学生主动发现还是老师给的。
- 技能说明写清了这个主题的触发情形，看说明就知道什么时候该读它。
- 篇幅合适；内容多时拆成几份，每份用自己的 `tags`。
- 保存后用 `skill-list` 核对状态与待确认修订，而不是只看命令返回成功。
